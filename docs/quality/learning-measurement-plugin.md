# 真实使用学习测试插件

本模块用于先积累可追溯的真实作答，再比较“答题前预测”与随后发生的结果。入口为 **设置 → 学习测试**，路径 `/opening/settings/learning-test`。这是单人、固定题目顺序的预测试跑；界面和导出不会把它称为教学效果实验。

## 开始测试

1. 在含迁移 `0066_opening_measurement.sql` 的版本中登录，准备一门高等数学课程；无需配置模型供应商或支付模型调用费用。
2. 打开学习测试，选择课程并启用“分部积分选择题测试”。先按自己当前水平作答六题。页面介绍将选择 u/dv、求 v、代入公式串成一个过程；三个评分目标分别记录。
3. 不会时可以使用提示、查看解析或跳过。如果查了教材、问了他人或使用其他 AI，请记录“使用了外部帮助”。这些记录保留，但不算独立答题成绩。
4. 完成初轮后，服务端按实际完成时间安排至少 48 小时和 7 天后的两轮测试，各三题。提前请求不会发题；回来较晚时保留真实时间，不能解释成精确 48 小时或 7 天成绩。预先规定的评分窗口分别截至初轮结束后第 4 天、第 10 天；超窗作答保留并单列排除。第 7 天轮实际开放时间还须晚于前一延迟轮最后提交至少 72 小时；暂停、使用帮助或撤回都不能抹去已发生的曝光。原定评分窗口不随开放时间顺延，超窗仍单列排除；历史间隔不足的记录也排除，避免把连续练习误作延迟验证。延迟轮完成前不显示正确与否和解析。
5. 可以暂停，刷新或重新登录后继续。关联课程归档后仍可从课程选择器读取记录和导出，但不能新增或修改作答；恢复课程后点击“重新读取”再继续。同一工作区同一用户的同一单元仅保留一份试验；换课程不能重置已见过的题。误点或事后发现用了外部帮助，可填写原因撤回该条证据。
6. 打开“测试数据”查看有效样本、排除原因、逐轮指标；下载 JSON 保留作答、模型版本、预测时间及其证据依赖。答题中的未公开结果也不会通过导出泄露。

页面浏览器验收由用户完成。Agent 验证非浏览器逻辑、契约、权限及数据库行为，不把 HTTP 成功或组件渲染测试当作浏览器验收。

## 如何读数据

- BKT 和平滑历史正确率使用同一条作答之前、同一技能的合格历史；预测在发题事务中持久化，提交答案后不能补写预测。
- Brier 和 Log loss 越低越好。差值定义为 **BKT − 基线**；负值仅说明这批配对样本的预测误差较小。校准分桶同时给出预测均值、实际正确率和样本数；Brier 变小不能单独证明校准改善。
- 跳过不是答错；未答不是零分；有帮助、撤回、重复或预测依赖已经撤回的样本不会混入独立配对评分。撤回保留原预测，不改写历史；未来预测用仍有效的历史重新计算。
- 题目、题目版本、题目族、单项技能和协议版本分开保存。只有本测试插件内记录的首次曝光可确认；在其他工作区或其他平台见过题无法自动发现。
- 全部模型参数目前是显式的未校准起始假设，不从这十二题调参，也不输出掌握率。经典 BKT 不等同于此前上传的多维 evidence engine。

## 算法与整合验收

经典 BKT 使用“当前知识概率 → 当前作答的贝叶斯后验 → 学习转移 → 下一题答对概率”的顺序，无遗忘项；公式可核对 [pyBKT 论文第 1 页](https://educationaldatamining.org/EDM2021/virtual/static/pdf/EDM21_paper_237.pdf)。固定参数为初始知识 0.2、学习 0.1、猜测 0.25、失误 0.1，不等同于已经拟合此用户。

`models.test.ts` 通过独立隐状态路径求和，核对全部长度 0–8 的 511 条答案序列，并覆盖初始/转移边界、不可条件化事件及一万次全对、全错、交替作答。它验证数学实现，不把合成数据当真实收益。领域测试还验证同技能与时间截止过滤、原预测不可改写、配对得分和缺测。

合并以主干的 S1–S7 为准，0066 原样保留，0067–0069 不变。PostgreSQL 集成验收检查试验写入前后生产 observations/sessions/tasks/plan drafts/acceptances 与固定时间的 S3 指标一致；经典 BKT 不接管现有任务或教练决策。晚到复测须先达到真实间隔再发题，未答预测及未完成轮次的答案仍统一遮蔽。完整 CI 和合并结果以 PR #61 的精确提交检查记录为准。

## 插件边界与扩展

`packages/contracts/src/opening/measurement.ts` 是 HTTP 与持久化边界。客户端不能提交正确性、首次作答、概率或时间；服务器负责这些事实。

`packages/domain/src/opening/measurement/` 是无 I/O 的计算模块：模型插件提供 manifest 与 predict，题库通过仅供服务器消费的独立入口 `@aistudy/domain/measurement-catalog` 提供稳定身份、公开题面、评分和排程（不从客户端常用的领域 barrel 导出答案），报告仅计算已持久化预测的配对误差。添加模型时给出新 ID/版本和参数，注册实现并用过去历史生成预测；新参数不能冒用旧版本。数据库校验试验冻结的模型配置与实现匹配，避免升级后静默换模型。

`packages/database/src/repositories/opening-measurement*.ts` 负责授权、服务端时间、事务、并发锁、幂等回执及题库快照。题目从固定的共同题序发出，模型不参与当前教学或选题。`apps/web/src/features/opening/measurement/` 提供启停、作答、结果和导出界面。主学习规划器不读取本模块状态。

扩展新单元时应新增版本化题库和输入契约，保持同一题目族不因换系数而改名。引入 Python/远程估计器时，在外层增加异步适配器，保证预测成功持久化后才发题；不要给纯同步领域函数添加网络调用，也不要在失败时伪造预测。

## 当前可测与仍缺少的证据

可以测量真实人的逐题预测误差、参与和缺失情况、帮助使用，以及返回后的延迟选择题表现。十二题、单用户、未等值的不同题目族不足以证明 BKT 提升了学习效果。新题族的难度变化也可能解释成绩变化。7 天结果发生在 48 小时测试及其反馈之后，包含提取练习与反馈的影响，不能当作未干预的纯遗忘曲线。自由作答、完整推导、证明及多维评分尚未覆盖。

本模块解决了测试内部的稳定身份、首次作答、客观评分、预测先于结果、延迟时间与撤回追溯。主教学链路的跨重建技能映射、自动生成题目的题族识别、专家评分校准和上传多维内核的正式接入仍需独立实现。后续使用更多真实学生的历史数据拟合参数，按学生、时间和新题族分别留出测试，再与 PFA/逻辑回归等更强基线比较。教学收益须另做同时间预算、共同测验、含失访统计的对照试验。

## 运维与回滚

先执行仓库常规迁移，再运行应用。插件默认为未报名，无环境变量和外部模型依赖。恢复旧应用时保留新增三张表；不要删除真实试验记录。若确需撤销数据库迁移，先备份数据库及导出试验，再按 commands、attempts、trials 顺序删除表。

测试 JSON 是分析导出，当前不提供导入恢复；现有 Opening 备份格式尚不包含这三张表。完整恢复使用数据库备份，不能将本导出误作完整应用备份。

### 数据库备份与恢复

报名说明和 JSON 导出入口均提示上述限制。启用真实使用前，站点管理员应将本数据库纳入备份，并在独立空库完成恢复演练。完整归档须包含用户、工作区、课程及其原始 ID，以及以下三张表，不能只复制界面可见作答：

- `opening_measurement_trials`：试验身份、协议、开始时间、初轮完成时间、冻结的完整 `catalog` 和 `models`、报名请求与状态。
- `opening_measurement_attempts`：原题快照、作答前 `predictions` 及其历史依赖、呈现/到期/作答时间、帮助与撤回记录。
- `opening_measurement_commands`：原始操作意图和幂等回执。丢失回执可能使恢复后的客户端重试无法被识别。

使用与数据库服务器同版本或兼容新版本的 PostgreSQL 客户端。下面的两个 libpq service 名分别指向现有数据库和**独立、空的恢复库**；由管理员预先配置连接与凭据，不将密码写入命令行或日志。不要把恢复目标指向在线库。

```bash
umask 077
MEASUREMENT_BACKUP_FILE=/secure/backups/aistudy-before-bkt.dump
PGSERVICE=aistudy-production pg_dump --format=custom --file="$MEASUREMENT_BACKUP_FILE"
pg_restore --list "$MEASUREMENT_BACKUP_FILE"
PGSERVICE=aistudy-recovery pg_restore --exit-on-error --single-transaction --no-owner --no-privileges --dbname=service=aistudy-recovery "$MEASUREMENT_BACKUP_FILE"
```

这是整库归档，不加 `--table` 或 `--schema` 过滤。`pg_dump` 提供一致快照；归档完成后的新作答不在该快照内。正式切换恢复库前停止应用和 worker 写入，确认备份截止时间与允许丢失的时间窗口，并按部署配置恢复数据库角色权限。文件材料等对象存储仍按现有站点备份方案单独恢复。归档包含未公开的题目答案与个人数据，只供受限管理员保管，不通过学习测试下载接口提供。

恢复后先使用制作备份时的兼容应用版本，保留试验声明的模型版本实现，再执行常规向前迁移；禁止用当前题库/参数重建旧试验。检查原课程下的试验 ID、初轮完成时间、三表记录数、模型配置和预测时间均与备份一致，再使用相同工作区读取、继续原未答题及重放原请求键。未完成的延迟轮仍应隐藏评分、解析和预测，分析导出也相同；跨工作区访问应被拒绝。完成检查再切换服务，避免在两套数据库上同时接收作答。

`tests/integration/opening-measurement-recovery.test.ts` 使用真实 PostgreSQL 和 `pg_dump` / `pg_restore`：在隔离 schema 中运行原始 0066，完成初轮并留下一道已答但结果隐藏的延迟题及一道未答题，归档后删除该 schema，再从归档恢复并重新连接。测试逐表比较完整持久化事实，校验冻结题库/模型、预测、时间、回执、权限及结果遮蔽，随后继续同一延迟轮。它不会跳过缺失客户端；环境需提供两个可执行文件。此测试只备份隔离的测量 schema，并保留测试主体身份；它验证测量数据恢复，不替代部署环境的整库和对象存储灾备演练。

```bash
PATH=/path/to/postgresql/bin:$PATH npm run test:integration -- tests/integration/opening-measurement-recovery.test.ts
```

该命令沿用仓库隔离数据库设置：`OPENING_TEST_DB=1`，`OPENING_TEST_DATABASE_URL` 必须指向 loopback 的 `aistudy_opening_test`，不能使用线上数据库。

## 方法依据

- [pyBKT 官方实现与模型说明](https://github.com/CAHLR/pyBKT)：经典 BKT 及其变体；本模块采用本地 TypeScript 的二元基础模型，不宣称调用 pyBKT 或上传内核。
- [pyKT 评估原则](https://arxiv.org/html/2206.11460v5)：避免同一作答多技能展开导致的信息泄漏，严格区分预测与更新。
- [scikit-learn 概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)：适当评分规则与校准图的区别。
