# 真实使用学习测试插件

本模块用于先积累可追溯的真实作答，再比较“答题前预测”与随后发生的结果。入口为 **设置 → 学习测试**，路径 `/opening/settings/learning-test`。这是单人、固定题目顺序的预测试跑；界面和导出不会把它称为教学效果实验。

## 开始测试

1. 在含迁移 `0066_opening_measurement.sql` 的版本中登录，准备一门高等数学课程；无需配置模型供应商或支付模型调用费用。
2. 打开学习测试，选择课程并启用“分部积分选择题测试”。先按自己当前水平作答六题。页面介绍将选择 u/dv、求 v、代入公式串成一个过程；三个评分目标分别记录。
3. 不会时可以使用提示、查看解析或跳过。如果查了教材、问了他人或使用其他 AI，请记录“使用了外部帮助”。这些记录保留，但不算独立答题成绩。
4. 完成初轮后，服务端按实际完成时间安排至少 48 小时和 7 天后的两轮测试，各三题。提前请求不会发题；回来较晚时保留真实时间，不能解释成精确 48 小时或 7 天成绩。预先规定的评分窗口分别截至初轮结束后第 4 天、第 10 天；超窗作答保留并单列排除。7 天轮与前一延迟轮实际作答相隔不足 72 小时也单列排除，避免把连续练习误作延迟验证。延迟轮完成前不显示正确与否和解析。
5. 可以暂停，刷新或重新登录后继续。同一工作区同一用户的同一单元仅保留一份试验；换课程不能重置已见过的题。误点或事后发现用了外部帮助，可填写原因撤回该条证据。
6. 打开“测试数据”查看有效样本、排除原因、逐轮指标；下载 JSON 保留作答、模型版本、预测时间及其证据依赖。答题中的未公开结果也不会通过导出泄露。

页面浏览器验收由用户完成。Agent 验证非浏览器逻辑、契约、权限及数据库行为，不把 HTTP 成功或组件渲染测试当作浏览器验收。

## 如何读数据

- BKT 和平滑历史正确率使用同一条作答之前、同一技能的合格历史；预测在发题事务中持久化，提交答案后不能补写预测。
- Brier 和 Log loss 越低越好。差值定义为 **BKT − 基线**；负值仅说明这批配对样本的预测误差较小。校准分桶同时给出预测均值、实际正确率和样本数；Brier 变小不能单独证明校准改善。
- 跳过不是答错；未答不是零分；有帮助、撤回、重复或预测依赖已经撤回的样本不会混入独立配对评分。撤回保留原预测，不改写历史；未来预测用仍有效的历史重新计算。
- 题目、题目版本、题目族、单项技能和协议版本分开保存。只有本测试插件内记录的首次曝光可确认；在其他工作区或其他平台见过题无法自动发现。
- 全部模型参数目前是显式的未校准起始假设，不从这十二题调参，也不输出掌握率。经典 BKT 不等同于此前上传的多维 evidence engine。

## 插件边界与扩展

`packages/contracts/src/opening/measurement.ts` 是 HTTP 与持久化边界。客户端不能提交正确性、首次作答、概率或时间；服务器负责这些事实。

`packages/domain/src/opening/measurement/` 是无 I/O 的计算模块：模型插件提供 manifest 与 predict，题库通过仅供服务器消费的独立入口 `@aistudy/domain/measurement-catalog` 提供稳定身份、公开题面、评分和排程（不从客户端常用的领域 barrel 导出答案），报告仅计算已持久化预测的配对误差。添加模型时给出新 ID/版本和参数，注册实现并用过去历史生成预测；新参数不能冒用旧版本。数据库校验试验冻结的模型配置与实现匹配，避免升级后静默换模型。

`packages/database/src/repositories/opening-measurement*.ts` 负责授权、服务端时间、事务、并发锁、幂等回执及题库快照。题目从固定的共同题序发出，模型不参与当前教学或选题。`apps/web/src/features/opening/measurement/` 提供启停、作答、结果和导出界面。主学习规划器不读取本模块状态。

扩展新单元时应新增版本化题库和输入契约，保持同一题目族不因换系数而改名。引入 Python/远程估计器时，在外层增加异步适配器，保证预测成功持久化后才发题；不要给纯同步领域函数添加网络调用，也不要在失败时伪造预测。

## 当前可测与仍缺少的证据

可以测量真实人的逐题预测误差、参与和缺失情况、帮助使用，以及返回后的延迟选择题表现。十二题、单用户、未等值的不同题目族不足以证明 BKT 提升了学习效果。新题族的难度变化也可能解释成绩变化。7 天结果发生在 48 小时测试及其反馈之后，包含提取练习与反馈的影响，不能当作未干预的纯遗忘曲线。自由作答、完整推导、证明及多维评分尚未覆盖。

本模块解决了测试内部的稳定身份、首次作答、客观评分、预测先于结果、延迟时间与撤回追溯。主教学链路的跨重建技能映射、自动生成题目的题族识别、专家评分校准和上传多维内核的正式接入仍需独立实现。后续使用更多真实学生的历史数据拟合参数，按学生、时间和新题族分别留出测试，再与 PFA/逻辑回归等更强基线比较。教学收益须另做同时间预算、共同测验、含失访统计的对照试验。

## 运维与回滚

先执行仓库常规迁移，再运行应用。插件默认为未报名，无环境变量和外部模型依赖。恢复旧应用时保留新增三张表；不要删除真实试验记录。若确需撤销数据库迁移，先备份数据库及导出试验，再按 commands、attempts、trials 顺序删除表。

测试 JSON 是分析导出，当前不提供导入恢复；现有 Opening 备份格式尚不包含这三张表。完整恢复使用数据库备份，不能将本导出误作完整应用备份。

## 方法依据

- [pyBKT 官方实现与模型说明](https://github.com/CAHLR/pyBKT)：经典 BKT 及其变体；本模块采用本地 TypeScript 的二元基础模型，不宣称调用 pyBKT 或上传内核。
- [pyKT 评估原则](https://arxiv.org/html/2206.11460v5)：避免同一作答多技能展开导致的信息泄漏，严格区分预测与更新。
- [scikit-learn 概率校准说明](https://scikit-learn.org/stable/modules/calibration.html)：适当评分规则与校准图的区别。
