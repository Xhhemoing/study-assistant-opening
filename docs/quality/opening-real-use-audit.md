## 1. 结论与不变项

**沿用现有 27 项计划；补齐真实使用连接点，不重建产品路线。** 当前安全、版本、费用、隐私方向合理，但“有模块/接口”还不足以支撑“少解释一次、换设备继续、围绕眼前一道题求助”。

- 保留：单语言模块化架构、opening 服务端入口、私有原件、程序校验权限/引用、保守学习证据、协商计划、五项核心范围。[V: E01]
- 保留：F01 可继续；F02 在相关契约缺口解决前不能仅因结构检查通过就宣布冻结。现有 PA-01–10 不被本报告取代。[V: E01,E06]
- 不新增：自动收邮箱、学校账号接入、完整知识本体、复杂调度器、学生模型训练、多 Agent 产品平台。[H: E01]
- 不把研究当授权：未选择付费供应商、未上传材料到外部、未部署；真实模型/手机/解析质量仍需独立验收。[V: E07]
- 更正此前建议：不能仅为提前演示而删除 `P02→L01` 依赖；重测接任务需要实际适配。优先修正 RU-07 的里程碑表达与基本交互交接。[H: E01]

## 2. 从真实需求逆向验收

用户输入仅证明：教师负责 Mathematics I 第一部分、六主题、两周密集授课、概念与练习测试；没有具体日期、考试权重、课外时间或学生能力证据。[V: E02]
已有长期需求来自批准规格：手机/电脑、纸面学习、不要求每题上传、学习与生活交流、可纠正记忆、少量待确认建议。[V: E01]

| 使用时刻 | 系统必须知道/保留 | 不能擅自补全 | 对应检查 |
|---|---|---|---|
| 收到邮件和两份附件 | 原始通知、文件关联、课程候选 | 开课日、考试日、各章权重 | AC01,AC02 |
| 空账号首次使用 | 可选课程创建、无课程也能问问题 | 强迫填完整画像或先做诊断 | AC03 |
| 上课打开“这一页” | 实际 PDF 页/图像及当前问题 | 仅凭文件名猜页码或公式 | AC04 |
| 拍下一段演算求助 | 题目和步骤、局部定位、已给帮助 | 识别失败等同数学能力差 | AC05,AC06 |
| 第二天在另一设备继续 | 可发现会话、有限历史、材料/卡点位置 | 靠浏览器本地 ID 或模型猜前情 | AC07 |
| 教师改安排/自己没做完 | 时间配置版本、任务状态、变更预览 | 自动把缺课表区域当空闲 | AC08 |
| 一门课要详解，另一门要提示 | 偏好的适用范围、来源、有效期 | 把局部选择泛化为个人永久偏好 | AC09 |
| 复习后判断改善 | 具体题目、帮助、核验依据、延迟新尝试 | 当场复述正确等同迁移能力 | AC10 |

默认界面仍只有至多三个优先行动；上述检查属于展开层/测试，不把审查字段全部展示给用户。现有 Today/助理/课程导航不变。

## 3. 发现与最小修正

以下子计划路径均相对 `docs/superpowers/plans/opening-release/`；每项修正须落实到原任务和测试，不新增平行计划。

### RU-01 / 高：课程存在，但原始材料关联不能直接复用 [C,V；PA-01 的新增实证]

- **场景：**创建 Mathematics I 后，将 PDF 归到课程；资料不能仅停留在收件箱。
- **证据：**`interfaces.md:33` 指定复用 membership；`packages/contracts/src/assets.ts:8–15` 包含 `source`，但 `packages/database/src/repositories/course-membership.ts:250–299` 只解析 document/block/card 的所有者，source 明确拒绝。E03 用实际 repository＋假 SQL 复现 `VALIDATION Asset type not yet membership-backed: source`。
- **反证边界：**课程创建/列表 API 已在 `apps/web/src/app/api/courses/route.ts:9–30` 实现，不能报告“没有课程后端”。source 拒绝是既有安全边界，不应简单删除该检查。
- **最小修正：**F02/F03/I01 明确 opening source 的受限所有权 resolver、关联/撤销契约与课程读投影；U01 指定复用 `/api/courses`，适配 opening 跳转。既有 `course-create.tsx:31`/`course-model.ts:33–35` 指向旧 learn 页面，不能原样搬入。
- **验收：**空账号创建课程→上传→关联→换设备列表可见；跨 workspace 拒绝；同一 source 复用于两课程不复制原件。属于复用与鉴权测试，不是放宽 source 类型校验。

### RU-02 / 高：保存会话与连续理解不是同一条链 [C,H]

- **场景：**第二天电脑上说“继续昨天反函数第二步”，无需重新粘贴问题。
- **证据：**规格 `2026-09-12-opening-release-design.md:30,43–45` 承诺上下文切换与次日恢复；`interfaces.md:49–51,65–74,144,155–156` 有当前 text/chunks、按已知 ID 列消息和创建会话，但未列会话发现/恢复接口，也未定义保存会话传给 provider 的历史结构。只有 ephemeral 明确 history。
- **F02 草稿进度（continuity）：** `interfaces.md` 已补 `ConversationSummary` / `ConversationResume`、`listConversations`/`resumeConversation` 与有界 `historyBound`（建议 maxTurns=40）。Zod 落地仍属 F02 Create 列表。
- **反证边界：**T03 已持久化会话，允许 reload；工程上可以把历史编码到 text/instruction，不能说接口绝对无法实现。缺的是服务端历史装配、顺序/预算/撤销过滤与跨端发现的明确责任和测试。
- **最小修正：**F02/T02/T03/U03 约定分页会话列表、服务端恢复 DTO、带角色的有界历史及当前作用域；记录材料/问题位置。范围切换可选开新会话，不强制设计复杂分支聊天。旧资料撤销后不可借历史重新发送。
- **验收：**新浏览器仅登录、不预塞 conversationId，也能找到会话；fake provider 检查确实收到必要历史；“继续第二步”live 语义单独验；无关课程记忆不串入。与 PA-07 分页要求合并。

### RU-03 / 高：选中文件不等于选中当前页，非空文本不等于可教数学 [C,V；与 PA-08 衔接]

- **场景：**手机看某页、询问其中一个式子；不能每次手工重打题目和页码。
- **证据：**`interfaces.md:23–27` 的 chunk 有物理页，但 `TurnInput:44–48` 只有 sourceIds，无当前页/chunk/区域选择语义；`07-experience.md:49,70` 承诺查看原件及原图纠正。E02 验证 58 个物理页/42 个逻辑页，第4/5物理页文本相同但像素不同。
- **F02 草稿进度（continuity）：** `interfaces.md` 已补 `TurnInput.currentPage`/`chunkId` 与服务端 membership 校验合同（AC04；422 codes）。区域选择仍不在本刀范围。
- **研究：**Docling 2.126.0 固定源码默认 `do_formula_enrichment=False`；普通提取成功不等于启用公式模型。官方 pypdf 文档说明数学式、布局和 OCR 的边界。[V: E04]
- **最小修正：**F02/I02/T02/U02 定义可选、服务端校验的当前物理页/chunk 定位；无法定位时询问，不猜。公式可靠性和原件可用性分开。保留逻辑幻灯片标签及物理页，不按文本 hash 直接去掉视觉不同页；区域裁剪可后续，不强求复杂标注器。
- **验收：**AC04 页码定位、AC05 模糊符号回看；公式增强默认/启用模式独立测量。页图授权、尺寸和费用需贯通 PA-08；本轮未证明 Docling 在此样本的公式准确率。

### RU-04 / 高：纸面题目身份与帮助曝光还可能断链 [C,H；扩展 PA-03]

- **场景：**上传一道题求完整讲解，之后记录“做对了”；或复习同技能的另一题。
- **证据：**`interfaces.md:47` 的 learningSessionId 可空；`99–113` observation 有 skillLabel/sourceIds/answer，却没有明确题面引用/快照或 retest 关联；`05-learning.md:27–30` 帮助按同一 session 处理。一个 PDF＋“反函数”不足以唯一识别哪道题。
- **反证边界：**现有计划已防客户端抹去同 session 帮助，也明确未来新 session 不自动继承旧曝光。缺口是自然聊天开始时如何获得并保持那个 session，以及后补记录如何对应原题；不是要求全课永久污染。
- **最小修正：**F02/T03/L01/L02/U03 让实际学习求助由服务端创建/复用活动 session，保留题面/定位/版本与可选 retestId；原始参考和学生演算明确区分。未绑定或事后无法确认的记录标 unknown/needs_check，不强记 independent。
- **验收：**无先建 session 的自然问答也记录实际曝光；同题后补不能洗成独立；真正新变式不继承无关帮助；相同技能下两题可区分，完成重测能关闭对应 due 项。普通闲聊不强制创建学习 session。

### RU-05 / 高：时间规则正确，但配置—保存—重读链需要明确 [H；PA-01 的场景细化]

- **场景：**先收到“两周”通知，之后补学期起点/节次钟点；电脑改可用时间后手机接受旧计划。
- **证据：**`06-planning.md:18,30–32,49–52` 已正确要求映射、休息保护和版本冲突；`interfaces.md:121–131,154` 仅给 WeekSession/TimeBlock 与“显式学期映射”，未冻结可用时间、时区、硬块和课程映射的读写/版本 DTO。
- **F02 缺口标记（continuity）：** `interfaces.md` 已标 `TimeConfig` + `TimeConfigRecord(courseId,version)` 与 `WeekSession.courseId` 缺口；尚未当作已冻结实现。
- **反证边界：**P02 已计划持久 schema，不能据接口简写断言会丢数据。这里是必须补全的实现/验收责任，不是另造排课算法。
- **最小修正：**F02/P01/P02/U03 给确认配置可读回的版本化协议，按课程 ID 绑定显示名称；区分未知时间和已确认空闲。新约束参与草案快照与接受校验；缺时间时仍可记录无日期任务和查看材料。
- **验收：**无日期邮件不产生确定日历；保存配置→刷新/重启/另一设备读回；变更节次/可用时间后旧草案409；未完成任务重新提出而非静默认定完成。无需引入求解器或外部日历。

### RU-06 / 中：记忆有生命周期，但适用范围仍靠自然语言猜 [H,C]

- **场景：**“这两周数学先给完整讲解”不能变成所有课程永久默认；“今天累”不能一直影响排程。
- **证据：**`interfaces.md:53–54,84–89` 的候选只有 temporary 布尔，MemoryItem 没有明确课程/全局适用范围；M01 `04-memory.md:17,29–31` 要求 expiry 和仅显式临时事实进上下文，T02 要用 approved memory，但转换/选用规则未冻结。
- **F02 缺口标记（continuity）：** `MemoryItem.courseId` + temporary→`expiresAt` 已在 interfaces；effective scope / apply-range 条文已标（AC09），wire 字段仍可选派生。
- **反证边界：**可从来源会话推导课程，现有文本也可写限定词；不是必须增加庞大画像模型，而是要让范围与过期约束可检验。
- **最小修正：**F02/M01/T02/P02 明确从来源推导或显式保存 effective scope；只有用户确认的全局偏好才跨课程使用。temporary→expiresAt 的规则明确，期限含糊则保持候选；疲劳只支持可拒绝的安排建议。
- **验收：**课程A偏好不影响B；过期内容不进新上下文；纠正后下一次回答使用新版；拒绝建议不等于稳定偏好改变。与 PA-04/既有隐私门禁共存，不能只验证“面板里有记录”。

### RU-07 / 中：M1 的用户可用含义未被基本聊天 UI 交付覆盖 [C]

- **场景：**用户想尽早用真实材料求助，而不是等全部记忆、提醒完成后才第一次使用。
- **证据：**总计划 `:95` M1 包含 I01–I03/T01–T03/U01–U02，宣称“能提交材料并求助”；基本 composer/message-list/assistant-view 全在 `07-experience.md:53–70` 的 U03，依赖 M03/L03/P03。
- **反证边界：**T03 可以先通过 API 验收，不代表完全没有早期闭环。问题是把 API 可用当成了手机/电脑可求助的里程碑。
- **最小修正：**在现有 U03 内注明基础保存对话部分的分段交接，或把 M1 明确标为 API 里程碑；保留 U03 最终整合门禁。建议前者，尽早收集真实反馈，但不提前开放未通过删除门禁的敏感记忆。
- **验收：**M1 若称用户可用，必须有真实上传→指定材料→提问→出处→刷新恢复的薄 UI。正式发布仍严格 Q03→Q01→Q02，不能用薄 UI 免除备份与隐私验收。

## 6. 落地顺序与研究停止条件

1. 将 RU-01–06 对应的契约/交接补丁并入既有 PA 审查处置，先审 F02；不反复重写需求文档。F01 不受这些语义研究阻塞。
