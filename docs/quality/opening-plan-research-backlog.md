关联：[计划核验 PA-01–10](opening-plan-audit.md)。全项目研究仍登记在 [Brainstorm INDEX](../brainstorm/INDEX.md)，本文件是 opening 分支的任务化队列，不另立产品规格。

## 1. 可直接复制给 Grok 的通用要求

> 项目背景：单用户、手机和电脑访问同一服务器的大学学习助理。Next.js/TypeScript/PostgreSQL、BullMQ/Redis、私有 S3；核心是资料上传、材料辅导、可纠正记忆、学习观察/重测、协商安排。先小规模确定性基线，不预训练学生模型，不默认 GraphRAG，不做未经授权采集。
>
> 请按下面指定 R-ID 调研，不做泛泛工具榜单。优先官方文档、固定版本源码、原始论文及可复现数据；至少给一个支持证据和一个反例/限制。每条结论标“直接证据 / 推断 / 未确定”，附 URL、文档版本或 commit、发布日期/访问日期、适用数据与硬件、许可证（代码和模型分别核查）。未查到就写未查到，禁止杜撰 DOI/性能数字。
>
> 输出：①一句推荐及适用边界；②与最简单基线比较表；③会失败的样本；④可本地执行的最小实验、指标和停止/回退条件；⑤会改变哪个 R-ID/任务接口；⑥仍需用户材料或本地验证的部分。模型价格、供应商幂等/保留政策必须注明具体 endpoint、模型版本与日期。不要索取密钥、原始私人聊天或可识别课表；优先合成/脱敏样本。
>
> 引用一篇论文不代表项目收益已验证；博客介绍不代替 API 保证；他人 GPU 吞吐不外推到本项目服务器。研究输出不能把“单位测试通过”“引用存在”“模型自评正确”当教育有效性证据。

## 2. 分题派发与阻塞边界

### R01 — 材料解析与照片公式可用性（优先派发）

- **问题：**比较计划候选 Docling `2.126.0`（版本存在性及兼容性也需核查）与轻量 PDF/PPT 文本提取＋按需视觉路线。数字 PDF、扫描页、含图表 PPTX、旋转照片、矩阵/负号各自需要什么能力？如何保留真实页/slide/图片坐标？哪些情况下应拒绝识别而非猜测？
- **Grok 输出：**支持格式/渲染/离线模型下载/CPU-RAM/许可证矩阵；官方能保证的范围与需测范围分开。核查容器禁网、进程超时、ZIP 膨胀限制下能否运行；不同时引入全部备选。
- **本地实验：**固定合成集＋用户授权真实集，分模态记录页码锚点、关键公式/符号正确率、失败/待确认、耗时/RSS；标注是字符提取、公式正确还是可解题，三者不可互换。
- **阻塞：**I02 解析器定型和 PA-08 照片辅导验收；不阻塞 I01 保存/下载原件。音频转写另行启用，保存不可省略。
- **落点：**`02-ingestion.md`、`03-tutor.md`、parser model manifest、Q02 cases。当前状态：waiting_grok；真实解析效果 pending_local。

### R02 — 真实模型、费用上限与多模态输入（优先派发）

- **问题：**在用户尚未确认准确月/日预算前，如何实现 provider 可替换且不超授权额度的 adapter？比较少量适合中文大学数学/英文术语/图像题的候选，分别核查结构化输出、图像计费、上下文限制、超时/拒答和请求幂等能力。
- **Grok 输出：**官方价格/币种/缓存/图像 token 计算、最大输入/输出、usage 缺失处理、requestId 查询和 idempotency 支持范围。明确“429 可重试”和“未知是否已执行”的区别；不承诺第三方 exactly-once。
- **本地实验：**同一固定题集分 hint/explain/listen 盲评；总延迟含排队和失败，费用含失败/未知预留；并发 reserve、午夜结算边界、价格版本变动、响应丢失对账。无预算时仅 fake 网络故障验证，live 保持 blocked。
- **阻塞：**T01 实际 provider 选型/计费与 T03 真实辅导；不阻塞接口或离线测试。预算金额和供应商账户由用户确认，不能让 Grok 代批。
- **落点：**T01 provider/usage/ledger、T02 输入预算、Q02 live evaluator。当前状态：waiting_grok/pending_local。

### R03 — 小规模跨语言/公式检索，何时值得向量化

- **问题：**当前文件/课程过滤＋关键词排序，面对中文问题、英文课件和数学公式，最低成本的可行基线是什么？怎样比较规范化关键词/全文、BM25、多语 embedding、混合召回，而非一开始建图？
- **Grok 输出：**固定页/结构分块与复杂分块的比较依据；中文分词、公式字符串、稀有术语、权限先过滤的失效案例；给增量索引与回退路径，不按“文档数”拍脑袋指定向量升级阈值。
- **本地实验：**人工标 gold source/chunk 的查询集；Recall@k/MRR、引用语义支持率、无答案拒答率、P95、每查询/重索引成本；按材料版本隔离，调参不得看最终 holdout。
- **阻塞：**T02 检索质量声明；不阻塞有界关键词基线。只有在固定失败集上显著改善且成本/延迟在预算内才升级。
- **落点：**T02 context/chunks、Q02 evaluation；长期算法地图搜索栏。当前状态：waiting_grok/pending_local。

### R04 — 学习证据、提示污染与延迟独立重测

- **问题：**单用户且只上传卡题，如何准确表述 observed_independent，而不推断整门课掌握？外部看答案不可观察时怎么报告？提示分层、同题重复、变式和平行题如何影响重测的教育效度？
- **Grok 输出：**retrieval practice/spacing/transfer/Variation Theory 的原始研究及适用边界；如果讨论 Yehao Chen 2026 预印本，先核实作者、版本、全文及实证性质，不能把概念提案称为稳定共识。说明独立核验、测验效应、题组等值及缺失不是失败。
- **本地实验：**人工核验 reference 的受控题组；独立/提示/揭示/未知、同题/新题、短期/延迟分开；报告分母、漏测率、错误反馈率、负担。标签型规则先做误判/拒绝判定审查，不为计算 Brier/Log Loss 而虚构概率。
- **阻塞：**L01/L02 标签含义与真实效果宣传；不阻塞保守事件记录。7/30 天收益属于后续纵向证据，不强迫首版等待 30 天才允许保存作答。
- **落点：**L01 evidence qualification、L02 precedence、Q02 人工金标与后续研究协议。当前状态：waiting_grok/pending_local。

### R05 — SRS / FSRS / BKT / IRT 的采用条件（后续研究）

- **问题：**固定两天重测、现有 srs-1、FSRS 分别适合何种记忆任务？单用户稀疏数据能否识别参数？BKT/IRT/DKT 对题目覆盖、Q-matrix、纵向轨迹、迁移可识别性有什么要求？
- **Grok 输出：**原始算法/实现版本、公开数据的训练/测试划分、冷启动和失败研究；把预测好、调度省时、学得更好三个主张分开。不要用一般复习卡准确率证明数学证明/项目能力。
- **本地实验：**保留固定规则 baseline；有合格概率输出时再比较校准/Brier/Log Loss 与负荷、延迟独立结果。单用户只能按时间/题族做隔离，不能虚构跨用户统计或泛化结论；多用户试验需另行范围批准。
- **阻塞：**只阻塞高级模型升级，不阻塞 L02。不给未经数据论证的统一样本量阈值或个人化收益保证。
- **落点：**后续 SRS/Assessment spike 和 ADR；不把训练步骤塞进 opening 27 项。当前状态：waiting_grok，deferred-adoption。

### R06 — Outbox、对象一致性、背压和恢复（优先派发）

- **问题：**PostgreSQL outbox＋BullMQ at-least-once，在 enqueue/dispatch、lease 失效、Redis 丢失和外部调用响应未知时，应怎样保持唯一业务写入并有界恢复？不可变 S3 对象与 DB 快照怎样构成可恢复备份？
- **Grok 输出：**官方 BullMQ 重复投递/锁/重试/job retention 和 PostgreSQL/S3 一致性边界；针对 PA-05/06 给事件时间线与最小协议，不推荐重写工作流平台。外部费用副作用不得等同于事务内 exactly-once。
- **本地实验：**在指定 crash window kill/restart；使 Redis 暂时不可达、租约过期、对象在备份时删除；断言唯一结果、可解释失败、无悬挂任务。观察 oldest-job、队列长度、RSS、DB pool、恢复时间；有界 admission 防任务洪峰拖垮交互。
- **阻塞：**I03/Q03 发布可靠性；不阻塞无外部副作用的纯规则。具体容量必须以目标机器实测决定。
- **落点：**I03 状态机、Q03 snapshot/journal/restore/operations。当前状态：waiting_grok/pending_local。

### R07 — 个人记忆、不保存与备份删除（优先派发）

- **问题：**已确认事实、临时状态、推断候选怎样按来源/版本进入上下文？纠正/删除后旧会话、索引、缓存、队列和旧备份如何不再恢复旧结论？所选供应商的零保留/训练使用承诺适用于哪个 API 和账户等级？
- **Grok 输出：**官方 retention/训练/区域/删除条款与配置要求；数据流清单覆盖浏览器缓存、代理/APM/错误上报、服务日志、Redis、DB、对象、备份和 vendor。法律适用有不确定性时建议专业确认，不声称一份模型报告就是合规认证。
- **本地实验：**放入合成 canary 文本，跑 no-save/失败/刷新/删除/重启/restore，检查所有应用可控持久化面；分开验证“可查看记忆”与“后续回答实际遵守更正且不引用过期事实”。第三方留存仅核政策/配置，不伪称能检查供应商内部。
- **阻塞：**M02/M03/Q03 隐私验收；稳定个人记忆不能在删除门禁未过时启用。PA-04 journal schema 可先修，不等待法律结论。
- **落点：**M01–M03、Q03、provider 数据用途/保留清单。当前状态：waiting_grok/pending_local。

### R08 — 确定性日程、估时与过度规划（后续优化）

- **问题：**截止/优先级贪心装入与小型约束求解器，在单人周课表＋休息硬约束下如何比较？什么失败案例值得增加任务拆分、切换成本、缓冲或求解器，而不是直接增加复杂度？
- **Grok 输出：**适用的 scheduling/constraint 方法、最坏复杂度、不可行解释和超时回退；区分用户锁定项与可优化项。不要用最大任务数/停留时间替代有效学习产出。
- **本地实验：**固定课表和冲突集；硬约束违规、重复 task、到期遗漏、超预算率必须显式报告；估时有数据后才算 MAE/P50/P90 覆盖、计划改动率、用户拒绝与负担。
- **阻塞：**只阻塞复杂优化和收益主张。P01/P02 的时间正确性及 PA-01/03 是本地契约/测试问题，不需要等待算法论文。
- **落点：**P01/P02、后续规划回放；保留确定性低复杂度回退。当前状态：waiting_grok，deferred-adoption。

## 3. 必须本地跑的效率/质量门禁草案 [H，未批准 SLA]

下面的数字是**用于首次基准的建议起点，不是实测结果或已批准承诺**。先取得目标服务器 CPU/RAM/磁盘/网络和准确付费预算，冻结环境、数据及阈值，再看结果；不能跑完后移动门槛。

| 测试面 | 建议首次负载/方法 | 判定及后续动作 |
|---|---|---|
| 元数据 API / 多端读写 | 两客户端；100/1,000/10,000 条 source/turn/observation；分页最大 100；稳定负载至少 1,000 请求 | 候选目标 P95≤1s；报告 P50/P95、错误率、payload、查询计划/索引。样本不足不宣传 P99。超界先查 N+1/全表读取，不先拆微服务 |
| 模型辅导 | 至少 30 个分层样本作探索性评测，类型包括照片/英文/错误推导/证据不足/倾听；重复请求并记录排队 | 元数据接受反馈候选≤1s，正文总响应候选 P95≤30s；必须同时满足语义人工检查。样本小不宣称总体准确率；不以丢弃慢/失败请求优化数字 |
| 解析/上传 | 文档 1/10/50MiB、图片到 20MiB、音频到 200MiB；页数/ZIP 展开/输出独立限额；包含恶意或损坏合成件 | 流式处理，禁整文件堆入 Web；timeout/RSS/page 上限先按目标机器分配冻结。报告每页耗时/峰值 RSS；未定预算前该门禁 blocked，而不是无上限运行 |
| 队列洪峰/恢复 | 交互请求同时突发 20 个解析作业；在租约、dispatch 和模型响应窗口故障注入 | 交互不被饿死；超容量明确拒绝/延后；无重复业务结果、无永久悬挂；记录 backlog drain time，结合实际文件耗时再冻结恢复上限 |
| 计划规则 | 100 任务＋一学期课表；重复/重叠/缺时间映射/DST/锁定项已超预算 | 候选纯规则 P95≤100ms；固定与生成反例中硬约束违规=0，不可行必须显式返回；性能结果不能替代时间正确性 |
| 检索/引用 | 至少 50 个 gold 查询作为起始诊断集；按模态/语言分层、标注无答案样本 | 报 Recall@5、语义支持率及分母；关键无依据断言/错误引用逐例修复。质量数值门槛在标注协议后、比较算法前冻结，不将 50 题当总体效度证明 |
| 备份/隐私 | 空 DB/storage 恢复＋新 journal＋删除竞态；计数/hash/引用完整性 | 测试集中未授权读写=0、已删除数据复活=0、缺对象不得静默成功；候选个人版 RPO≤24h/RTO≤2h，须用户确认并实际演练 |
| 学习收益 | 合法授权的延迟独立题；按题族/时间隔离，记录漏测与帮助曝光 | 第一阶段只报告观察/负担/错误，不输出因果提升；充分纵向设计后才检验收益，不承诺统一样本量或从 N=1 推广到所有学生 |

共同记录：commit、硬件、容器限额、依赖/provider/prompt/价格版本、样本 ID/hash/来源、随机种子、命令、时钟、冷/热缓存、并发、所有失败/重试/费用、实际输出与回退措施。对有副作用的请求，预算必须包含未知预留；业务提交、费用和供应商送达分别统计。

## 4. 研究返回后的处理规则

1. 每题单独状态：`waiting_grok → evidence_received → locally_tested → decision_recorded`；证据矛盾标 `inconclusive`，不可跳过本地门禁。用户当前未要求启动 Grok，本轮只建队列。
2. 先核原始链接/版本和反证，再形成“沿用基线 / 批准 spike / 暂缓”的建议；研究建议不自动改已批准算法或五项范围。
3. 需要代码时，更新相应 interfaces/子计划/测试；回归失败按“复现→根因→最小修复→同命令复测”留证。真实效果测试只在用户授权预算/材料范围内进行。
4. 工程明确缺口 PA-01–04/09 不排入外部研究等待队列；高级算法 R05/R08 不能成为拖延可用基础版的理由。
5. 本轮未深审的长期笔记/导入/市场/插件/离线专项，继续沿 `docs/brainstorm/INDEX.md` 原队列，在恢复对应产品范围时逐项审查；不因本次 opening 核验自动关闭旧 AIST 问题。
