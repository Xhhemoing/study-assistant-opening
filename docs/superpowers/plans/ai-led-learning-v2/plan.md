## 0. 结论与首个交付目标

二次开发的主线不是继续增加学习工具，而是将现有资料、知识、辅导、观察、复习与计划能力组织为一个**由 AI 主动编排并呈现教学内容的学习空间**。

用户从材料、主题、问题或目标进入，直接开始学习；AI 将内容组织成可理解、可交互、可追问、可暂停的活动，原材料作为随时可核查的依据。实际尝试和反馈决定下一步，用户始终能够改变路线。教学不是自动写一本讲义，陪伴不是自动控制学习。

**首个可试用版本必须是一段真实的 AI 主讲闭环：进入 → AI 开始教学 → 局部追问或换解释 → 实际尝试与反馈 → 暂停 → 跨端继续 → 可选独立题/后续回顾。**不接受“阅读器加聊天先上线、AI 主讲以后再做”作为这个版本的替代交付。可以只覆盖一门课的一个单元，但不能改变主体验。[U01]

建议首单元采用线性代数的“秩与零空间”。理由是便于同时验证文字、公式、几何互动、解题步骤与能力维度；这是工程验证样例，不意味着项目最终变成数学刷题产品。

## 1. 不可偏离的目标与明确不做的事情

| 目标 | 开发约束 | 判断是否偏离的反例 |
|---|---|---|
| G1 AI 主讲 | 首页以开始/继续学习为主；主区是 AI 组织的内容，材料按需查看 | 必须先翻页选段才获得任何教学；主要成果仍是阅读器 |
| G2 完整陪伴 | 理解、探索、实践、反馈、沉淀、复习与恢复之间可连续 | 每个功能单独存在，用户反复搬运上下文 |
| G3 用户自主 | 不强制先建课程；可以跳过、直接看讲解、改道或退出 | 先测验才允许阅读；错误或不参与阻止继续 |
| G4 可靠个性化 | 偏好可调、反馈分型、依据不足不介入 | 停留时间长就判卡住；点赞直接提高掌握状态 |
| G5 合适表达 | 同语义驱动文字、公式、图示和交互，局部可改 | 每次生成一整页任意代码；图文参数不一致 |
| G6 证据诚实 | 来源、核验方式、帮助程度、能力维度与未知均可区分 | 有引用ID就称事实正确；延迟原题叫迁移 |
| G7 连续恢复 | 保留位置、思路、实际尝试、帮助与未解决问题 | 只恢复聊天窗口；生成失败就丢草稿 |
| G8 增量可靠 | 复用原有栈、事实账本与安全机制；守现有CI与验收分工 | 推倒重建、复制评分系统、绕过权限/预算/发布门槛 |

**本轮不以这些能力为主线：**虚拟老师形象、多 Agent 同学课堂、社交和课程市场、更多通讯平台接入、全新微服务或图数据库、未经本项目数据验证的掌握率预测、端到端任意脚本生成、语音或动画数量竞赛。它们不是永久禁止，但必须证明直接服务上述目标，且不能挤占首个主讲闭环。

已有阅读器、原资料管理、自由探索、笔记和日程仍保留。它们转为教学的证据、成果与时间支持，不通过删除老功能制造“简洁”。对于尚不可靠的能力，只关闭相关入口并说明限制，不假装成功。

## 2. 本轮调研方法与验证边界

本轮使用 GitHub 连接器核对当前提交、CI 作业日志、核心契约、辅导策略、worker 与重测源码；检索用户 Library 中的旧实施指南，核对前期预算、统计口径及变更约束；查询原始论文出版页、作者摘要与可访问正文，以及官方项目/协议文档。文末与 `sources.json` 给出具体来源、读取范围和局限。[C01–C15, P01, R01–R07, E01–E04]

部分论文正文访问受出版站点限制，因此没有将“读到摘要和可检索正文片段”描述为“逐篇完整复现”。外部项目本轮只作官方文档与机制调研，没有安装部署；其功能说明不作为学习效果证据。

容器尝试克隆该仓库时因无法解析 `github.com` 失败，源码核查通过已连接 GitHub 完成。因此本轮没有完整依赖安装、仓库单元/集成测试、数据库事务测试或真实 provider 测试。项目浏览器验收继续按 AGENTS 由用户负责，未擅自运行或委派。[C01]

额外执行了两类小范围验证：

- `validate_design.py`：20 项独立设计模型检查，全部通过，覆盖偏好优先级、弱行为信号、帮助归属、跳过、延迟统计、版本/隐私条件和示例数值一致性。它是用于发现方案矛盾的独立小模型，**不是本项目代码测试，也不验证事实核验器本身是否正确**。
- `plan-validation.json`：30 个任务ID唯一，依赖无悬空、无环，8个目标均有任务映射；所有任务保持 `proposed`。这是计划文件检查，不是功能验收。

本计划分别使用“源码已核对”“设计风险”“待运行验证”“待用户体验验证”“学习效果未知”，不将它们压缩为一个完成百分比。

## 3. 研究结论如何落到开发，而不是变成宣传口号

| 依据 | 本轮采用的结论 | 不作出的推断 | 对应开发与验证 |
|---|---|---|---|
| R01 Bastani等，PNAS 2025，数学RCT | 辅助阶段的好表现不等于撤除辅助后的能力；教学保护值得设计 | 不能把该特定短期结果推广为所有AI必然有害/有益 | 作答、帮助、独立结果分离；V2-13/26/27 |
| R02 Kestin等，Scientific Reports 2025，大学教学RCT | 经过教学设计的AI辅导有值得进一步验证的潜力 | 不证明任意上传材料自动编课都有效，也不确定某个固定介入频率 | 教学活动有目标、结构和反馈；V2-02/08/16/27 |
| R03 帮助困境研究 | 何时给帮助、给多少需要考虑任务与学习情境 | 不固定“必须先挣扎”或“一错就讲完” | 用户请求优先，条件化策略；V2-11/17/18 |
| R04 提取练习实验 | 在适当目标下主动回忆可支持之后的保持 | 不是所有阅读和探究都必须做题 | 可选解释、独立尝试、延迟回顾；V2-13/21/27 |
| R05 间隔研究 | 合适的复习间隔与保持目标相关 | 不把默认两天说成个人最优算法 | 初版沿用可编辑启发式，报告范围；V2-21 |
| R06 多媒体学习研究综述 | 分段、适当前置与学习者控制具有设计价值 | 不等于越多动画/配音越好，也不把偏好固化为学习风格 | 同语义表达、可暂停、文字替代；V2-10/15/23 |
| R07 2026过度帮助预印本 | 模拟评测提示模型可能过早、过频繁或给出过多答案 | 不是对真实长期学习者的因果验证 | 独立介入策略与拒绝/延后动作；V2-11/18/26 |

研究支持初始设计与验证问题，不提供本项目已校准的最佳频率、最佳延迟、准确率或提分保证。首版参数应在受控试用中修订，而不是将论文里的效应值当作产品承诺。

### 3.1 对参考项目只取有用机制

**DeepTutor：**借鉴“先组织结构，再生成类型化内容，允许局部重写，以及教学内容与个人学习状态分离”的方式。不要照搬整个系统、后端、复杂自主运行时或掌握门槛。[E01]

**OpenMAIC：**借鉴“教学提纲→不同教学场景”的分阶段组织。AI主讲不要求同时实现虚拟教师、同学角色、TTS或多Agent社交课堂，也不要求允许生成任意HTML。[E02]

**A2UI / json-render：**借鉴声明式UI、受控组件/动作目录和schema检查。首版推荐使用当前React/Zod栈实现小目录；通过兼容性小试验再决定是否引入库。组件白名单减少任意代码执行风险，但仍须校验文本、链接、参数与动作权限，不能当作“全部安全”的证明。[E03,E04]

## 4. 当前仓库的真实起点

### 4.1 应保留的基础

现有 `learning.ts` 已区分结果 `correct/incorrect/unverified`、判断来源、帮助程度、题目与来源版本、观察修订和限制性证据状态。`read-service.ts` 从统一服务端证据读取摘要。新的教学体验应读写这套事实与资格判定，不另造一个“AI说会了”的分数系统。[C03,C08]

`tutor-turn.ts` 已具备持久任务claim、授权版本chunks、历史与记忆来源合并、预算调用、写回前privacy epoch以及完成事务参数。它是新教学生成的可靠执行基础；本轮没有证明这些全链路在当前环境运行成功，也不将旧审查里已修问题复述为现存漏洞。[C04]

### 4.2 需要处理的差距

| 现状与证据 | 对新目标的影响 | 改造原则 |
|---|---|---|
| 当前CI失败；日志指向material-library.tsx的`react-hooks/exhaustive-deps`规则定义缺失；后续主检查未跑 [C09,C15] | 不能把此提交当已通过发布基线 | 最小修复、重跑真实失败，按现有CI完成质量检查 |
| `learningSessionCreateInputSchema`要求courseId/skillLabel；会话帮助函数偏hint/explain [C03] | 自由主题/探索不能直接套这条正式会话路径 | 增加可空课程的活动上下文并兼容单一事实服务，不伪造课程 |
| thin推荐路径无currentPage会澄清，hint曝光后可推荐worked_example [C02] | 页面操作成为教学前提；帮助升级条件过粗 | 新主讲入口从目标/活动出发；深度由请求、实际尝试和权限共同决定 |
| explain按模式记录revealed，worker可带attemptId但problemId为null [C02,C04] | 将AI讲课直接套此模式可能使概念教学与题目答案暴露混淆 | 区分instruction和针对item/attempt的帮助，保持旧记录保守解释 |
| 重测缺维度默认transfer，技能标签回退取首个匹配节点 [C05] | 延迟不自动等于迁移，重名/重命名可能误关联 | 创建题目时绑定稳定身份与测量要求；缺信息保留未知 |
| 推荐仍依赖粗布尔汇总；技能证据已存得更细 [C06,C07] | 旧正确、最新失败、不同维度可能不足以影响选择 | 改进只读汇总输入，不重新训练复杂掌握模型 |
| 合法引用ID、软页过滤不能单独验证主张 [C02,C04] | 整节AI教学需要更强支持关系和覆盖检查 | 新增教学编译后的内容审核，不全局恢复强制页码 |
| K02验收是限定工程范围，浏览器/实际教学效果尚有空缺 [C13] | “verified”不等于用户已学会或产品体验完整 | 分开记录工程、真实模型、用户体验、学习效果 |
| 旧K02a范围排除一键课堂等 [C10] | 与新AI主讲优先级冲突 | 显式修订范围；不以旧排除阻止当前目标 |

`variantProblemRef()`改变的是题目引用字符串，不生成或验证新的题干。这是一个函数职责边界，不能直接证明当前生产已经误授独立证据，但必须防止二次开发把“换ID”当作“新题证明”。[C02]

## 5. 产品结构与用户旅程

### 5.1 主界面

桌面主要区域是当前教学活动；小范围提纲提供方向；追问/换解释/自己试试就在当前内容附近；原材料和依据按需展开；草稿与成果有稳定位置。移动端保留同一活动语义，不把整个桌面三列缩窄后堆到屏幕。首页优先“继续上次”“开始一次学习”，计划提醒退为辅助。[U01]

首屏不要求用户理解KnowledgeNode、workspace graph、模型参数和评估权重。可以选择“理解概念、解决问题、系统学习、自由探究”等自然意图，但不能以填完问卷作为开讲前提。已有偏好作为建议起点，用户可随时纠正。

### 5.2 一次学习的基本循环

**进入 → 形成当前教学意图 → AI准备当前活动 → 用户阅读/操作/表达/实践 → 适量反馈 → 修改或继续 → 保留成果和断点 → 可选后续。**

它不是不可跳过的状态链。阅读、探究、论证与作品可以只有过程产出而没有正确率；没有完成检测也能结束。用户要求完整推导时提供推导，并如实记录相关题目是否暴露答案。

材料很长时先形成小范围提纲，详细编译当前活动，最多按预算预取有限后续，不一次性生成整门课。已发布活动固定版本；后续路径变更不篡改已发生的教学和作答。

无材料入口可以开始，但必须区分“基于可核查材料的教学”和“一般知识讲解/补充”。具备被授权检索能力时查找来源；没有时不伪造参考文献或偷偷引入另一个外部服务。需要强核验的主张不得自动升级为已核验结论。

### 5.3 首单元样例

以`T(x,y)=(x+y,0)`引入问题：二维输入为什么只剩一个输出方向？先观察输入与变换结果，再解释零空间与像的关系，随后呈现正式定义和计算示范。用户可以请求更直观、更多证明、完整讲解、用英文术语或跳过某活动。

互动的矩阵、输入向量、输出向量和文字结论读同一参数模型。之后的独立题不能仅换引用ID，也不能把示例换两个数就自动宣传为迁移。恢复时显示真实草稿、曾给的具体帮助与尚未核验能力，而不是“你已掌握90%”。

## 6. 系统设计：在现有架构内增加教学组织层

### 6.1 五类概念，避免重复建模

| 概念 | 职责 | 不承担的职责 |
|---|---|---|
| LearningActivity（学习活动上下文） | 当前意图、owner/workspace、可选course、路径、版本和断点 | 不自动生成掌握事实 |
| TeachingUnit / ActivitySpec | 教学目标、内容块、来源关系、教学动作、验证状态 | 不另存一套用户作答账本 |
| 统一资产与内容Revision | 教学正文、用户笔记/草稿等各自的权威内容与版本 | 不将教学正文在多个表无差别复制 |
| 原始Observation / Attempt / Exposure | 实际尝试、帮助、核对与修订 | 不将完成度、点赞或访问时长当成绩 |
| LearningEpisode只读投影 | 跨材料与活动重建“发生什么、下一步是什么” | 不成为另一套评分/事实来源 |

先由V2-03核实统一资产承载能力。推荐正文尽量复用现有Document/Block/Revision；若必要字段不能表达，通过一项范围明确的ADR增加教学元数据和索引，不为了未来想象设计通用内容操作系统。[C01,P01]

**无课程兼容方案：**新活动始终有workspace+owner+activityId，courseId可以为空。新v2事实写入仍进原有服务与表，在迁移批准后允许活动范围的观察；旧API保持courseId必填。已有课程查询只读取其范围，新的活动读取复用相同资格判定。禁止创建用户看不见的假课程，也不因为无课程就弃掉用户作答或把它存成第二套不可合并事实。需要核对所有SQL约束、外键、归档与读路径后才能实施，不是简单改一行nullable。旧LearningEvent v1只能接受其原本能表达的、已适当核验并映射的观察；没有课程或不能表示的观察保留在原始观察层，不强塞布尔正确事件，也不丢弃记录。

### 6.2 教学生成链

**目标/材料/允许的学习上下文 → 授权来源包与覆盖关系 → 小范围教学提纲 → 当前ActivitySpec候选 → 结构与内容核验 → 持久化新版本 → 受控渲染 → 用户命令/尝试 → 更新路径候选。**

模型负责提出教学结构、解释、例子和反馈候选。程序负责事实范围、版本、权限、预算、组件执行和记录。不能让一次模型返回同时发布内容、决定掌握、覆盖历史并写入正式计划。

模型角色可以在同一个provider调用框架内按阶段划分，不等于需要多Agent自治系统。现有provider-neutral适配与用户选择保留，新增输出schema应与现有`ProviderOutput`兼容扩展或独立版本化，不能破坏旧辅导响应。

### 6.3 拟议接口轮廓

下列路径是新增接口提案，不声称已存在：

| 接口 | 作用与约束 |
|---|---|
| `POST /api/opening/teaching/activities` | 自由创建；intent/material refs/course可选；服务端设置owner与版本 |
| `GET /api/opening/teaching/activities/{id}` | 返回可读教学块、断点和状态，不返回未揭示答案 |
| `POST /api/opening/teaching/activities/{id}/commands` | next/skip/rephrase/expand/branch/return；携带clientKey与expectedVersion |
| `POST /api/opening/teaching/activities/{id}/feedback` | 分型反馈、作用范围、目标活动；不修改能力事实 |
| `POST /api/opening/teaching/activities/{id}/checkpoint` | 保存草稿与可恢复状态；与生成结果版本冲突显式处理 |

正式作答、观察修订与复习候选走现有服务的v2适配，不另写一个直接给correct=true的教学接口。所有参数仍在HTTP/模型/持久化不可信字段边界校验；内部类型化数据不反复“防御验证”。[C01,C03]

### 6.4 两组状态必须分离

生成状态例如`queued/generating/needs_check/ready/failed/unknown/cancelled/stale`；学习活动进度例如`active/paused/completed/skipped`。前者是内容能否使用，后者是用户走到哪一步，两者均不能自动等于能力掌握。

幂等按逻辑命令+owner范围+已有版本机制实现。不额外发明内容hash体系来替代主键、版本、事务和唯一约束。若网络结果未知，先查已持久任务；外部请求是否已执行无法确认时，不承诺端到端exactly-once，也不自动释放预算再重试。[C01,C04,P01]

### 6.5 教学内容的核验层

**结构层：**块类型、必要参数、长度、可用动作和资源范围。

**引用身份层：**来源属于用户授权范围、版本存在、锚点可回查；材料同页不混淆。

**语义支持层：**主张与材料是否真正相关、条件是否遗漏、是否只是AI推断。模型可做候选审核，但不能因其自报confidence高就作为结论。

**可核验内容层：**确定性计算采用实际计算/符号检查；程序结果来自受限测试；开放证明与作品承认可接受解多样及无法自动确定。测试通过不等于程序全部正确，符号等价也不等于证明所有条件成立。

**发布与继续边界：**核心结论未核验不得以“已核验教学”发布；可以给出明确的讨论/待核对状态。来源删除、隐私变化与活动版本冲突在读取、发给模型前、最终写回时各按现有边界处理。

完整合法JSON不保证事实正确，真实引用不保证覆盖充分，第二模型同意也不提供独立真值。三个错误不能互相替代。

## 7. AI介入与教学决策

### 7.1 明确偏好先上线，推测性适应后上线

首版即提供“尽量少打断/适度陪伴/主动带练”等快捷预设，但内部时机、频率与帮助深度分别处理。会话临时选择优先于课程偏好，再优先于全局默认。学习模式与自动化操作权限分离；喜欢主动教练不等于允许自动删除资料、改长期计划或增加外部数据传输。

无需重新询问已知偏好。用户说“本次直接讲，不要考我”，立即生效；安静模式不妨碍用户主动求助。只改变当前范围，不将临时疲惫推断为永久偏好。

### 7.2 决策次序

先确认用户明确请求与授权，再检查是否存在可靠需要帮助的依据；然后检查内容的可信程度、当前节点是否适合打断、最近反馈与重复提示情况；最后从有限动作中选择响应、轻建议、延后或不介入。

长时间停留、滚动、视频暂停单独不足以判定卡住。低依据时不主动纠正；用户求助而内容不确定时解释不确定并共同核查，而不是不允许用户继续。用户正在推导或输入时不抢焦点，除非明确要求实时帮助。

初始策略使用可解释规则，不训练在线黑箱。冷却时段、候选数量和预取量是可配置工程参数，并非论文给出的最佳值。模型可建议动作，但不得绕过用户限制。

### 7.3 分型反馈

| 反馈 | 可立即更新 | 不应更新 |
|---|---|---|
| 现在别打断 | 当前介入节点/密度 | 学科能力 |
| 提示过多/透露答案 | 帮助深度 | 对整个学科的兴趣 |
| 换一种解释 | 表达方式与例子 | 一次性贴固定学习风格标签 |
| 判断不对 | 暂停依赖该判断，复核证据 | 只微调权重后继续认定相同错误 |
| 有帮助 | 类似情境下的偏好候选 | 掌握状态、独立完成率 |

明确偏好变化可以快速生效；教学效果改进必须谨慎，需要可比较的实际表现。缺少复测时保持未知，不把未提交算错，也不能从统计分母删除后宣称策略更好。[R01,R03,R07]

## 8. 教学表达、交互与无障碍

第一版目录包含结构化文字、公式、分步说明、例题、问题、草稿、来源和一个矩阵变换互动。之后按真实任务增加关系图、参数演示、对比与论证场景。每一类都说明“帮助用户理解什么”，不是为炫技添加动画。

语义内容与布局分离。用户要求更直观、更多证明、更简短或调整英语比例时，只修订相关块或表达，不重生成整节课。文字和图示使用同一组参数；无法正确渲染时回退静态表达并保留用户状态。

候选组件与动作需白名单。禁用任意eval、任意shell、生成页面脚本和不受约束的外链加载；代码实践使用独立、限资源、默认无外网的执行适配，不能在主站服务里直接跑用户代码。没有可用沙箱时诚实标记未执行。[E03,E04]

支持键盘操作、可暂停、可回看、减少动态效果、图示文字摘要及不只靠颜色编码；用户在阅读的块不因后台生成而跳位。现有AGENTS要求Tailwind工具类与lucide-react，新的UI工作按这些约定实施，不引入无关样式系统。[C01]

## 9. 学习证据与复习闭环

教学讲解是学习过程；题目帮助是对某次作答的影响；独立表现是有条件的观察。这三者必须分别建模。`instruction`不自动污染整个知识点后续尝试；但对同一道题看过答案不能靠新建session或更换ID洗成独立。[C02–C05]

新题判定依据题目实际内容/来源身份/版本及与旧题的关系，不以字符串变化证明；延迟标记和迁移维度分别确定。题目生成时就记录测量目标与维度；找不到稳定nodeId时保留待关联，不按同名首个节点随便挂载。

`delivered`只说明系统记录的帮助已可获得，不代表用户一定阅读，也不能排除用户在纸外或其他软件获得帮助。产品应使用“本系统未记录针对该题的帮助”等准确说法，不能把日志当成对现实世界的全面监控证明。[P01]

正常学习产生的成功、错误与未知都保留。`observed_independent`是有限的证据状态，不改称全面掌握。自对照、教师核验、程序判定与模型建议维持可区分方法和适用范围。

学习结束可以草拟简短总结与少量后续候选；用户选择性沉淀笔记/卡片/题目，正式计划变更按现有规则确认。复习沿用L02与计划桥接，调用Opening实际`planDay`路径，不误用历史`buildTodayPlan`。复习间隔初版仍为可编辑启发式，不宣称已经训练FSRS/BKT。[C11,P01,R04,R05]

### 9.1 正确的延迟效果口径

先定义可用于测量的条件：题目/版本适用、延迟窗口满足、帮助状态可解释、结果已适当核验。**这些条件不能包括“做对了”。**然后再在合格观察中数正确与错误。

`观察到的延迟独立正确率 = 合格观察中的正确次数 / 合格观察中的正确次数与错误次数之和`。

同时报告邀请/到期总数、参与数、缺失、接受帮助、版本失效、过早与无法核验。空分母为未知，不是0%或100%；不同条件排除可能重叠时另报不重复总数，避免相加失真。过程数据不自动提供因果结论；正式试验另按预先约定的意向性分析与缺失处理。[P01]

不同教学策略可能改变求助和参与概率，因此不能只比较两组中“最终独立且可评价”的子集就宣称因果效果。正式试验需对所有分配参与者定义主要结局，预先规定缺失数据、退出、帮助使用及敏感性分析；本段条件性正确率只是过程指标。

本轮设计小模型中的示例为：1次正确、1次错误、1次未知、1次受助。可评价独立结果为2，正确率1/2；另外2次必须报告。只先选“独立且正确”再计算会得到虚假的100%，因此该错误被列为回归测试。

## 11. 具体验收方案

### 11.1 工程与用户体验

首个完整旅程必须覆盖：无课程从问题进入、真实模型开始教学、查看依据、要求完整解释、跳过活动、提交原始尝试、请求同题帮助、换题再尝试、生成中刷新、另一设备继续、材料撤回后继续、网络失败与预算不足。

验收不是所有场景都成功生成内容；拒绝越权、预算不足不调用、失效引用不显示和未知状态不伪报成功同样是正确结果。核心目标范围内必须有已核查教学或明确的未覆盖说明；不能用人为缩小分母伪造“覆盖100%”。

**发布阻断项：**已确认的数据丢失、跨owner访问、无授权外传、来源撤回后回流、未揭示答案泄露、生成动作越权、严重且未修的教学错误、将受助/未知记录自动提升为独立掌握。它们接入现有不可逆边界与发布检查，不另建与原CI冲突的治理系统。[C01]

性能记录首个已检查教学块、后续响应、恢复时延、失败率与实际费用。可在固定测试环境提出“暖上下文首块p95≤20秒、已持久活动恢复p95≤2秒”等**初始工程目标**，在实测基础上调整；这些不是已测数据、论文结论或跨环境保证。冷上传解析单独统计，不用首个未验证token伪装“已经可学”。预算用用户确认的上限B，而非模型自行许诺费用。

### 11.2 实施时验证命令

沿用仓库实际规则，先核对包级AGENTS。对已新增的具体文件运行最近的测试，例如：

```bash
node node_modules/vitest/vitest.mjs run --project unit packages/domain/src/opening/intervention-policy.test.ts
node node_modules/typescript/bin/tsc -p packages/domain/tsconfig.json --noEmit
```

集成测试只在**事先确认的独立测试库**中设置`OPENING_TEST_DB=1`和测试库连接，按修改范围执行。禁止把示例命令连接到用户数据库。完整lint/typecheck/test/build留给现有CI或另行明确请求，不在没有变化时反复全跑。浏览器测试维护，但Agent未经授权不自行执行；现有CI浏览器检查照旧，不为省事删除或跳过。[C01]

本轮附带的`validate_design.py`命令与以上不同：它只执行方案小模型，可在本交付目录直接运行；不能把其20项通过写进仓库CI通过清单。

### 11.3 真实教学验证

先做少量同意参与者的可用性观察，建议5–8人为探索性工程起点，仅用于发现流程问题，不能检验普遍提分。记录用户能否开始、理解当前动作、调整路线、继续断点，以及哪里增加了确认和操作负担。

随后再设计效果比较：预先冻结材料与评测版本、学习目标、主要结局、分配方法和缺失处理；依据试用方差、最小重要差异、重复测量及分组结构确定样本量。不能把前述人数直接用于显著性结论。

可以比较相同素材下的“基础材料辅导”与“AI组织教学”，以及规则介入与反馈适应；对照是研究条件，不是把产品默认方向改回阅读器。评测题与答案不得提供给教学模型或出现在用户教学材料中。优先记录独立新题、解释/迁移/应用任务与延迟表现，满意度、时长与帮助依赖作为不同指标。仅有前后进步或模型模拟，不做因果效果宣称。[R01,R02,P01]

学习者可以退出、求助或看答案；这些行为按协议如实记录，不以实验需要限制其正常学习。出现可靠的内容伤害或明显负担增加时停止相关策略，保留稳定路径。

## 12. 风险、迁移与发布

| 风险 | 优先处理 |
|---|---|
| 新体验只是好看的长讲义 | M1必须有追问、可选真实尝试与反馈、暂停恢复，不以生成篇数验收 |
| 有引用仍讲错/漏条件 | 建覆盖关系与主张核验；严重错误单列，不让平均分掩盖 |
| 自动化把用户带偏 | 显式偏好与可撤销路径，长期计划不静默变更 |
| 新上下文复制了学习事实 | 单一原始观察与资格判定；Episode只读，内容仅一个权威存储 |
| 帮助曝光或重测语义不当 | 按item/attempt/版本归属，独立与迁移分开，未知不升级 |
| 整节重生成丢草稿 | 局部版本补丁、expectedVersion与冲突保留；历史内容不改写 |
| 生成成本/等待时间失控 | 小范围提纲+当前活动，有限预取/修复；unknown先核对不盲重试 |
| 来源/个人信息跨用户缓存 | 每次授权、隐私epoch、来源失效、用户状态隔离 |
| 增量迁移难回退 | 先扩展后读写切换，功能关闭不删用户数据，备份从新持久化上线即覆盖 |
| 任务完成掩盖体验/效果未知 | 分层报告，用户未验收保持pending；效果不足不作提分宣传 |

发布采用按用户/能力类型feature flag，不将全部用户直接切入未验证教学生成。先保证旧功能兼容；新内容和个人状态分离；不对历史观察统一补写correct、independent或transfer；不在撤回功能时丢失用户已生成的笔记与草稿。[C01,C03]

正式发布仍使用当前SHA的现有CI与授权流程。新真实学习研究若只能说明“可使用、体验问题减少”，可据此限定范围发布工具，但不得扩写为“已证明学习效果显著提升”。本计划不要求为了宣传效果把用户锁进强制测验。

## 13. 这份计划的实际执行起点

第一批工作是**V2-00（目标收口）、V2-01（真实CI失败修复）、V2-02（一个可核查教学单元）、V2-03（活动/内容/证据兼容设计）**。这四项结束后，立即推进可串起来的AI主讲切片，不转去扩展与主体验无关的接入和外围平台功能。

本计划的最终判断标准只有一条主线：**用户进入之后能否直接开始可信的AI教学，能够思考和实践、获得适当帮助、自主改道，并在下次自然继续；每项能力结论都有对应证据边界。**
