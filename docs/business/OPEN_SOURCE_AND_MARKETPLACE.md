# 资源平台、开源与商业化

## 1. 战略原则

- 开放用户数据、协议和迁移能力；
- 收费于稳定云服务、高质量资源、AI成本、机构能力和运营保障；
- 不以阻止导出作为护城河；
- 资源平台先解决备考内容供给，不做泛社交信息流；
- 共享内容、个人状态和班级状态分离。

## 2. 资源平台对象

每个 `ResourcePackage` 包含：

- 名称、作者和机构；
- 适用考试、年份、地区和教材版本；
- 科目和考纲覆盖；
- 内容版本和变更记录；
- 题目、题解、卡片、例题、量规和学习路径；
- 来源与版权许可；
- 审核状态；
- 依赖的其他资源包；
- 推荐场景策略，但不能强制覆盖用户策略。

资源包可以：

- 固定版本；
- 跟随更新；
- Fork为私有版本；
- 向上游提交改进；
- 导出为开放包；
- 被教师下发到班级。

## 3. 内容与个人状态分离

```text
ResourcePackageVersion
  └── ContentItemVersion
          ↑
          └── Attempt / Review / Note / Error by each user
```

发布者更新内容时：

- 创建新 `ContentItemVersion`；
- 历史作答继续引用旧版本；
- 用户选择跟随、固定或 Fork；
- 个人复习间隔、错因和笔记不被覆盖；
- 如果答案发生实质变化，系统标记旧预测需复核，而不是静默重算。

## 4. 快速供给策略

### 第一层：官方种子包

只选择一个垂直场景，建立：

- 官方考纲；
- 章节和考点；
- 代表题；
- 题型；
- 基础错因；
- 真题和评分标准；
- 资源版本映射。

### 第二层：邀请制教师和创作者

提供导入模板、版本工具和审核后台。早期用合同、分成或固定报酬保证质量，不依赖纯用户自发贡献。

### 第三层：社区 Fork 与纠错

开放：

- Fork；
- 差异比较；
- 错误举报；
- 修正提案；
- 版本讨论；
- 个人私有修改。

### 第四层：AI候选内容

AI生成内容必须标记：

- 使用模型；
- 来源；
- 生成时间；
- 审核状态；
- 是否通过支持性检查。

未经审核的AI内容不能与官方或教师审核内容使用相同质量标识。

## 5. 资源质量评分

不使用单一星级作为排序依据。内部评分考虑：

- 来源完整性；
- 版权和许可；
- 教师/专家审核；
- 答案争议率；
- 考纲匹配；
- 版本新鲜度；
- 题目统计质量；
- 举报和修复速度；
- 使用后同类错误变化；
- 用户目标和阶段适配性。

默认UI只显示少量标签，例如：

- 官方；
- 教师审核；
- 社区验证；
- AI生成未审核；
- 适用于2027考研；
- 与当前教材版本匹配。

详情页可以展开质量依据，开发者设置可查看评分组成。

## 6. 社会化学习范围

MVP支持：

- 资源包分享；
- Fork和版本更新；
- 学习小组共享计划模板；
- 教师下发任务；
- 匿名聚合的常见错因；
- 优秀解法和解释对比。

MVP不做：

- 泛内容信息流；
- 公开个人掌握排行榜；
- 强制打卡社交；
- 无审核私信；
- 以互动量作为主要学习质量指标。

## 7. 开源分层

### 建议开放

- 学习数据 Schema；
- 资源包规范；
- 导入导出协议；
- 迁移校验器；
- 本地/服务端基础领域规则；
- 插件 SDK；
- 基础适配器；
- 自托管参考配置。

### 可商业闭源

- 官方托管云；
- 高可用同步和托管备份；
- 高级AI路由和批处理；
- 机构管理、审计和SLA；
- 官方资源审核后台；
- 支付、版权保护和市场运营；
- 反作弊和高级分析；
- 专有高质量内容。

## 8. 许可证候选

最终许可证需法律审查。建议基线：

- Schema、资源规范、SDK：Apache-2.0；
- 本地核心和通用领域包：MPL-2.0 或 Apache-2.0；
- 若希望网络部署修改必须公开，可将特定服务端模块采用 AGPL-3.0；
- 官方云和机构模块：商业许可；
- 每个资源包：单独版权与内容许可。

不建议在缺乏清晰商业目标时把整个仓库一律设为AGPL，也不建议以“开源”名义发布不可运行的残缺核心。

## 9. 商业模式

| 收入来源 | 用户价值 |
|---|---|
| 免费基础版 | 基础目标、练习、有限云空间和社区资源 |
| 个人订阅 | 云同步、高级AI、更多存储、复杂预测和导出历史 |
| 资源购买/订阅 | 经过审核的真题、题包、解析和学习路径 |
| 创作者市场抽成 | 支付、分发、版本更新、版权和质量工具 |
| 教师/班级版 | 下发、班级聚合、作业、资源管理和反馈 |
| 学校/机构版 | SSO、权限、审计、私有部署、SLA和支持 |
| 模型额度 | 对高成本生成和解析进行透明计费 |

免费版必须允许导出用户自己的原始数据。付费不能成为数据赎回费。

## 10. 开源与商业治理

- 公布稳定协议与兼容性政策；
- 公共路线图区分社区核心与官方云；
- 外部贡献需要 CLA 或 DCO 策略；
- 安全漏洞有私下披露渠道；
- 资源版权争议有下架和申诉流程；
- 官方云的模型、存储和资源费用透明；
- 商业模块不得破坏开放格式兼容性；
- 自托管版本有明确支持窗口和升级路径。

## 11. 市场冷启动

1. 选择一个考试和一门高价值科目；
2. 制作一个可证明质量的官方种子包；
3. 与少量教师共建资源和错误分类；
4. 用真实学生完成4至8周闭环试验；
5. 公开资源版本、纠错速度和学习效果指标；
6. 再扩展相邻科目或同类考试；
7. 稳定后开放更广泛创作者入驻。

不要以资源数量作为冷启动成功标准。早期更重要的是：内容正确、能更新、能关联个人状态，而且确实推动学习任务完成。
