# 信息层级与 AI 交互规则

## 1. 三层信息设计

### Layer 1：默认结果层

面向绝大多数用户，只显示：

- 状态词；
- 少量结果性数据；
- 下一步行动；
- 可展开入口。

状态词固定为：

- **稳固：**当前场景已有足够稳定证据；
- **可用：**大部分基础任务可完成，但存在明确限制；
- **薄弱：**近期失败或关键能力不足；
- **未测：**没有足够有效证据。

状态不使用“95%掌握”文案。必要概率用于内部排序，默认不展示。

### Layer 2：原因与解决层

点击状态后打开抽屉，结构固定：

```text
为什么
- 最近两道变式题均在分类讨论处失败
- 基础题已稳定，不建议继续重复

怎么改善
- 做1道步骤提示题，预计8分钟
- 做1道无提示变式，预计12分钟

其他操作
- 原因判断不准
- 暂时跳过
- 调整优先级
```

原因必须指向可执行干预，禁止只展示没有行动意义的复杂分析。

### Layer 3：开发者设置

开发者模式显示：

- 原始学习事件；
- 派生能力切片；
- 状态映射规则；
- 时间衰减、证据权重和最低样本；
- 场景模板继承链；
- 模型版本和运行日志；
- 预测校准数据；
- AI输入摘要、输出及审核状态；
- 参数覆盖、模拟和重新计算。

开发者设置必须有警告、重置、导入导出和变更预览。修改参数产生新版本，不原地篡改历史结果。

## 2. 默认首页信息预算

桌面端首屏最多包含：

- 今日任务列表；
- 一个总进度区；
- 最多三个高风险点；
- 一个近期趋势；
- 一个主要操作。

移动端首屏优先显示当前任务和下一步，不堆叠分析卡片。

每个考点行最多显示一个状态词和两个补充字段。详细内容进入抽屉或独立页面。

## 3. AI 介入模式

### 手工模式

- AI只响应用户请求；
- 不自动生成正式卡片或题目；
- 不自动改变计划；
- 可用于检索、解释和格式整理。

### 副驾驶模式，默认

- AI生成候选卡片、错因和下一步；
- 写入正式知识或题库前由用户确认；
- 可自动完成低风险元数据工作；
- 高影响计划变更需确认。

### 教练模式

- AI可在用户设定的时间预算内调整今日队列；
- 仍不能静默修改来源事实、正式答案和历史事件；
- 用户可查看每日调整摘要并一键撤销。

### 冲刺覆盖

冲刺不是第四种AI模式，而是临时策略覆盖：提高模考、错题和限时任务权重，限制新增资料和低价值整理。

## 4. 自动化权限矩阵

| 操作 | 自动 | 建议后确认 | 必须手工 |
|---|---:|---:|---:|
| OCR、元数据、格式转换 | 是 |  |  |
| 去重候选、考点候选 | 是 |  |  |
| 今日任务排序 | 教练模式 | 副驾驶模式 | 手工模式 |
| 生成卡片和变式题 |  | 是 |  |
| 错因分类 | 低置信候选 | 是 | 用户可纠正 |
| 改变长期策略 |  | 是 |  |
| 无提示回忆、正式解题 |  |  | 是 |
| 删除、公开或出售内容 |  |  | 是 |
| 修改官方答案或来源事实 |  |  | 是/审核流程 |

## 5. 防止 AI 代学

程序性、迁移和表达任务默认执行：

1. 先让用户尝试；
2. AI提供最小必要提示；
3. 保留原始答案；
4. 展示解析和差异；
5. 用户重新完成；
6. 使用新情境验证迁移。

用户可主动选择直接看答案，但该次行为不能作为高质量掌握证据。

## 6. 结果与原因的关联

每个结果必须包含机器可读的：

- `status_code`；
- `summary_metrics`，最多三个；
- `reason_codes`，按重要性排序；
- `recommended_actions`；
- `evidence_snapshot_id`；
- `strategy_version`；
- `model_version`。

默认UI只渲染前四项的精简文本；展开层和开发者模式读取相同对象，避免不同页面给出互相矛盾的解释。

## 7. 无障碍和可理解性

- 不仅用颜色表示状态；
- 所有图表提供文本摘要；
- 键盘可以打开原因抽屉和完成任务；
- 状态词含义在产品内保持一致；
- 不使用负罪感、羞辱或虚假紧迫文案；
- 模型失败时降级为规则队列，并明确显示任务仍可继续。
