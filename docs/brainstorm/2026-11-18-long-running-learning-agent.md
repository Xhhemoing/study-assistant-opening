# 长效学习 Agent 的候选架构

学生可以托付未来六周的备考，也可以随时打开一篇随笔。助手要记得两件事各自做到哪里，判断外界变化影响哪件事，在学生可以作决定的地方提供帮助。本文对照 `c9072ef5` 的现有实现，提出供讨论的设计。

## 从 DeepSeek 的 Super-agent 借什么

用户指的是 DeepSeek Harness 团队 2026 年 10 月 31 日的《Super-agent 设计探索：迈向更自主的 Agent 系统》。微信直链本次显示环境验证，正文由团队同步全文和中文转载交叉核对。作者讨论连续、高效、主动、持久四项能力。Router 协调多项任务和人的注意力，独立 Worker 保有各自的上下文；有明确归属的后续事件可以直接交给订阅者。系统可以在后台工作期间接收新指令，也能从摘要沿引用取回原始依据。公开代码是研究原型，只实现了文中部分构想。其合成任务实验衡量调度，学习质量要另行验证。[微信原文](https://mp.weixin.qq.com/s/zoS7GlReWPhfCjENGxXCdg) · [作者同步全文](https://x.com/DeepSeekHarness/status/2116857257245987236) · [中文转载](https://www.chaincatcher.com/article/2300676) · [官方研究原型](https://github.com/deepseek-ai/dsh-superagent-prototype)

在学习产品里，整理讲义、发现冲突、准备备选练习可以委托；写下一版论点、决定是否看提示、独立解出一道题要给学生留出空间。文章中的任务引用可以帮助手找回上次讨论。课程概念之间的先修关系还需要教学来源，学生能力判断还需要作答和帮助记录。三者可以互相引用，各自保留判断依据。

## 推荐的产品组织

**共享一个能跨周接续的学习助手，让每项活动拥有自己的工作空间、作品和判断方式。** 单一会话流程容易做出统一首屏，但会限制创作、实验等开放任务。把每项能力都做成独立 Agent 又会让学生反复交代背景，并把课程和个人时间冲突留给人处理。建议保留现有入口，只在需要跨活动接续、协调时间或说明变化时共享状态。

- **公共内核**保存学生托付的范围、目标与期限、跨课可用时间、可自动执行哪些事，以及最近使用的活动和作品版本。打开助手、课程、笔记或图中节点，都能回到同一份作品。可用时间和授权以已保存设置为准，学生可以随时修正、暂停或取消委托。
- **学习活动**负责接受哪些动作、哪些产物需要保存、怎样恢复、什么算完成。练习拥有提示和复测规则，写作拥有多个稿件、逐段反馈和版本比较。通用界面可以显示“已保存”“继续上次”，活动自己决定恢复到哪段和有哪些下一步。
- **事件协调**复用现有数据库、事务和任务队列。资料就绪直接通知受影响课程，改评直接交给学情和复测；当多个目标争用时间或新材料的意义需要解释时，再请助手综合判断。在授权的材料范围内，模型可以发现规则没有预列的关联并提出建议；结论能沿引用回到讲义原段、稿件版本或具体作答。
- **主动程度**随委托而定。平时静默准备可逆的草案，学生回来时合并展示有意义的变化；在学生选择的提醒条件下，才为即将到期或必须取舍的事情打断。改变已接受的安排要符合授权，跨课挤占时间要显示代价。缺席期间保留草稿，重新回来先核对还有效的任务。后台推进依赖实际运行的 Worker 与持久任务，恢复时检查有效期、回执和预算。

## 知识图谱怎样跟上每一次相关变化

| 发生了什么 | 希望学生看到什么 | 由谁更新、何时生效 |
| --- | --- | --- |
| 老师补发一份讲义，或撤回一份资料 | 能看到新讲义的处理状态；已失去权限的内容不再被展示或引用 | 资料与课程模块在变更提交时记录事实及受影响课程。读取时按当前权限判断。解析就绪后才提取概念。 |
| 新章节提出额外先修，或两章出现同名概念 | 可以打开更新依据，看到受影响的要求和练习；尚在核对的关系有清楚标记 | 构图任务处理变化的章节，复核跨章节关系。改名、拆分、歧义过大时扩大范围，必要时全课程重建。复用含义相同的节点身份，历史作答绑定原含义。 |
| 学生独立答对、看过提示，或纠正一次误评 | 能立即核对作答记录，并看见哪条复测建议因此变化；课程结构可以保持稳定 | 学情模块按有效作答版本、帮助记录和要求重算证据。一个人的表现可支持“可能需要补某概念”的假设。修改课程先修关系仍须有相应教学依据。 |
| 学生为某一段笔记链接一个概念 | 下次从笔记或概念均可找回这条关系，随后可选择打开原资料或练习 | 笔记负责显式链接，资产查询组合当前可读的笔记、课程和作答。学生可以纠正或解除自己建立的链接。 |

一个能检验设计的反例是：正在整理第一份讲义时，第二份讲义完成解析并加入课程。读取旧材料的任务随后成功，也可能交付缺少第二份讲义的图。设计应保留这次新增的待处理记录，合并重复任务，直到补齐。界面展示本次任务的结果和实际覆盖的资料。目前界面以课程图版本上升推断“已整理”，而确认单个节点同样会提升版本。这是对现有源码的并发时序分析，尚未经运行复现。[整理状态](../../apps/web/src/features/opening/knowledge/knowledge-rebuild-control.tsx) · [图谱写入](../../packages/database/src/repositories/opening-knowledge.ts)

## 三种可以直接体验的交互

1. **临时只有十五分钟。** 学生在讲义旁说“今晚只有十五分钟”。助手列出能做完的一个练习、会顺延的事项及期限影响，允许直接采用或继续读。学生次日从手机打开仍可回到上次那道题和已写步骤。
2. **从变化追到行动。** 打开复习建议，看到“新讲义补充了一个先修概念”。点开可对照讲义原段、上次在这一步的作答与提示，再选“先试一道”“我已经学过”“这两处是不同概念”。纠正后保留原记录并更新后续建议。后台处理期间可以继续写作，回来查看这次调整影响了什么。
3. **没有课程也能写。** 新用户直接起草一段文字，分别请求论证和语言反馈，从初稿派生两版，比较后只采纳一句。下次直接回到 B 稿改了一半的段落。之后由学生选择是否将某段作品关联到英语课；助手润色过的版本保留帮助记录。编辑器用稿件和反馈表达进度，无需编造总步数或完成率。

## 怎样判断能力和效率是否真的提高

先对照现有入口，使用同一组任务比较学生实际经历。候选方案在完成以下验证前仍属产品设计。

| 要判断什么 | 可观察的结果 |
| --- | --- |
| 体验及自主权 | 陌生用户能否直接开始写作；隔一周能否找回正确草稿与上次卡点；恢复花多久、需重复交代几次；通知中有几次确实需要当时打断。 |
| 图谱与教学能力 | 构图途中新增、撤回、拆分、改评后能否读到正确依据；记录变更到受影响建议生效的时间。隔周用新题独立验证薄弱点，分别观察受助和独立表现。 |
| 真正的可扩展性 | 让同一学生同时完成课内数学复测、无课程多稿写作。写作加入稿件分支、分维反馈、恢复后，如果还需改写数学评分、全局调度或伪造课程，公共层就划错了。 |
| 长效运行与成本 | 在新材料到达、两课争用时间、任务重复投递、Worker 中断及用户取消的情况下，核对积压、重复处理、等待和模型成本；同时检查漏学、无效提醒和未经授权的改排。 |

第一轮比较优先选择“同一周内补发讲义、修改作文、十五分钟后离开再回来”。它同时检验主动跟进、跨任务接续、作品所有权和图谱变化。现阶段已用相同的合成作答输入直接调用活动证据契约，只变更是否提供课程 ID：带课程通过，无课程被拒，唯一错误字段为 `courseId`。它验证了此接口的具体限制。图谱并发、跨周体验及学习效果仍待后续验证。
