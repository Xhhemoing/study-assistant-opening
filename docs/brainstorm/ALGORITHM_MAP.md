# 项目算法与工程做法地图

**状态：**exploring，作为研究与选型索引，不替代已批准设计。  
**适用范围：**AIstudy 全部产品、领域、数据、AI 和基础设施板块。

## 1. 总体原则

每个板块必须明确：用户结果、领域对象、代码落点、可解释基线、增强候选、评价指标、升级门槛和回退路径。选择“在现有数据与资源约束下，经过验证后效果最好且仍可演进”的方案，而不是无条件选择最复杂算法。

共同要求：

- PostgreSQL 中的正式资产与不可变事件是事实源；索引、向量、图谱、摘要、评价和计划都是可重建投影。
- 模型、规则、提示、特征、索引和策略全部版本化；结果保留输入快照与 reason codes。
- 先建立可回放的规则/统计基线，再用离线评估、影子运行和受控上线证明升级收益。
- AI 只生成候选；正式知识、计划高影响变化和能力证据遵循现有权限策略。
- 数据不足、服务不可用或算法漂移时，必须能退回手工流程或确定性基线。

## 3. 统一评估流程

```text
问题与用户结果
→ 版本化基线
→ 固定回放集/人工金标
→ 候选算法离线比较
→ 安全与偏差检查
→ 影子运行
→ 小流量发布
→ 监控真实学习结果
→ 推广或回滚
```

训练/验证/测试应按用户和时间隔离，避免同一用户或未来信息泄漏。所有模型必须提供最近可靠版本或规则基线回退。

## 4. 按实施决策门推进

研究不是一条要求所有开发等待的全局串行队列。按现有任务边界分轨：

1. **Task 9–11：**继续应用壳、笔记、关系和现有对象搜索；不等待 Source、AI、评价或高级算法研究。
2. **Task 14 前：**完成 AI 学习支架、Provider 数据边界、不可信输入和成本/可靠性最小研究。
3. **外部采集纵向切片前：**固定 `Source/Snapshot/Anchor`、来源权利、去重和重放基线；该切片位于 Task 12 后，不回头扩大当前搜索范围。
4. **Task 21 前：**固定 `LearningIntent/Task/Event/Artifact/Verification` 边界和数据用途；确定性任务排序只需在 Task 25 前完成回放与负担评估。
5. **Task 24 前：**完成学习证据资格、复杂作品、公平性、不确定性和用户异议研究。
6. **规模触发后：**再研究混合检索、FSRS/IRT/BKT、推荐、关系图谱、策略学习和跨设备同步。

顺序体现决策依赖：没有可靠来源、事件、构念和评测集时，不应提前训练排序、图谱或复杂学习模型；但这些后期依赖不得阻塞已批准且不依赖它们的基础纵向任务。
