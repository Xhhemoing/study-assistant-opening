# 项目算法与工程做法地图

**状态：**exploring，作为研究与选型索引，不替代已批准设计。  
**适用范围：**AIstudy 全部产品、领域、数据、AI 和基础设施板块。

## 1. 总体原则

每个板块必须明确：用户结果、领域对象、代码落点、可解释基线、增强候选、评价指标、升级门槛和回退路径。选择“在现有数据与资源约束下，经过验证后效果最好且仍可演进”的方案，而不是无条件选择最复杂算法。

共同要求：

- PostgreSQL 中的正式资产与不可变事件是事实源；索引、向量、图谱、摘要、评价和计划都是可重建投影。
- 模型、规则、提示、特征、索引和策略全部版本化；结果保留输入快照与 reason codes。
- 先建立可回放的规则/统计基线，再用离线评估、影子运行和受控上线证明升级收益。
- AI 只生成候选；正式知识、计划高影响变化和能力证据遵循现有权限策略。
- 数据不足、服务不可用或算法漂移时，必须能退回手工流程或确定性基线。

## 2. 板块地图

| 板块与明确指向 | 当前基线 | 扩展候选 | 核心指标与升级门槛 |
|---|---|---|---|
| **统一资产与版本**：`packages/contracts`、`packages/domain`、`packages/database` | 稳定 UUID、revision 追加、乐观并发、关系引用而非复制 | 内容寻址附件、细粒度变更集、按资产类型的合并策略 | 资产唯一性、恢复率、冲突保全；只有离线/协作需求证明需要时升级合并算法 |
| **多源捕获与连接器**：全局捕获、Worker、未来 connector SDK | `spec/check/discover/read/state`、增量游标、幂等键、原始记录保留 | CDC/Webhook、动态限流、分区并行、沙箱插件 | 重复写入率=0、恢复完整率、抓取延迟、单记录成本；通用协议稳定后才做平台专用连接器 |
| **来源识别与版本**：`Source/Snapshot/Anchor` | 规范化 URL、外部 ID、内容哈希、来源特定版本键 | MinHash/SimHash 近重复、实体解析、跨来源聚合 | 精确率优先的去重集；误合并必须可拆分，未达标则只提示候选 |
| **解析与分块**：Parser/Enricher Worker | 格式感知解析、标题层级/页码/代码结构分块，稳定锚点 | 语义分块、版面模型、多模态 OCR、变化感知重解析 | 锚点恢复率、解析覆盖率、检索命中率、耗时；高级分块必须超过固定结构基线 |
| **搜索与检索**：Library/Explore/AI Context Builder | 权限过滤后全文检索；关键词、时间与类型筛选 | BM25+向量+关系/时间多路召回，RRF 融合，学习排序重排 | Recall@k、nDCG/MRR、引用正确率、P95；先有查询评测集，向量不可用时退回全文 |
| **知识关系与主题**：`Document/Claim/Relation` | 用户关系、规则实体抽取和 AI 关系候选 | 增量聚类、实体消歧、时间图谱、社区摘要 | 关系精确率、重复率、人工接受率；图查询/规模证明关系表不足后再引入图后端 |
| **学习记忆与上下文**：Memory Fabric、AI | 来源/用户/事件/任务/能力分层，作用域过滤，按需 ContextPack | 混合记忆召回、时间失效、冲突图、上下文预算优化 | 来源支持率、过期命中率、跨域泄漏=0、用户纠正率；不允许自动记忆替代领域事实 |
| **探索与 AI 候选**：Explore、`packages/ai` | typed result contract、来源引用、候选审核、角色化提示 | 多阶段检索-生成-核验、模型路由、工具计划 | 引用支持率、候选接受/修订率、幻觉率、成本/延迟；始终保留无 AI 手工闭环 |
| **学习意图与任务**：`LearningIntent/Task/PlanItem`、Learn | 截止、优先级、风险、预计时间和用户固定项的确定性排序 | 约束优化、上下文 bandit、保守策略学习 | 单位时间完成有效产出、逾期、计划扰动和用户覆盖率；不以停留时间为目标 |
| **复习调度**：Card/Review/SRS | 明确版本的规则调度，提示后作答降权 | FSRS 参数拟合；特殊能力采用专用调度 | 延迟回忆、校准、每日负荷和遗忘成本；回放/前瞻实验优于基线后才切换 |
| **能力评价**：Attempt/Artifact/Feedback/Assessment | 能力切片、规则证据计分和 reason codes | Beta-Binomial、Logistic+校准；数据充分后 IRT/BKT | Brier、Log Loss、ECE、分场景误差；禁止输出无明确定义的单一掌握度 |
| **干预与推荐**：资源、练习、下一步 | 规则资格过滤+可解释排序+多样性约束 | Learning-to-rank、因果 uplift、保守 contextual bandit | 延迟表现、迁移、单位时间提升、覆盖与纠正率；点击率仅作诊断指标 |
| **同步与冲突**：后期客户端 | 幂等事件、乐观并发、服务端事实源 | 按资产类型采用 CRDT/三方合并/操作日志 | 丢失率=0、重复率=0、冲突可见；不采用一个 CRDT 处理所有对象 |
| **权限、隐私与安全**：Auth/Workspace/Plugin Runner | 默认拒绝、workspace 过滤、最小权限、密钥代理、审计 | 行列级策略、能力令牌、敏感度分类与策略引擎 | 跨工作区泄漏=0、删除完整率、权限回归；外部内容一律按不可信输入处理 |
| **导入、导出与可移植性**：Library/完整包 | 版本化 manifest、校验和、先校验后提交、幂等导入 | 流式包、增量导出、迁移适配器 | 对象/关系/历史恢复率、往返一致性；任何新资产都必须定义导出语义 |
| **异步任务与运行可靠性**：Worker/BullMQ/Outbox | Outbox、幂等消费者、指数退避、死信与检查点 | 分区队列、自适应并发、工作流编排 | 重复副作用=0、恢复时间、积压、P95；模块化单体达到瓶颈后才拆服务 |
| **可观察性与实验**：全栈 | 结构化日志、trace/correlation ID、版本和 reason codes | 数据漂移、模型质量、成本和 SLO 联合监控 | 每个关键结论可追到输入、版本和运行；实验必须预注册主指标和停止条件 |
| **交互与无障碍**：Web/UI | 三入口、渐进披露、键盘/语义 HTML、响应式设计 | 个性化密度、适应性提示，但不改变资产语义 | 任务成功率、错误率、可达性、首次有效行动时间；不得用黑暗模式提高指标 |

## 3. 统一评估流程

```text
问题与用户结果
→ 版本化基线
→ 固定回放集/人工金标
→ 候选算法离线比较
→ 安全与偏差检查
→ 影子运行
→ 小流量发布
→ 监控真实学习结果
→ 推广或回滚
```

训练/验证/测试应按用户和时间隔离，避免同一用户或未来信息泄漏。所有模型必须提供最近可靠版本或规则基线回退。

## 4. 优先研究顺序

1. `Source/Snapshot/Anchor`、来源去重和重放基础。
2. `LearningIntent/Task/PlanItem` 及确定性调度基线。
3. 全文+语义混合检索评测集与 ContextPack。
4. 学习事件、复习调度和能力校准。
5. 推荐、关系图谱、策略学习和跨设备同步。

顺序体现数据依赖：没有可靠来源、事件和评测集时，不应提前训练排序、图谱或复杂学习模型。
