# 长短期目标驱动的学习架构与最小前置补习

## 1. 决策问题

用户需要长期学习与短期考试同时存在；时间不足时，以目标为先、转向应试练习；拍照 AI 批改和手动评价并存，由用户最终裁定；教学取决于偏好与实际目的；AI 可沿知识图谱主动补足必要前置。方向已由用户在 2026-10-17 明确，随后授权调研、形成新框架并改进项目，不再将这些能力问成互斥选项。

需要解决的架构问题是：相同作答如何服务不同目标，目标如何改变排序与教学深度，前置补习如何帮助当前任务而不无限扩张，以及现有课程、冲刺、图谱与证据如何共用身份和记录。

## 2. 范围与约束

| 层次 | 范围 |
|---|---|
| 用户场景 | Math I 考前冲刺作为验收场景，同时保留长期课程学习 |
| 入口 | 课程配置、今日计划、开始此项、主讲与作答、学习记录 |
| 领域 | Goal、KnowledgeSnapshot、Attempt、Observation、LearnerSnapshot、TeachingLearnerFocus |
| 代码 | contracts、domain/opening/adaptive、database repositories、web planning/teaching、AI teaching compiler |
| 正式落点 | [目标驱动学习框架](../plans/2026-10-17-goal-driven-learning-framework.md)；首批实现目标上下文贯通 |

不变量：一次学习只记一次时间；首次作答与无提示独立作答不是同一事实；用户改评保留原记录并更新有效评价；目标期限不能伪装成任务真实截止时间；`notBefore`、工作区权限、材料版本、已交付帮助与已有计划确认语义继续有效。前置缺少证据是未知，不自动当作不会。

## 3. 已核对事实

以下代码事实以本轮实施前 `851e6ff` 为核对基线，后续切片变化见正式计划，不能把方案文字当完成证明。

| 事实 | 依据与含义 |
|---|---|
| 正式目标模型已存在 | [goals schema](../../packages/database/src/schema/goals.ts) 已有 `course_goals`、`goal_time_windows`，允许同课程不同 kind 的目标；当前唯一键为 workspace/course/kind。不能新建第三套目标，也不能说任意跨课程、多考试目标已贯通 Opening |
| Opening 使用另一条较窄运行链 | [learner-snapshot-service](../../apps/web/src/features/opening/planning/learner-snapshot-service.ts) 读取 `workspace_preferences.adaptive_planning.courseGoals`；其值是课程节奏、主日期与 milestones，不是正式多目标集合 |
| 图身份尚不连续 | [build-course-knowledge](../../apps/worker/src/jobs/build-course-knowledge.ts) 重建时给节点分配 `randomUUID()`；[assemble-snapshot](../../packages/domain/src/opening/adaptive/assemble-snapshot.ts) 把可学节点聚合为 `nextSkills` 标题。源快照有 id，规划聚合与历史证据尚未形成稳定技能引用 |
| 要求身份不能代替技能身份 | [learning-attempts](../../packages/database/src/repositories/opening-learning-attempts.ts) 为教学块生成 `teaching:<blockId>:v<contentVersion>` 的 `requirementKey`，适合隔离具体要求与版本，不能充当长期技能主键 |
| 可复用的记录基础已存在 | [learning schema](../../packages/database/src/schema/opening-learning.ts) 与 [attempts schema](../../packages/database/src/schema/opening-learning-attempts.ts) 已保存会话、帮助、题目版本、作答、观察和评价修订关系，不需要另建“冲刺掌握账本” |
| 测量插件不能直接等同生产决策 | [measurement schema](../../packages/database/src/schema/opening-measurement.ts) 保存试验、预测和测量作答；正式评估与排程接管仍需技能身份、证据资格和效果验证 |

外部调研于 2026-10-17 核验；以下仅引述原论文/官方文档可支持的结论：

| 一手来源 | 支持的设计依据 | 不能外推的结论 |
|---|---|---|
| [Clement et al., JEDM 2015](https://jedm.educationaldatamining.org/index.php/JEDM/article/view/JEDM111) | 在有限时间和动机资源下，以实际学习进展选择活动，并用专家知识约束探索 | 儿童数分解任务的结果不能证明大学微积分冲刺的收益，也不证明项目任意加权公式有效 |
| [CMU CTAT 官方教程](https://tat.pact.cs.cmu.edu/CMUCTAT/CTAT/docs/tutorial-example-tracing.html) | 同一问题可以记录多条正确解法及常见错误路径；步骤反馈需要考虑解法 | 未收录路径不一定错误，不能用唯一参考步骤否定其他正确解法 |
| [Aytekin & Saygın, ACE, JEDM 2024](https://jedm.educationaldatamining.org/index.php/JEDM/article/view/737) | AI 候选关系结合专家知识可减少先修图构建负担；图谱可以提供学习路径 | 自动关系不是普适因果关系，不能要求学完所有上游节点才能做题 |
| [IES/WWC 学习实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) | 支持例题与独立问题交替、间隔与检索；各建议证据强度不同 | 没有给出统一最佳冲刺配比；偏好图示也不意味着固定“学习风格”决定效果 |
| [Corbett & Anderson, Knowledge tracing](https://link.springer.com/article/10.1007/BF01099821) | 根据技能表现估计特定规则是否学会，并辅助练习安排 | 潜在掌握概率不是考试分数、整课完成率、迁移能力或某教师命题概率 |

## 4. 假设与未知项

| 假设/未知项 | 风险 | 验证方式 |
|---|---|---|
| 临近目标时集中题型训练更符合当前用户收益 | 高分目标可能需要综合迁移，简单提速反而遗漏内容 | 相同时间预算下看独立限时题表现与缺口，不以任务完成数代替 |
| 单次短前置补习能减少原题阻塞 | 图边宽泛、标签同名或原题另有解法时可能绕远 | 记录原任务、补习理由、用时与随后独立关键步骤表现 |
| 自动模式 7 天内转应试有用 | 日期不是考试、估计学习量不准、各课程差异大 | 将 7 天作为可调整产品规则，允许显式理解/应试覆盖；观察用户改回次数 |
| 现有技能标签可用于首批局部前置匹配 | 同名不同要求会误关联 | 只处理唯一标签和要求不歧义、有近期有效弱项证据的 supported 直接前置；其余不自动绕行 |
| 个体任务收益可以进一步估计 | 少量个人样本、重复题、时间选择偏差使估计不可靠 | 先积累独立后测和时长；不显示精确提分收益，不训练复杂调度模型 |

## 5. 候选方案与取舍

### A：保持当前任务类型优先与课程轮换

沿用 deadline、复测、昨日积压等分组及组内课程轮换，教学只根据近期表现选择讲解/练习。优点是简单、可回放；缺点是看不到目标急迫度，临考训练可能被普通积压和固定轮换打断。

### B：目标上下文驱动的规则策略（本轮采用）

复用 Opening 课程设置解析一个运行时目标上下文，同时送入候选预算、排序、教学 focus、服务端编译重查和 AI 内容生成。将真实任务截止和时间准入作为约束；将目标优先级、临近程度作为普通任务取舍依据。图谱补习首批只在一次教学内生成最多一个有证据的短前置环节。

这能形成可用切片，但仍是课程目标上下文，不是完整多目标调度。后续用正式 `course_goals`/`goal_time_windows` 适配替代数据来源，保持消费者使用同一上下文接口。

### C：直接以 LLM 或 bandit/RL 统一规划与教学

理论上能适配复杂偏好和动态收益，但当前缺稳定技能身份、可靠收益标签和可比较独立后测。LLM 还会混淆原始事实与建议，在线探索也可能消耗临考时间。暂不采用；LLM 负责内容组织与解释，规则持有时间、权限、顺序与写入边界。

| 维度 | A | B | C |
|---|---|---|---|
| 目标效果 | 间接依赖日期与待办 | 可明确服务当前目标；真实学习收益待验 | 可能更好，但尚无项目证据 |
| 数据需求 | 任务与近期观察 | 再加课程目标、日期、图谱关系 | 需要充分的动作、收益、时长与独立后测 |
| 延迟/成本 | 本地规则低成本 | 本地规则，复用既有 AI 编译 | 训练/在线推理和探索成本更高 |
| 可解释性 | 任务类型可解释 | 输出目标理由、补习范围与返回要求 | 需额外解释和反事实评价 |
| 隐私 | 现有作用域 | 复用材料准入，只有必要目标摘要进模型 | 可能扩大行为历史发送范围 |
| 回滚/可移植 | 现成基线 | JSON 可选字段，规则可退回，存储源可替换 | 模型与反馈循环迁移成本高 |
| 扩展性 | 无目标耦合的上限明显 | 先桥接身份和正式目标，再扩条件路径 | 数据与实验成熟后再评估 |
| 失败处理 | 原始排序 | 无目标保留原行为，缺前置证据不绕行 | 必须另有规则降级，不能只依赖模型 |

## 6. 推荐与升级条件

采用 B；保留 A 作为兼容基线；C 留作后续研究。图谱支持条件前置和多解法是正式框架方向，首批不能声称已实现。用户改评直接进入有效评价链，避免增加审核队列。

算法升级前需要：稳定技能与题族身份、可回放且不泄漏结果的决策输入、真实时长、独立验证结果，以及比规则基线更好的效果/负担证据。没有通用的“收集 N 条即可升级”数字；按预先定义的实际改善与不确定性判断。

## 7. 验证计划

- **工程数据：**合成长短期课程、已确认/未确认里程碑、日期边界、积压、真实 deadline、`notBefore`、重复标签、多要求和失效材料场景。
- **基线：**本轮前的任务排序和教学决策；比较是否遵守用户目标与已有约束，不把模拟正确率称为学习效果。
- **通过标准：**显式模式被尊重；临考目标能超过普通积压；真实截止与推迟不被目标覆盖；缺失证据不触发补课；歧义身份不串用；新旧配置往返不丢数据；编译时重查上下文。
- **学生验收：**课程配置后查看今日理由，开始同一技能，理解/应试模式呈现不同深度；存在有效直接前置弱项时出现短补习说明。浏览器由用户验收，不在本轮文档任务中执行。
- **学习指标：**同时间预算下未见题独立得分、限时完成、必要补习用时、用户改序/改模式负担；长期另看延迟保持。单人趋势不作因果证明。
- **回退：**出现真实截止被挤掉、帮助记录丢失、跨要求串证据或旧配置被重写时先修复/停用相关策略；无明显学习收益时保留规则可解释基线，不扩复杂模型。

## 8. 数据与风险边界

复用现有 workspace/owner 隔离、来源授权、版本检查、模型预算和删除/备份策略；来源正文属于学习材料，不能作为修改系统权限的指令。照片和批改内容后续接入现有作答链，不因本方案扩大供应商数据范围。图谱候选不能自动升级成可靠前置，教师题型频率不能自动变成命题概率。
