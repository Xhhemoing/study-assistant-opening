# AIstudy 可执行实施计划

> **历史计划：已被取代。**本文件保留早期“备考学习决策平台”的里程碑，供追溯原始决策。当前开发必须使用 [终身学习平台实施计划](../plans/2026-07-21-lifelong-learning-implementation.md)。新计划将目标学习、自由探索、笔记与知识库设为平等入口，并先建立统一资产和长期课程模型。

**计划版本：**0.1  
**基线日期：**2026-07-21  
**实施原则：**纵向切片、单体优先、规则先行、真实验证、每个里程碑保持可运行。  
**预估：**2–4名开发者约24周；单人全职约36–48周。预估不包含大规模题库版权采购和内容制作。

## 1. Definition of Done

每项功能完成必须满足：

- 需求和验收条件有文档或 Issue；
- 数据契约和权限边界明确；
- 单元、集成或端到端测试覆盖主要风险；
- 错误、空状态、加载和降级状态存在；
- 桌面与移动关键视口可用；
- 异步写入支持幂等或去重；
- 不记录密钥或不必要的敏感内容；
- 变更不破坏完整导出；
- 文档和迁移随代码更新；
- CI 中 lint、typecheck、test、build 通过。

## 2. 预定命令

以下命令在 Milestone 0 脚手架完成后生效：

```bash
npm install
npm run dev
npm run worker:dev
npm run lint
npm run typecheck
npm run test
npm run test:integration
npm run test:e2e
npm run build
npm run db:migrate
npm run db:seed
npm run compose:up
npm run compose:down
```

最终脚本名以根目录 `package.json` 为准，不允许文档和实际命令长期不一致。

## 3. 里程碑总览

| 里程碑 | 目标 | 参考周期 | 可交付结果 |
|---|---|---:|---|
| M0 | 技术验证与仓库脚手架 | 2周 | 可运行 Web、Worker、DB、CI |
| M1 | 账户、目标与场景预设 | 2周 | 用户获得空的今日计划 |
| M2 | 内容、题目与资源包基础 | 3周 | 可导入并固定版本的种子题包 |
| M3 | 作答事件与精简结果 | 3周 | 练习→状态→原因→下一步闭环 |
| M4 | 今日计划与基础复习 | 3周 | 根据时间和场景生成任务队列 |
| M5 | 来源、资料和基础锚点 | 3周 | PDF/网页快照可回链 |
| M6 | AI候选与人工审核 | 3周 | 候选卡片/错因/变式可审核 |
| M7 | 资源平台和社会化基础 | 3周 | 发布、Fork、更新、教师下发 |
| M8 | 模考、归档和完整导出 | 3周 | 备考闭环和数据可携带 |
| M9 | 校准、公测和生产加固 | 2–4周 | 小规模真实公测 |
| M10 | 开源与自托管准备 | 公测后 | 可部署社区版本 |

M0–M4 是首个可用闭环；M5–M8 是目标 MVP；M9 后才能公开宣称预测效果。

# M0：技术验证与脚手架

## M0.1 锁定技术版本

**任务：**读取 Next.js、PostgreSQL、Drizzle、BullMQ、认证库和测试工具官方文档，编写 `docs/decisions/ADR-001-stack.md`。

**验收：**

- Node 支持范围、依赖版本和升级策略明确；
- 自托管约束经过核查；
- 认证、迁移、队列和对象存储各有最小验证；
- 未验证的库不进入生产依赖。

## M0.2 创建 monorepo

**创建：**

```text
package.json
package-lock.json
tsconfig.base.json
eslint.config.mjs
apps/web/
apps/worker/
packages/domain/
packages/database/
packages/contracts/
packages/config/
packages/ui/
tests/
```

**验收：**

- `npm install` 成功；
- `npm run lint && npm run typecheck && npm run test && npm run build` 成功；
- Web 显示健康页；
- Worker 能消费一个测试任务。

## M0.3 本地基础设施

**创建：**`infra/docker/compose.yml`、`.env.example` 和启动脚本。

服务：PostgreSQL、Redis、S3兼容对象存储。

**验收：**

- 新环境按 README 可在30分钟内启动；
- 健康检查覆盖 DB、Queue 和 Storage；
- 停止并重启后测试数据保持；
- `.env` 已加入 `.gitignore`。

## M0.4 CI

**创建：**CI 工作流，执行 lint、typecheck、unit、integration、build。

**验收：**

- Pull Request 必须通过检查；
- 缓存不会掩盖依赖缺失；
- 集成测试使用隔离数据库；
- 失败日志不泄漏密钥。

**Checkpoint M0：**从空环境启动 Web 和 Worker，提交测试任务并在数据库记录结果。

# M1：账户、目标与场景预设

## M1.1 身份和会话

**文件区域：**`apps/web/src/features/auth/`、`packages/database/src/schema/identity.ts`。

**验收：**

- 用户注册、登录、退出和会话失效可用；
- 服务端校验权限；
- Cookie 安全配置符合部署环境；
- 端到端测试覆盖未登录重定向和会话过期。

## M1.2 StudyGoal 纵向切片

**功能：**创建考试目标、日期、科目、目标结果和每日时间。

**验收：**

- 可创建、编辑、归档目标；
- 日期和每日时间经过服务端校验；
- 用户只能访问自己的目标；
- URL 可直接回到目标主页。

## M1.3 场景模板引擎

**文件区域：**`packages/domain/src/strategy/`、`packages/contracts/src/strategy.ts`。

**内置：**期末、高考、考研、自定义。

**验收：**

- 模板有 ID 和语义化版本；
- 继承顺序为基础→场景→科目→资源建议→用户覆盖→临时覆盖；
- 用户明确覆盖不会被模板升级静默改写；
- 单元测试覆盖优先级和回滚。

## M1.4 首次启动流程

**验收：**

- 4步内完成场景、日期、科目和时间设置；
- 移动端 320px 无横向溢出；
- 完成后进入今日页面；
- 未有内容时提供选择资源或上传的明确入口。

**Checkpoint M1：**新用户能建立期末、高考或考研目标，并看到由模板生成的空计划结构。

# M2：内容、题目与资源包基础

## M2.1 共享内容 Schema

**文件区域：**`packages/database/src/schema/content.ts`。

实现 `ResourcePackage`、`ResourcePackageVersion`、`ContentItem`、`ContentItemVersion`、`SyllabusNode`、`Rubric`。

**验收：**

- 内容更新创建新版本；
- 历史版本可读；
- 考试年份、教材版本、来源和许可可记录；
- 迁移测试可回滚。

## M2.2 开放资源包契约

**文件区域：**`packages/contracts/src/resource-package/`。

**验收：**

- JSON Schema 有版本；
- 导入前校验并返回结构化错误；
- 未知可选字段可安全忽略；
- 错误答案版本不能覆盖历史对象。

## M2.3 第一份种子包

先选定一个科目和考试场景。若尚未决定，用版权清晰的演示内容，不将演示题宣称为正式备考资源。

**验收：**

- 至少20个考点、50道题和5种错因；
- 题目覆盖识别、程序、迁移或表达中的至少三类；
- 每项内容有来源和版本；
- 可完整导入、固定版本和卸载。

## M2.4 资源选择流程

**验收：**

- 用户可查看适用考试、年份、审核状态和覆盖；
- 可选择跟随更新或固定版本；
- 资源页默认信息精简，质量依据可展开；
- 未审核 AI 内容有明显标签。

**Checkpoint M2：**用户可以选择一份资源包并在目标中浏览考纲和题目。

# M3：作答事件与精简结果

## M3.1 不可变学习事件

**文件区域：**`packages/database/src/schema/events.ts`、`packages/contracts/src/events.ts`。

**验收：**

- 事件有全局ID、类型、用户、内容版本、时间、上下文和 Schema 版本；
- 重复请求使用幂等键去重；
- 修正通过新事件完成；
- 历史题目更新不改变旧事件语义。

## M3.2 练习播放器

实现选择、短答和步骤题中的最小集合。

**验收：**

- 保存答案、用时、提示、信心和错因；
- 网络重试不会产生双重作答；
- 提交后立即确认保存；
- 键盘和移动端可完成流程。

## M3.3 规则评估引擎

**文件区域：**`packages/domain/src/assessment/`。

**验收：**

- 输出 `stable/usable/weak/untested`；
- 区分至少 recognition、recall、procedure、transfer；
- 输出 reason codes 和 recommended actions；
- 规则配置和版本可追踪；
- 给定同一事件快照，结果确定且可重算。

## M3.4 精简状态卡和原因抽屉

**验收：**

- 默认只显示状态、最多两个数据和主行动；
- 原因抽屉最多先展示三条主要原因；
- 每个原因至少关联一个可执行动作；
- 不以颜色作为唯一状态信息；
- 开发者设置可查看输入事件和规则版本。

**Checkpoint M3：**用户完成一道题后，获得精简结果，能展开原因并进入针对性任务。

# M4：今日计划与基础复习

## M4.1 Planner 契约

输入：目标、场景策略、可用时间、内容范围、能力切片和未完成任务。  
输出：有序任务、预计时间、原因和策略版本。

**验收：**

- 输出总时间不超过用户预算；
- 用户固定任务不被自动移除；
- 规则可解释每个任务为何入队；
- 相同输入和版本得到稳定输出。

## M4.2 场景任务组合

实现期末、高考、考研三个默认组合。

**验收：**

- 期末优先范围覆盖和章节补缺；
- 高考支持多轮和跨科时间；
- 考研区分真题、背诵和专业课输出；
- 用户可在常用设置调整时间、强度和科目优先级。

## M4.3 复习调度

MVP 使用明确版本的基础算法；是否引入 FSRS 由 Spike 决定。

**验收：**

- 查看答案不被计为高质量回忆；
- 复习状态与共享卡片内容分离；
- 归档内容不进入队列；
- 调度变更有版本和测试。

## M4.4 今日页面

**验收：**

- 首屏只显示计划、总进度、最多三个风险和一个主操作；
- 用户可以开始、跳过、固定或调整任务；
- AI/评估不可用时仍能使用规则计划；
- 完成任务后队列正确推进。

**Checkpoint M4：**形成完整的“设置目标→选资源→今日计划→练习→结果→下一任务”闭环。

# M5：来源、资料和基础锚点

## M5.1 文件上传与对象存储

**验收：**

- 使用预签名或受控上传；
- 校验类型、大小和所有权；
- 上传状态可重试；
- 未落盘不得显示成功；
- 文件哈希用于去重和版本识别。

## M5.2 PDF 解析 Spike

只支持受控 PDF 范围，记录：页面文本、块、页码、坐标、哈希。

**验收：**

- 建立固定测试语料；
- 测量文本提取和页码回链；
- 扫描件明确降级或进入OCR；
- 解析失败可见且不会生成伪锚点。

## M5.3 网页快照

**验收：**

- 保存快照和原URL；
- 引文锚定快照而不是假设动态网页不变；
- 版权或抓取失败时只保存允许的信息；
- UI显示精确、文本、结构或仅来源四级状态。

## M5.4 来源查看器

**验收：**

- 从题目、解释或卡片回到来源；
- 锚点失效可检测；
- 可尝试文本指纹重定位；
- 无法恢复时明确降级。

**Checkpoint M5：**用户能从学习内容回到受控 PDF 或网页快照中的证据位置。

# M6：AI候选与人工审核

## M6.1 Provider 接口

**文件区域：**`packages/ai/src/providers/`。

**验收：**

- Provider 可替换；
- 请求有超时、重试、成本和模型版本；
- 结构化输出经过 Schema 校验；
- Provider 不直接写正式内容。

## M6.2 AI Job 与 Worker

**验收：**

- 任务幂等；
- 重试不产生重复 artifact；
- 输入使用最小必要上下文；
- 失败状态和人工重试可见。

## M6.3 候选内容

支持候选卡片、错因和变式题。

**验收：**

- 候选带来源、模型和生成时间；
- 未审核内容不能进入官方资源；
- 用户可接受、编辑、拒绝；
- 接受后创建正式内容新版本或个人内容。

## M6.4 支持性检查

区分：来源引用、主张支持和AI推断。

**验收：**

- 引用存在不自动判定正确；
- 显示 `supported/partial/insufficient/conflicting/inference`；
- 高风险冲突阻止自动发布；
- 保存人工审核结果用于后续评测。

**Checkpoint M6：**AI减少制卡和分析摩擦，但不会静默改变正式知识或个人历史。

# M7：资源平台和社会化基础

## M7.1 发布和版本

**验收：**

- 作者可发布草稿、审核版和新版本；
- 用户可固定、跟随或 Fork；
- 更新显示结构化差异；
- 个人状态永不随资源升级被覆盖。

## M7.2 质量和治理

**验收：**

- 来源、许可、审核和适用年份必填；
- 用户可举报答案、版权和质量问题；
- 下架不删除用户已产生的历史；
- 排序不只依赖下载量或点赞。

## M7.3 教师下发

**验收：**

- 教师可将资源和任务下发到班级；
- 学生个人笔记和完整状态默认不公开；
- 教师看到授权的完成和聚合数据；
- 内容更新不覆盖已提交作答。

## M7.4 常见错因聚合

**验收：**

- 只展示达到最小样本的聚合；
- 用户可看到“常见问题”及对应练习；
- 聚合结果不能直接覆盖个人错因；
- 可追踪数据和算法版本。

**Checkpoint M7：**同一资源可被多人使用和更新，同时每个人保有独立学习状态。

# M8：模考、归档和数据可携带

## M8.1 模考

**验收：**

- 支持限时、整卷、暂停策略和提交；
- 记录时间分配、空题、修改和错因；
- 模考影响 `timed_stability`，不直接覆盖其他能力；
- 单次异常结果不会静默大幅改变长期计划。

## M8.2 考后归档

**验收：**

- 支持长期保留、低频维护、季节归档、停止复习和删除；
- 归档不删除原始历史；
- 删除明确展示影响；
- 归档内容可重新激活。

## M8.3 完整备份和恢复

**验收：**

- 包含内容引用、个人事件、策略、派生版本和文件清单；
- 在兼容版本恢复；
- 恢复测试在CI或定期任务中执行；
- 缺失文件和不兼容版本给出明确错误。

## M8.4 外部投影与损失报告

首批：CSV、Markdown、Anki。

**验收：**

- 导出前显示保留和丢失字段；
- 不宣称外部格式无损；
- 用户可下载完整开放包作为补充；
- 导出失败可重试且不重复计费。

**Checkpoint M8：**备考结束后可归档，用户可以恢复完整包并获得外部格式的明确损失报告。

# M9：校准、公测和生产加固

## M9.1 事件质量审计

- 检查重复、时间异常、错误内容版本和提示漏记；
- 建立数据质量仪表盘；
- 无效事件不得进入训练集。

## M9.2 校准基线

**验收：**

- 为具体任务定义预测目标；
- 用户和时间隔离训练/测试；
- 报告 Brier、Log Loss 和校准曲线；
- 按场景、题型和数据量分层；
- 与简单规则/基准比较。

## M9.3 小规模公测

建议30–100名目标用户，持续4–8周。

比较：

- 激活时间；
- 计划完成；
- 错误后干预闭环；
- 延迟表现；
- 迁移题；
- 模考稳定；
- 原因展开率和纠正率；
- 用户留存和任务负担。

## M9.4 生产准备

- 性能和容量测试；
- 队列积压和死信处理；
- 备份恢复演练；
- 数据库迁移演练；
- 对象存储生命周期；
- 成本预算和限额；
- AI服务熔断；
- 日志、指标和告警；
- 安全测试和依赖扫描。

**Checkpoint M9：**只有在校准和用户结果通过预设门槛后，才扩大用户和考试范围。

- 有升级、回滚、备份和恢复文档；
- 提供兼容性矩阵；
- 官方云专属功能不破坏开放数据格式。

## M10.3 贡献治理

- CONTRIBUTING；
- Code of Conduct；
- 安全披露；
- DCO/CLA；
- Issue/PR 模板；
- 发布和版本政策；

## 5. 首批研究与产品实验

### 实验 A：信息密度

比较“精简结果+原因抽屉”和完整仪表盘，主要看任务启动、完成和理解，不以点击原因抽屉本身判胜。

### 实验 B：推荐价值

固定时间预算下比较系统队列、固定队列和用户自选，观察延迟正确率、迁移表现和主观负担。

### 实验 C：AI介入方式

比较先答后提示、直接解释和候选制卡，判断不同知识类型下的效果。

### 实验 D：资源更新

观察跟随、固定和Fork是否能被用户理解，测试更新是否破坏个人状态。

## 6. 关键风险与触发条件

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 范围失控 | M0前增加多个考试 | 固定一个种子垂直领域 |
| 内容冷启动 | 开发完成但无可信题包 | 提前并行建设种子内容 |
| 状态误导 | “稳固”后失败率过高 | 提高证据要求、分情境、降级标签 |
| 默认UI仍复杂 | 首次任务超过15分钟 | 减字段、延后设置、可用性测试 |
| AI成本失控 | 单活跃用户成本超预算 | 缓存、轻模型、额度和规则降级 |
| 解析泥潭 | 大量格式例外阻塞 | 限定受控PDF和快照范围 |
| 社区低质内容 | 举报和答案冲突增加 | 邀请制、审核级别、版本和下架 |
| 模型没有增益 | 不优于规则基线 | 保留规则，不上线复杂模型 |
| 过早微服务化 | 跨服务调试占比上升 | 保持模块化单体 |
| 自托管拖慢MVP | 早期适配多环境 | 先保持可配置边界，公测后发行 |
