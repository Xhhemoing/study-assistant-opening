# 多工具开发分工

**生效：** 2026-10-13；2026-10-26 调整评审粒度与连续开发节奏。取代 [codex-team.md](codex-team.md) 与 [project-lead-prompt.md](project-lead-prompt.md) 中的角色、模型路由和派单流程（两者仅作历史）。根 `AGENTS.md` 的编码、测试、浏览器验收分工约定不变。

## 分工

当前主线程负责目标、集成与最终交付；普通低风险改动可以直接完成。下表按工具可用能力分工，不要求每个小板块依次转交全部工具；只在委派时写短任务卡，不为主线程的小改动额外建卡。

| 工具 | 负责 |
|---|---|
| Claude Code | 架构与接口、migration、并发/事务/权限、跨包权衡、疑难定位和集成；可承担非本人实现的独立审查。 |
| Grok Bot | 边界清楚的实现、必要测试、lint/类型修复和文档整理；同一完整结果下可连续完成多项内部任务。 |
| pi / 只读子 Agent | 按风险提供独立审查或方案核对，不固定充当每次改动的第二、第三道角色。 |

有独立并行收益或需独立核验时才委派；同一路径单写者，公共契约、迁移编号、授权和事务协议串行协调。子 Agent 默认配置见下节，不静默换模型。所需独立评审不可用时保留“未评审”，可继续不依赖它的工作，不把主线程自查冒充独立评审。

## 三任务并行

- 主线程负责完整结果、就绪任务调度、共享语义和最终集成；派工后继续接线、核对边界及集成，不空等所有子任务结束。
- 最多同时运行 3 个子 Agent，可为 3 名独立实现者，覆盖通用的两名实现者上限；调查和评审也占这 3 个名额，等释放后再派，不启动第 4 个。独立任务不足时不凑数。
- 普通子 Agent 默认 `gpt-6.1-sol`、`high`，工具支持时显式设置；偏离前说明原因和实际配置，不能静默替换。
- 先用短任务卡明确 owner、互斥写入范围、前置依赖、现有类型与业务失败路径，再发出就绪任务；共享契约、schema、锁文件、授权和事务语义由主线程协调，不按文件或前后端机械拆成不兼容实现。依赖变化先回主线程，不自行改约定。
- 共享 checkout 仅用于互斥路径；优先复用，活跃 worktree 仍最多 3 个，不要求每人新建。worktree 不隔离数据库、Redis、端口等运行资源，使用前由主线程协调。
- 按当前用户要求连续开发后集中验证与 review；子 Agent 不各跑全量检查，主线程排队安排必要检查，保留既有 `run-heavy` 资源控制；集中检查覆盖同一集成候选，风险评审时保持该候选稳定。高风险边界仍按下表提前核对，不禁用既有测试和 CI。
- 阻塞时返回证据、未决依赖和接管点，由主线程调整；同一路径确认原 owner 停止写入并交接后才能接管，不重复并行接手。状态沿用 STATUS，不新增账本平台。
- 仅以实测说明提效，端到端耗时须包含协调、等待和返工；未测量不宣称提升。

## 评审时机

| 当前改动 | 默认做法 |
|---|---|
| 文案、文档、已有界面小修或局部低风险修复，且不改变共享契约、安全和数据语义 | 实现者自查实际 diff，运行适用的最近检查；无具体疑点时不额外启动独立 review。 |
| 复杂、跨模块或跨包的完整可用结果 | 组件和衔接完成后集中做一次独立只读评审，覆盖实际调用链、关键失败路径和模块间影响。 |
| 授权、隐私、事务/并发、migration、费用、取消/生命周期或数据正确性 | 在依赖实现展开前定向核对关键边界；仍须完成最终集成评审，边界未变时复用早期结论并重点审新增集成风险。 |

这里的单位是用户可使用、可验证的结果，不是文件、组件或任务卡。例如同一功能的接口、服务、UI 与回归测试通常组成一次集成评审；不能把所有不相关工作攒成大批再审。任务大小不降低风险等级，用户或项目针对特定风险要求的评审仍保留。

评审者只报具体缺陷、影响、反例和最低修复建议。影响当前结果的正确性、安全、数据或可用性的缺陷先修；风格偏好和范围外增强不阻塞。修复后验证原反例，仅复查受影响差异；没有新风险不固定多轮重审。送审期间保持候选稳定，主线程可继续无文件、语义和运行资源冲突的独立工作；未通过的高风险边界不供依赖工作采用。

## 一个完整结果的流程

1. **选结果**：从 [STATUS.md](../STATUS.md) 和当前计划明确本轮可用结果、依赖及缺少的证据；小改动直接推进，委派才按下方模板交接。
2. **连续实现**：在适合当前任务的现有工作区和分支完成相关组件，尽早接通实际入口并运行最近的非浏览器检查；不为每个内部任务新建分支、worktree、PR 或等待 review。
3. **按风险审查并集成**：按上表安排评审，主线程核对实际差异、衔接和检查结果。已有检查在候选、输入、环境及覆盖未变时复用；集成引入的新影响补相关检查，不能把局部通过拼成整体通过。
4. **交付与 Git 操作**：更新 STATUS，说明实际结果、检查与未验项。只有当前授权包含相应操作时才提交、推送、开 PR、合并或发布；PR 以完整结果组织，目标分支现场核实，合并/发布保留既有 CI 和审批要求。
5. **用户验收**：浏览器和真实使用由用户负责，提供入口、前提、步骤与预期，问题写进 STATUS 的“使用反馈”；待用户验收不阻塞独立的后续开发，也不能标成通过。

TypeScript 改动执行所属包类型检查，行为变化执行最近的有效回归；文档改动检查 diff 即可。完整 lint/typecheck/test/build 按现有 CI 或明确要求执行，不在每个组件结束后重复；同时只运行一份完整构建或门禁，共享数据库检查串行安排。

同时最多 3 个活跃 worktree。仅在需要隔离或并行且所有权清楚时新建；合并后确认无独有修改且已有清理授权才移除，工作流本身不授权删除。

开工恢复只核对当前目标、工作区、候选差异和下一依赖；只有具体疑点才回读历史。用户插入状态问题时简答后继续已授权主线，不把每次回复当成新的切片收尾。相关组件可并行时明确单写者，主线程在等待评审期间继续独立工作。

## 任务卡模板

```text
目标：<用户看得到的完整结果；本任务承担哪部分>
owner：<唯一负责者；主线程负责调度与接管>
前置依赖：<就绪证据、现有类型/业务语义与失败路径；变化先回主线程>
工作区/分支：<已核实且可复用的位置；确需新建时说明隔离原因>
允许修改：<文件或目录；只读任务填无>
需协调：<共享契约、migration、依赖/锁文件、CI 等未分配事项，不自行扩大范围>
要保留的行为：<安全、权限、错误处理等>
边界结果：<本任务交付的可接入行为、失败处理与不允许改变的共享语义>
检查安排：<最近检查及执行者；集中检查由主线程排队，不各跑全量；文档仅检查 diff>
完成标准：<可接入结果及证据；TypeScript 改动补所属包 typecheck>
评审时机：<低风险自查 / 完整结果集中评审 / 高风险边界提前定向核对>
返回：改动、证据位置、实际命令与退出码、未验证项、未解决依赖及接管点
先读当前工作区和目标包的 AGENTS.md。不自行扩大 Git 操作权限，不跑浏览器测试，不调用付费模型 API。
```

## 工具用法

**Grok Bot**：桌面版直接贴任务卡。命令行用 `grok -w <分支名> --prompt-file <卡片文件>`，首次需要登录（`grok` 交互界面里完成）。pi 里的 `sand-ai/grok-bot` 只能聊天，不支持工具调用，不能用来写代码。

**pi**：只读审查用项目角色 `opening-sol-reviewer`（`tokenfree-sol/gpt-6.1-sol`，2026-10-13 实测可用）。`glm-reviewer`、`k3-reviewer`（`lant`）当天连接失败，恢复后可作为更换模型的第二审查。换了网关后只改 `.pi/agents/*.md` 的 `model` 一行，并在这里更新可用列表，不再新增路由文档。

**Claude Code**：围绕一个完整可用结果或已授权合并批次组织工作，可连续完成其内部任务。开工先读 STATUS，收工更新自己负责的行；多个会话并行时，按文件与分支划清所有权。

## 不再做

- 反复“全面分析项目进度”。现状以 STATUS 和 PR 列表为准，有具体问题再查。
- 新建 evidence、baseline 文件，或把任务账本当状态入口。`docs/superpowers/plans/*/tasks.json` 仍受 `validate-opening-plan.mjs` 校验，保持可通过即可；当前状态只看 STATUS。
- 为一个小改动走完整的定位→实现→审查→交付角色链。

## 图谱按需维护

图谱用于定位和导航，不作为日常开发完成的门槛。常规开发不在内部任务、提交、状态问答或每批收尾时自动刷新，也不自动启动后台更新。纯文档/注释改动无需刷新。源码变化后，若已有图，将 Graphify 现有的陈旧标记置为待更新：

```powershell
$ErrorActionPreference = 'Stop'
if (Test-Path -LiteralPath 'graphify-out/graph.json') {
    Set-Content -LiteralPath 'graphify-out/needs_update' -Value '1' -Encoding UTF8
}
```

查询前检查此标记；陈旧图只作历史导航，涉及当前调用链、依赖或影响范围的结论必须回读现行源码。确需当前关系图或用户明确要求刷新时，在对应有效工作区运行一次 `graphify update .`，等待结果并记录失败/未完成；完成前不把旧图说成已更新。不在历史目录借用其他版本的图。

已有结构图仅需重算社区/图分析时可运行 `graphify cluster-only . --no-label`（不调用模型）；它更新 graph/report，并在可生成时更新 HTML，不更新 wiki 或 manifest。其他导出按实际需要单独生成并核对。刷新期间不并行运行其他 Graphify 写入；不用 `--force` 绕过缩减保护，也不以跳过关系清理的原始 `--no-cluster` 输出替代正式图。

项目代码验收仍使用实际源码、适用测试、独立评审与现有 CI；按需索引不减少授权、隐私、事务、数据正确性或发布边界的检查。
