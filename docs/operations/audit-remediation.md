### 可信代理上线核验

可信IP头默认关闭；配置头缺失、非法或含多个地址时，仅省略IP桶，仍执行账号与全局限流，并非拒绝该请求。仅在确认Hermes是单层Nginx直连应用时，候选配置是由Nginx覆写`X-Real-IP`为`$remote_addr`，然后配置`AUTH_TRUSTED_IP_HEADER=x-real-ip`。必须检查实际登录/注册location及头继承，并阻止外部绕过代理直连应用端口；若前方还有CDN/LB，只信任明确的代理地址范围。旧 `compose.aistudy.yml` 仍发布 `3000:3000`，Opening compose 则绑定 loopback，必须核实实际部署路径及 IPv4/IPv6 监听边界。上线前在隔离出口和冷窗口下使用不同不存在邮箱轮换伪造头，确认始终命中同一真实 IP 预算；单账号重复请求只证明账号桶，不能替代代理验收。未完成前保留为阻塞项。

### 存储与回滚的实际边界

配额针对原始上传、活跃预约及仍存的历史副本，不包含缺少字节元数据的派生图片，不是S3磁盘硬上限。清理回执未完成的删除继续占额；原始对象或历史清理回执大小未知时，保守占满字节额度。上线前需盘点这些记录并完成合法的元数据补齐或对象清理，否则该工作区可能无法新增上传。multipart清理失败保留原失败并记录脱敏日志；需把staging未完成MPU清理合并到既有bucket lifecycle，不能覆盖已有规则。S3复制成功但后续SQL回滚产生孤儿对象的既有路径仍需补偿设计。

应用回滚保留已执行的additive迁移与学习数据，不自动恢复数据库备份；恢复数据库需要独立维护窗口和恢复演练。首次迁移失败且新 worker 从未尝试启动时，恢复旧 root worker 只表示原可用状态恢复，不能计作非 root 加固成功。新协议 worker 尝试启动后若回退 legacy，root 私有暂停记录与 systemd 持久条件会阻止旧 worker 启动；Web 恢复属于降级，显式回退返回 3，后续 restart/status 也不得报告完整成功。若无法确认 worker 停止或暂停保护安装失败，禁止继续恢复旧指针/配置并报告回退失败。恢复未完成会保留 `activation-incomplete`，后续 restart/status 返回 3 且不得解除原 guard；只有完整激活或核验一致的恢复才能清除。若当前指针与服务配置已经不一致，baseline capture 也可能拒绝部署，须保持暂停并按保留快照人工修复一致性，再执行受管验证，不允许跳过身份检查。返回受管新协议版本可恢复原运行意图，但不会删除旧目标的暂停记录；恢复 legacy 必须先人工核对残留任务和外部结果。
