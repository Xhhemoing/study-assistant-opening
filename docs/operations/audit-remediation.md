# 分板块审议与修复状态

更新日期：2026-10-17。审议对象是用户提供的 `study-assistant-opening-audit.docx`，代码基线为开发主干 `851e6ff`。原报告采用静态审计，没有运行项目测试；本轮将代码复核、行为测试和仍待现场验证的事项分开记录。

结论是先修复租户边界、外部调用、作业终态和错误评分依据，再处理体验与工程反馈速度。原报告揭示了真实缺陷，但不宜将所有风险描述视为已经发生的故障，也不能一次照搬所有架构替换建议。本轮没有改变许可证、删除远端分支、合并其他功能 PR 或操作生产服务器。

## 一 安全与认证

| 原报告条目 | 审议结论 | 本轮处理 |
|---|---|---|
| H1 登录与注册无限流 | 属实；仅进程内计数不能覆盖多实例 | 使用 Redis 原子滑动窗口，分别限制账号、入口总量及明确配置的可信代理 IP；失败返回 429 和 Retry-After。Redis 不可用时认证返回 503，限制等待时间 |
| H2 服务商 SSRF | 属实；仅 URL 校验或先查 DNS 后 fetch 不足以防重绑定 | 使用连接阶段的 DNS 校验并固定连接地址；拒绝非公网地址和重定向，保留原主机名的 TLS 校验。生产禁止本机 HTTP，开发本机模型需显式开关 |
| H3 Render 默认开放注册 | 属实；不能只修一份部署文件 | Render 明确启用 Opening；生产未设置 OPENING_RELEASE 时默认关闭注册，显式配置 0 才开放，并同步能力与就绪检查 |
| M1 原生备份跨租户引用 | 文档、修订等引用确实缺少统一验证；部分表已有触发器，不能笼统声称所有外键均不设防 | 写入前检查整批引用与嵌套父子身份；必需实体只接受包内记录或目标工作区已有记录。原格式允许的历史断链保持原语义，但拒绝接到现存外部实体；冲突查询绑定工作区，不披露外部 ID；工作区锁内生成恢复计划 |
| M2 无界请求体 | auth 和原生恢复路径属实，其他旧路径仍需逐一迁移 | auth 限制 8 KiB，原生恢复限制 50 MiB；按实际读取字节限制，并在超限时取消流。尚未将所有旧 JSON 与 multipart 路径统一 |
| M3 大文件缓冲与配额 | 属实，需对象存储直传或流式上传方案 | 待独立切片；不通过简单降低格式上限掩盖上传链路问题 |
| M4 解析进程继承密钥与 root 服务 | 静态配置可证实风险；生产进程身份仍需现场核实 | 待子进程环境白名单、非特权服务及部署回归；本轮未声称生产加固完成 |
| M5 未知错误泄漏 | 属实 | 未知异常改为固定 500 提示，避免返回 SQL、URL 或凭据；仅记录脱敏错误类别 |
| M6 安全响应头与 M7 提示注入 | 需要修复；CSP 需结合编辑器、预览与实际资源测试，正则不能证明模型免疫注入 | 待专项切片，继续保留当前模型无执行工具、渲染限制和来源权限边界 |
| L1 开发 AUTH_SECRET、L2 枚举、L3 403/404 差异 | 仍有改进空间；限流不等于已消除时序和存在性侧信道 | 保留为后续项，不宣称账号枚举已修复 |
| L4 改 baseUrl 复用旧密钥 | 属实，必须在数据库写入边界防竞态 | 地址改变时要求同时提交新密钥，服务端与表单一致；保留规范化后相同地址的无密钥更新 |
| L5 环境文件忽略、L6 health 连接、L7 钉钉回调、L9 部署配置、L10 测试钩子 | 需要定向行为或部署验证 | 补充忽略 infra/docker/opening.env；其余尚未全部处理，尤其 CSRF 例外必须结合回调签名验证，不能直接放行所有回调路径 |
| L8 中文下载名 | 属实，Headers 的 ByteString 限制可本地复现 | 使用 ASCII fallback 和 RFC 5987 filename*，覆盖中文与异常字符 |

限流会在 Redis 故障期间阻止新的登录/注册，这是明确的可用性取舍；已存在的会话不经过这两个入口。可信 IP 头默认不启用；开启前代理必须覆写它并阻止绕过代理直连。服务商本机开发开关不允许在生产放行私网服务。
