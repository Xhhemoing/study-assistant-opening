# 账号维护与删除边界

本项目尚未提供正式账号注销接口或维护命令。不要直接执行 `DELETE FROM users`，不要禁用 append-only 触发器，也不要给 Web 角色增加绕过权限来清理账号。报告 QA08 描述的是直接数据库清理失败，不是现有产品注销功能失效。

## 先确认当前支持什么

截至 2026-10-20 的代码核实：

| 任务 | 现有能力及限制 |
| --- | --- |
| 退出登录 | `/api/auth/logout` 撤销当前会话，不撤销该账号的其他会话。 |
| 停止新登录 | `users.disabled_at` 被 `loginUser` 检查，但没有正式停用账号的管理 API 或 CLI。 |
| 停止已有会话 | `revokeSession` 可撤销单个会话；本轮修复后会话查询同时检查 `users.disabled_at`，已停用账号的存量会话也会被拒绝。正式账号管理 API 或 CLI 仍未提供。 |
| 删除单个资料 | 资料操作服务具有作用域检查、删除收据、对象清理失败重试；不等于删除整个账号。 |
| 删除账号及全部衍生数据 | 尚未实现，不能宣称已支持，也没有可以直接运行的安全删除 SQL。 |

代码依据：

- [登录与退出服务](../../apps/web/src/features/auth/service.ts)、[会话解析](../../apps/web/src/lib/session.ts)、[身份仓库](../../packages/database/src/repositories/identity.ts)。
- [资料操作服务](../../apps/web/src/features/opening/sources/source-service.ts) 的 `actOnSource` / `retry_cleanup` 保留失败对象的清理收据；[OpeningS3](../../packages/database/src/storage/opening-s3.ts) 提供单对象删除原语。
- [library_revisions 不可变约束](../../packages/database/src/migrations/0001_library.sql) 与 [learning_events 删除保护](../../packages/database/src/migrations/0014_learning_event_delete_guard.sql) 是现有数据安全措施。级联删除仍会触发这些约束。
- [旧计划 Task 10](../superpowers/plans/2026-08-15-server-authoritative-learning-loop-repair.md) 描述过受限维护角色及注销流程，但不是已交付能力。计划中的 `0017_account_deletion.sql` 不存在；实际该序号已用于 conversations，不能按旧计划文件名直接执行迁移。

## 需要暂时停止某个账号访问时

先确认具体账号 UUID、工作区归属、操作原因与授权对象；不得依据报告中的示例账号推断生产删除范围。

管理员先限定具体账号 UUID，在一个维护事务中锁定该用户行、设置 `disabled_at`，并撤销该 UUID 下所有未撤销会话，确认目标账号恰好一行后提交；不删除任何用户数据。本轮修复使停用后发生的会话解析拒绝该账号，包括停用期间迟到创建的会话。已经通过身份验证的在途请求不因此自动取消，维护方仍需协调它们完成。若需暂停后台处理，还应单独核实该工作区的排队任务和进行中任务；停用登录不自动取消 Worker 工作。

验证应覆盖被停用账号的新登录、原有会话及并发登录失败，以及其他账号正常访问。恢复访问需要明确授权；先确认停用前的登录请求已结束，再在限定同一 UUID 的事务中再次撤销全部会话并清除停用标记，避免停用期间迟到创建的会话随账号恢复而复活。用户应重新登录。正式维护工具实现前，此文档不提供未经数据库验证的生产操作命令。

## 需要永久删除账号时

这需要独立完整功能，不能通过一个通用 CASCADE 或关闭触发器完成。实现前先把维护请求限定到明确的账号和工作区，然后完成以下步骤：

1. **列明归属与保留范围。** 根据当前数据库外键和业务关联盘点用户、工作区、学习事实、资料及版本、测量结果、预算账本、后台任务、outbox、搜索投影和对象存储引用。区分独占数据、共享引用、审计保留内容与第三方已接收数据；不能仅靠表名或对象前缀推断归属。
2. **验证恢复准备。** 按 [Hermes 发布运维](hermes-deployment.md) 保留数据库及实际对象存储备份，并在隔离环境恢复验证。应用导出不等于完整账号备份。确认备份保留期限及删除完成后是否仍包含待保留副本，明确向请求者说明。
3. **关闭并发写入。** 撤销访问、协调在途请求、Worker 租约及对象上传凭证。被删除账号不能在数据库清理后由迟到任务重新写回数据；不能因此停止或删除其他账号的任务。
4. **设计受限数据库事务。** 为维护操作建立明确的权限边界、依赖顺序和审计结果，保留普通 Web/Worker 角色的不可变约束。任何特权删除能力必须经过单独迁移与权限测试，不能通过关闭全表触发器或向普通角色开放任意表删除来实现。
5. **可靠完成对象清理。** 数据库事务无法原子提交 S3 删除。清理对象前必须记录准确的 bucket/key、归属和可重试结果；数据库提交后即使进程崩溃，仍能继续清理。可复用资料删除的收据思想和 S3 原语，但需要账号范围的完整实现，不能只删数据库记录而丢掉对象清单。
6. **验证完成条件。** 在真实隔离数据库验证事务失败回滚、外键依赖、不可变表授权、跨工作区保护、并发写入、重复请求和崩溃恢复；模拟对象删除失败并确认可重试。最后确认账号不能登录、旧会话无效、无目标任务/对象残留，其他账号数据与服务不变。保留不包含原始学习内容的必要操作结果。

数据库事务提交前可以回滚事务；对象已经删除后不能承诺事务回滚能恢复全部数据。恢复需要根据经过验证的数据库和对象备份单独制定方案，并评估对其他账号和删除请求的影响。没有验证恢复路径时，不开始永久删除。

## 本轮处理范围

QA08 的事实状态是“账号删除维护能力未实现”。本轮补充此操作边界，并修复停用账号存量会话仍可访问的问题；未停用生产账号、删除账号、执行删除 SQL、关闭触发器或修改生产角色。完整注销需要另行交付请求身份核验、维护执行、对象清理与恢复验证；本说明不代表该功能已经完成。
