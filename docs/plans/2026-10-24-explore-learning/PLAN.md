# Study 引入 Explore 优秀交互的开发方案

版本：v2，2026-10-24。以用户指定的本地最新实际开发分支（含未提交与新增文件）为开发基线；生产版仅作兼容性参照。状态：开发设计与静态源码核验，不是已实现、已测试或已部署报告。

## 1. 产品目标与边界

把 Explore 的“概念预览 → 显式深入 → 按目的继承上下文 → 返回原位置”接入 Study 现有学习链路，让学生在材料、课堂和对话中解决局部困惑，同时保留原任务与学习证据。

目标学习与自由探索共用资料、对话、笔记和模型服务，但保留不同节奏：

- 目标学习：原位解释、短支线、恢复原题和草稿、按需要独立验证。
- 自由探索：允许相关问题和多条思路，不强制建课、写总结或安排复测。
- 自我解释：保存学生自己的理解、AI 反馈与修订；没有独立证据时不标掌握。

首版不做无限画布、全库默认上下文、自动生成大量概念、模型排行榜、自动开支线、自动回填总结、口语音视频评分或通用 Agent 编排引擎。使用原创组件与文案，借鉴交互机制，不复制对方品牌、素材或代码。

## 4. 目标交互与命名

### 4.1 概念预览

- 第一入口：在现有课堂/阅读器选区工具栏增加“简短解释”；用户不用重新选课、填页码。
- 自动概念锚点：只使用当前课程/当前来源中有可靠对应的概念，优先每个内容块首次出现处；歧义词不强绑，公式、代码、链接、引用与输入区不自动包裹。
- 首屏内容：概念名、一个短片段或已有解释、来源位置、一个“继续问”主操作；资料摘录明确标“材料原文”，不能冒充 AI 解释。
- 无合适依据：显示“暂无对应解释，可带此片段提问”，不拼造释义，不为了补齐每个词后台调用模型。
- 提问时默认只预填，不因点击锚点就发送付费请求。继续深入后沿用预算与显式发送。
- 桌面：锚点浮层，父内容可见；移动端：轻量底部面板，恢复原滚动；不照搬斜叠卡遮挡布局。
- 浮层只有一个活动实例；Esc 关闭并回焦点，键盘可操作；不依赖 hover 或颜色，支持减少动效。

### 4.2 三种追问的产品语义

| 用户文案 | 首版行为 | 上下文规则 |
|---|---|---|
| 讲深一点 | 从选区/回答的某个概念进一步解释 | 原任务身份 + 确切片段 + 少量必要父背景；不继承全部兄弟讨论 |
| 换种讲法 | 默认同会话改述；用户选择“保留原讨论，另开”时才建分支 | 显式选定的原回答 + 截至该点的历史；不把重述当新知识证据 |
| 相关问题 | 显式另开相关主题 | 继承相关主题/所选片段；默认不继承全部父历史 |

内部关系类型与用户文案分开，避免把 Explore 的方向箭头当必学规则。正式分叉允许从已完成轮次创建；生成中/失败轮次不可作为稳定分叉点。未保存临时对话先提供“保存后另开”或明确的临时旁支，不静默持久化。

### 4.3 主线与返回

每个深入讨论显示短路径“原题/原材料 → 当前问题”和“返回刚才位置”。主任务不因旁支自动完成、改排或替换。

返回优先恢复同一原始对象、内容版本、块/页和草稿；失效时说明原因并提供打开可用原件/当前版本的显式选择，不伪造成功定位。刷新后的恢复与同页切换分开测试。

目标模式先允许一条展开旁支；再深入时保留当前支线继续问或收藏相关问题。学习模式可允许更深一层并给出可返回路径。这是初始产品限制，不是学习科学定律；服务端另设有界遍历和上下文总预算，限制值放在明确策略中。自由探索允许手动继续，不以考试限制强制截断。

关闭旁支立即可返回；“写一句收获”可选。只有显式开始“我来解释”才进入需要作答的学习任务。

### 4.4 三个完整场景

**读材料：**选中术语 → 看可信摘录 → 带选区继续问 → 返回相同页与版本 → 自选保存笔记。

**做题：**先保存原答案 → 请求提示/解释 → 服务端记录帮助 → 返回同题同草稿 → 修订答案；需要独立验证时另用未曝光新题。闭卷模式在服务端禁用辅助，不仅隐藏按钮。

**自由探索：**提出问题 → 查看概念 → 深入/相关主题 → 自己解释或保存开放问题；不强制创建课程、练习或计划。

### P03：概念预览与内容交付

建议新增窄领域模块 `opening/concepts`；不在通用 Markdown 组件里访问数据库或决定权限。

请求（建议新增 `POST /api/opening/concepts/preview`，可记录内容交付，不伪装纯读 GET）：

- nodeId（可选）、term；明确的 sourceId/sourceVersion/page/chunkId 或 savedTurnId/activityId/contentVersion/blockId；
- 当前 StudyContextAnchor；客户端交付幂等 key；

响应为判别联合：`available | ambiguous | unavailable | restricted | stale`，包含可展示短文本、`source_excerpt | saved_explanation` 标识、真实来源定位、解析后的锚点、必要 exposure receipts。缺依据不返回填充内容。

读取顺序：固定来源与概念映射 → 现有允许读取的对应片段 → 若有可信、来源完整的已保存解释则可引用。不能根据 label 去全库抓一段看似相关内容。每次先做授权/材料角色/版本/考试状态检查，再发布内容与曝光回执。

图谱不是必备前提：本地查到显式 knowledge rebuild 与媒体片段修正触发 rebuild，未见普通资料 parse/index 完成自动重建的普遍接线。P03/P04 必须在无图谱时仍支持选区与原文片段；不为让词下划线出现而静默启动全课付费抽取。有图谱但依据待核对时显示其状态，不当作可信定义。

- P03 默认不调用模型，无新增解释缓存表；使用当前数据读回。
- 若后续增加“AI 简短解释”，走统一 tutor/model-task 与预算，不靠页面 mount/useEffect 自动生成；结果身份与 source revision、选区、用途、模型配置关联。

- 数学符号和多义词不按 lower-case 字符串简单合并；不能把 z̄ 与 z 当同概念。
- 受限答案或混合页角色不清时，只给不泄露内容的状态与原件入口；不得把答案片段装扮成“定义”。

验收：他人资料、旧版本、同名概念、公式选区、答案区、闭卷、原材料删除、缓存跨作答、delivery ack 失败。ack 失败保留服务端保守已交付事实，不能恢复成独立作答。

### P04：概念锚点和选区交互

落点：`learning-prose.tsx`、引用标记插件、课堂 `selection-ask.tsx`、阅读器 `source-reader.tsx` / `SourceContentBody`、`message-actions.tsx`。

- 新增纯 `remarkConceptAnchors` 与 `ConceptChip/ConceptPreview`（名称为建议），只处理经过调用方提供的候选词及已核验 locator。
- 每段同词只标必要次数；嵌套链接、引用、KaTeX、代码、隐藏答案、可编辑区排除。渲染顺序不能破坏现有引文、源码 range 和数学公式。
- 术语自动标注是便利入口，用户任意选区提问仍保留；中文/英文、触屏与键盘效果一致。
- 回答选区的现有 `selectedSourceFor` 可能扩展到整个 Markdown 块或回退整段；预览和引用篮须显示实际范围并让用户确认，不能静默扩大到含完整解答的区域。
- 预览升级仅转入同一绑定下的提问草稿；第一版不要求持久分支 DDL。

验收：现有 citations、公式、复制、保存片段和屏幕阅读器不退化；选中后焦点变化不丢片段；关闭预览恢复来源焦点；只点击预览无模型调用。

### P05：上下文预览与引用篮

三层展示：固定学习身份、用户所选片段、服务器实际检索依据。前两层在发送前可看；实际依据在请求完成后读真实回执，不在发送前伪称模型已使用。

- 首版单片段沿用现有 context，不需要数据库改动；多片段作为后续契约扩展，不能把字符串拼成来源不可分的长 prompt。
- 每条 quote 保存 origin type/id、revision、locator、引用文本；服务端重取授权内容。固定课程/attempt/版本不作为可随便移除的 chip。
- 初始容量使用现有单片段和总输入限制，不凭新增槽位绕开总预算；多片段另设显式总字符与数量上限，并在 contracts/domain 单处维护。
- 超限提示缩小范围；若历史做截断，保留当前问题与必要身份，公开“历史仅带入部分”；不默调用模型做摘要。
- “不用资料”只控制检索，不能假装清空历史；另开相关问题与清空历史是独立动作。
- 不做无真实 tokenizer/供应商统计支撑的精确上下文百分比环。可显示片段数量、字符范围、已裁剪状态与请求后真实 usage。

验收：删除一个片段不改变其他顺序和来源；同名不同版本不合并；引用失效明确失败；跨 owner 引用被拒；选区不作为系统指令；保存笔记可回到每一段真实出处。

### P06：持久化支线

只在用户明确另开时创建新会话，主线保留。默认新分支零模型调用，首条发送仍是现有 tutor 请求。

建议以现有 conversations 为唯一对话存储，附加一条 `opening_conversation_branches` 关联记录，而非新增第二套 messages。若实现团队选择直接扩列，也必须表达下面同等语义。

关系记录建议字段：childConversationId（唯一）、parentConversationId、forkTurnId、relation（deepen/rephrase/related）、contextPolicyVersion、selectionRefs、returnAnchor、workspace/owner、createdAt、clientKey。根 conversation 可由祖先解析；首版不为性能预建未必要的冗余树。

必须解决：

- 父/子/轮次/选区同 owner/workspace；fork turn 确实属于父会话且状态完整。
- 同一客户端逻辑创建幂等；事务创建 child 与关系，不接受半条分支。
- 分叉范围由服务端按稳定顺序截断，不能只比较时间戳或 UUID。必须确认已完成 turn 是否可变；若可原位修改，应引用现有修订身份，必要时新增最小 parent-turn revision/snapshot；单个 fork ID 不等于冻结内容。
- rephrase 使用截止点历史，deepen 使用选区与有限父背景，related 使用主题与所选片段；先保留三种明确策略，不做用户可编程策略引擎。
- 所有继承的历史、来源引用、上下文 provenance、预算估算统一由现有 history resolver 扩展处理，但必须保留 `model` 与 `record_referents` 两种用途差异：当前普通模型排除系统查询快照；记录追问只继承用户指代，不能把旧助理查询回答当当前事实。不得为“统一”而取消这些边界。当前代码也不是读取整个会话：仅完整问答、最多20组候选、总字符12000并做来源撤权检查。新分支继承同等总预算，不能按每层20组重复放大。
- 父后来追加的消息不进入旧分支；兄弟分支不进入；递归总深度与总预算有界；禁止循环关系。
- 当前资料权限失效时，不把冻结文本当绕过权限的凭据；沿用当前 resolver 的保守祖先失效语义，拒绝携带已失效继承上下文并说明，不擅自仅删一条引用却留下由它推导的后续回答。用户可明确另起不依赖该来源的主题。历史显示与后续模型使用权限分别处理。
- 删除/隐私清除遵守现有产品语义；父不可用时保留子自身历史及失效关系提示，不级联静默删除子。涉及必须清除的继承数据从 snapshot/备份恢复策略一起处理，不能保留内容副本逃避删除。
- 分支关闭仅折叠/归档支线，不标原题完成、不取消已付费请求、不清除曝光。是否取消生成沿用既有停止操作。
- 临时会话默认不持久化分支，严禁通过关系创建“偷偷保存”。

建议接口：`POST /api/opening/conversations/{id}/branches`（create）、现有 resume 扩展 branch descriptor、`GET .../{id}/branches`（局部导航）。返回含 child ID、验证后的 returnAnchor 与 context summary；不接受客户端直接提供继承正文。

备份：扩展现有 OPENING_BACKUP_TABLES、table-queries 的精确列读取、restore row columns、JSON 字段登记、关系与隐私过滤、empty-namespace 检查及版本兼容校验；不是仅增加导出字段。新增关系、引用 revision 与父轮次依赖进入 export/restore/validate/delete。导入时按既有 ID 保持或映射规则处理所有边，不能漏任何引用；缺父依赖显示 orphaned 不扩大上下文；恢复后用相同 fixture 比较可见消息、历史边界和曝光资格。

### P07：我来解释

第一版只支持文字。两种明确行为：

- 非评分“整理我的理解”：用户原话 → AI 有依据反馈 → 用户修订 → 可存笔记，不写正式正确率。
- 评分“解释检查”：有版本化题意/目标概念/评分标准/可信资料的学习题，才进入 attempt → observation → AI grading → 修订/资格链。

现有 listen 模式只是入口，不作为评分器；不得把任意闲聊识别成正式作答。用户需明确开始并提交。

建议解释评分要点：核心概念是否准确、必要条件是否齐全、因果/推理是否连贯、能否给合适例子或反例。评价语义区分正确、遗漏、冲突和待核对，有文本依据；首版沿用当前 criteria.verdict 的 correct/incorrect/unverified，在反馈中注明遗漏或冲突，不擅自给已有 strict schema 添加不兼容枚举；不把语言华丽、篇幅、背诵标准句当理解。

保留原答，AI反馈与用户修订分别归属；AI不能覆盖原文。题意不足、来源争议、超出可核对范围、模型输出不合契约时 abstain。帮助后的修订可显示进步，但不变成 independent；复述成功不自动提升同技能的程序执行/迁移维度。

任务身份优先复用现有题目版本与能力维度；若契约没有记录 explain 的任务种类，应补边界字段并沿所有 observation/projection/backup 消费者处理，不能只改 prompt。评分规则需可复现版本。当前 evaluatorVersion 固定为 ai-rubric-v1，解释 rubric 应与现有 evaluator 版本分开记录或做明确兼容扩展，不直接替换该 literal。本地已添加 materialAnswerRefs/materialSourceRefs（包含 manifestRevision）；解释评分和资格计算必须携带同等材料修订依据，不能仅锁文件字节版本。独立验证另用未曝光题并保留现有延迟协议。

正式解释题不能直接套用当前 retest 自动链来写维度：本地 `attempt-service.ts:115–126` 明确将该路径设为 transfer，考试整合设为 procedure。P07 需从服务端题目任务种类解析 explain，批改、改评、资格撤回、技能投影和复测入口使用一致语义；客户端不能自行传 explain 改变证据类型。解释后的迁移题只有实际满足迁移任务定义时才写 transfer。

P07b 必须有投影隔离门：本地 `adaptive/snapshot-evidence.ts` 当前按 skillLabel/requirementKey 组织 observations，未消费 explain 维度；仅新增 opening_skill_evidence 行不能防止泛化到其他能力。在所有学习摘要、BKT输入、自动错题卡、FSRS和下一步消费者支持明确任务维度前，解释题的记录/反馈可保存，但不流入这些未适配聚合。已有题目沿旧路径不变。不能仅改变显示名或拼接 skillLabel 来伪造维度隔离，也不为本切片重建整个自适应引擎。

后台批改直接复用当前本地已有的 grade-observation durable job 及其 answerRevision/status 契约，不另造解释队列。尚在并行修改的 material provenance/改评路径需协调接入并完成相应验证；可先交付非评分理解记录，但不能把同步聊天结果冒充已完成的正式评分。费用未知不自动重发；改评新 revision，旧结果保留。

建议接口：优先扩展现有 attempts 创建/提交与 grading 输入，新增 explanation task descriptor，而非单建一套 `/explain/score` 数据真值。具体字段以调用链复核结论收口。

验收：正确但短的解释、流畅却错误的解释、遗漏条件、照抄、已看过反馈、来源争议、重评、模型未知结果、不同维度、备份恢复后重新评分。真实评分质量需人工核定样本校验；静态代码/单元通过不能证明教育收益。

### P08：用户整理知识节点

复用现有节点稳定 ID，新增独立用户整理投影；不向 suggested/supported/needs_check 依据状态混入 confirmed/rejected。

建议 `opening_knowledge_node_preferences`：owner/workspace/course/node、decision（accepted/dismissed；无记录为未选择）、displayLabel nullable、version、updatedAt。同 owner/node 唯一。采纳仅用于用户组织/导航；不能让无依据节点自动成为教学先修或正确答案。

- “采纳/隐藏/改显示名/恢复默认”是用户层动作，不修改原始 label、skill identity、材料事实或历史评分映射。
- 现有 proposals 若仅支持有限任务类型，不能直接冒充通用节点审核器。首版直接显式更新偏好，模型提出批量变更时再扩受控 proposal 类型。
- 重建后稳定节点保留偏好；旧节点 retired 不按同名硬转移到新节点；无法对应则提示待核对，不凭别名做匹配。本地 `retainKnowledgeIdentities` 已按唯一未变定义/身份保留节点，新增用户偏好必须进入 `referencedNodeIds` 的读取集合与 expectedReferencedNodeIds 并发校验；否则只有用户整理过、尚无学习证据的节点可能在重建时丢失关联。不是另写一套匹配器。
- 点击节点能预览真实依据；现有证据列表不能精确定位时不造死链接。
- 不强迫所有节点确认完才能学习；前台先少量展示，不做长审核清单。

验收：重解析/重建、改名不改技能身份、同名不同概念、隐藏恢复、并发更新冲突、跨课程/owner、备份读回。

### P09：局部树和收束

使用真实 branch relations 投影父问题、当前点、直接子支线和返回点。移动端列表、桌面窄栏；没有支线不显示空地图。关系类型同时有文字，不只靠圈的形状。

收束区只在用户结束重要讨论时出现：可选一句收获、未解决问题、存笔记或返回。用户确认的文本才进入主线引用，不自动把旁支全部历史合并主会话，不自动生成卡片、任务或图谱节点。

### 8.2 必测故障矩阵

| 场景 | 预期 |
|---|---|
| 流式中抽屉展开/返回 | 同请求、同会话，不重复创建，不丢草稿 |
| 首次保存响应未知 | 能查询恢复；不因重试产生重复对象 |
| 预览显示后 ACK 丢失 | 保留保守曝光，不标独立 |
| 材料版本更新/撤权 | 不悄悄读取新版本或使用旧授权缓存 |
| 同名概念/复杂公式 | 不错误合并身份，不破坏公式 |
| 分叉后父追加消息 | 子上下文不含分叉后内容 |
| 父被归档/删除/清除 | 明确降级，不能越权恢复继承内容 |
| 不同分支看同题答案 | 曝光关联同题，不洗白 |
| 多标签重复建分支 | 一次逻辑请求只产生一个 child |
| 预算不足/费用未知 | 展示状态、可回原任务/示例；不自动换模型或重发 |
| 解释反馈后重答 | 保留原答与帮助，不按独立首答计分 |
| 图谱重建/偏好并发 | ID稳定时保留整理；冲突明确，别名不改知识身份 |
| export→restore | 树关系、固定版本、引用、返回点、解释维度与曝光保持一致 |
| 闭卷/来源受限 | 服务端拒绝辅助路径，预览/引用/分支均不旁路 |

数据库集成采用隔离原生 PostgreSQL，权限/并发/备份不能用 mock 代替；Worker 持久任务验证真实重启。PGlite 可近测但不替代原生 PG 多连接与恢复。

### 8.3 用户浏览器验收包

按仓库约定由用户完成，Agent 提供入口、测试账号/材料准备条件、步骤、预期与限制。每片提供桌面、窄屏、键盘和减少动效场景；页面可返回、焦点、选区、公式、定位都需实际验收。未反馈标待验收，不用 HTTP 200 代替。

第一批体验验收：打开示例→看术语→继续问入口→返回；真实课中保存原答→预览→继续问→宽屏→返回原题；刷新恢复；预算不足回示例；旧资料版本拒绝默换。

## 9. 度量与学习效果

产品事件与学习证据分开。不能把客户端点击、展开、停留计为掌握。

建议最小事件：preview_opened、deepen_started、main_resumed、explanation_submitted、branch_created。只记内部对象 ID、版本、类型、耗时和状态，不默认采集选区/答案全文。沿用现有权限、删除和保留策略；不存在相应政策时先收集必要的会话内诊断，不无限保留行为日志。

| 指标 | 分母与含义 |
|---|---|
| 返回原任务成功率 | 已明确开始深入的任务上下文中，成功恢复同一对象与位置的比例；关闭浮层不算深入 |
| 恢复完整性 | 应恢复的会话/草稿/返回点案例中实际恢复成功数；应用测试与真实体验分开 |
| 重复困惑 | 同概念/任务短期再次求同类帮助，作为诊断，不武断解释为差表现 |
| 自我解释完成与质量 | 明确开始解释任务的人次；质量由固定rubric、人工抽查及后续独立题评估 |
| 无辅助新题/延迟表现 | 有有效版本、独立资格和未曝光题的提交；记录排除原因 |
| 成本和等待 | 使用实际预算账本/回执；unknown 单列，不当零成本 |
| 图谱可用性 | 从节点到真实材料/任务的成功定位，不按节点总数评价 |

空分母显示 no_samples；尚未埋点显示 not_collected。先收当前流程基准，再做小范围可控体验比较；同一用户相同原题的第二次答对不能直接算干预收益。不同学科、目标/自由探索、初学/熟悉者分别看，不混一个总分。

## 10. 发布与组织

- P01/P02/P03 可拆独立 PR，但共享 AssistantView、LearningProse、contracts、迁移与备份清单只设一个写入负责人；并行最多按仓库允许的活跃工作树数。
- P03 的材料授权与曝光由数据库/服务层负责，UI 不自行决定能否读取；P06 由 conversation/history 服务负责上下文所有权；P07 由既有评估链负责证据投影。
- 使用现有 capabilities 机制逐片开启，不新建第二套配置协议；新增 capability 要同步 public config、服务端返回与构建兼容性。
- 可先开放示例和有来源的预览；评分解释、持久分支待各自数据库/恢复验收通过再开。
- 性能目标先测量；不承诺未经测量的首字秒数、开发天数或提升比例。重复编译/全量测试仅在改动或失败依据需要时执行。
- 真模型质量验证必须使用允许的预算、可核对材料和人工评价，不用预置演示输出冒充真实结果。

## 11. 上线完成标准

第一批完成：有可独立运行的无模型示例；真实学习中能点开预览、带正确背景追问、同会话展开、回到原位置；资料和帮助规则不被绕过；近测/接口/必要数据库与CI完成；用户浏览器状态明确。

完整方案完成：持久支线可创建、恢复、导出导入；上下文按关系和分叉点正确继承；自己的理解与评分维度分离；节点整理不污染来源和掌握；成本未知、权限变化、版本变化、取消与删除均有明确行为；指标有真实分母。

运行通过、用户交互通过、真实模型评分质量、学习收益是四种不同证据，分别报告。
