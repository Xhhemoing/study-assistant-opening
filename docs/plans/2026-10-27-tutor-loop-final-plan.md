## 1 最终目标与交付范围
首个交付确定为：学生从对话入口说明线性代数学习目标，系统利用已有有效记录选择一个 span（向量张成）活动，按需提供示例或提示，以未暴露新题和确定性评分检验，再按授权安排三天复测；中断后从对话或今日入口继续，已推迟、取消和改评的结果保持一致。
产品目标是减少选题、找资料、排程与恢复的组织负担，并争取提高撤去帮助后的延迟独立成绩。学生仍保留目标、偏好、帮助选择和评价更正的决定权；规则负责证据资格和当前状态，不保证真实掌握。技术交付、用户浏览器验收、部署和学习效果分别记录。
首轮限定一门试用课程、span 现有静态题族、已有确定性评分和三天未见题协议。对话是统一入口与续学位置，作答继续复用现有 span 工作区，不重造聊天内解题编辑器。其他课程、自由探索和笔记入口不强制改为导师流程。
本计划确定后续实现范围和验收方式。本轮不改产品代码、环境开关、线上配置或全局评分政策，不启动真人招募，也不构成提交、合并或发布授权。

## 4 最终用户流程
### 4.1 开始与选择活动
试用预置经核对的课程、可访问材料和 span 题族。学生输入“两周后考线代，每天约 45 分钟”，优先复用当前课程与目标；存在多个课程或资料缺失时只询问影响选择的必要条件，不凭标题虚构归属或来源。未填写学习时段也可开始；明确给出的 45 分钟保留，未给出时沿用 span 本次活动 20 分钟的默认值并允许修改，不把它写成长期目标或固定日程。相对日期按工作区时区解释。
无日程的新起步路径复用课程和活动创建能力，跳过旧首启的默认 19:00 日程及多日 course_seed 初始化，不覆盖已保存设置，也不通过填入虚构时段绕过校验。没有日程设置时，今日入口仍读取并展示真实到期任务和续学入口，只不生成日历草案；需覆盖现有 no_settings 分支。旧排程入口保留原有时间和时区约束。
服务端根据当前有效记录、已有会话位置和用户意图调用规则，选择继续原活动、短诊断、针对性讲解、减少帮助的新题或到期复测。已有可信记录者不重复诊断；无证据时先一题，必要时再补一题；题量是初始策略，不是掌握阈值。用户主动要求完整讲解或表示“完全不会”时可以转短示例。

### 4.2 帮助与独立检验
复用已有提示与答案交付语义；对话中的帮助绑定实际 attempt、题目版本和课程要求。模型生成了提示、服务端交付成功、客户端是否收到分别处理；状态不明保留 unknown，不伪称未帮助。已有各通路的提示级别不因名称相似被机械替换。
对局部错误给最小有效反馈；对新手提供不同数据的短示例或步骤补全，再逐渐撤去帮助。允许主动查看完整解答。解答交付后形成或修订的同题答案不能作为独立成功；解答交付前已经独立提交的原始事实保留，不倒改历史资格。
随后使用未暴露的新题和确定性评分。域外输入、歧义和无法判定的答案拒判并给出可操作说明，不让 LLM 临时补一个“正确”结果。界面区分本题独立完成、仍需帮助和待验证；同族新题正确不等于整章掌握或远迁移。

### 4.3 结束与接续
结束时只显示本次结果、待验证事项和一个下一动作。已获限定授权且满足条件时自动安排现有三天未见题复测，并明确告知到期时间、推迟和撤销入口；否则展示待接受建议，并如实说明尚未安排。
再次进入时先核对有效记录与任务状态：优先恢复尚未完成的活动；没有进行中的活动时，提供已到期、未推迟或取消的复测。用户可以改选、跳过或继续当前问题，不强制每次打开都先考试。对话和今日入口读取同一下一动作投影。

## 5 自动组织动作的权限与撤销语义
### 5.1 一次明确授权后的限定自动执行
最终选择采用课程范围的“导师试用”授权，不要求每道题或每次复测再次确认。启用界面一次说明适用课程、span 技能族、允许动作、每日总预算、关闭入口及已有账号总开关状态。每日总预算包含练习与复测：优先沿用既有预算或学生明确给出的 45 分钟；没有预算时展示可修改的 30 分钟默认值，随授权确认，不能由模型暗改。该授权是后续产品中由学习者作出的选择，不由本计划或模型对话推断产生。
自动动作只包括：选择或继续本范围内的活动，以及从合格确定性评价安排一个现有协议允许的 span 复测周期。课程目标结束、归档或用户关闭授权后停止新增自动安排；账号评价或复测总开关关闭时同样停止。没有明确结束日期时授权持续到关闭或归档，不暗中扩展到其他课程。
不静默打开账号总开关，也不将全局 copilot 改成 coach。总开关关闭时提供明确设置入口，用户可保留现行手动接受方式。普通任务创建、长期目标变更、其他日期的计划重排、资料发布或删除，不包含在此限定授权中。
自动复测的关联任务属于同一授权动作，继续通过现有 schedule → accept → createTask 事务形成。不能让模型直接调用裸数据库写入，也不能绕过归属、版本、有效观察、来源可用性、预算和同技能一个活跃周期的检查。权限和目标日预算在提交时重验。既有全局预算或固定安排更严格时继续服从；同日已安排活动与新增复测的预计分钟不得超过授权范围，预算不足保留待安排原因、不静默扩额。并发接受不能各自借用同一剩余预算；旧授权下排队的请求不因模型已生成回复就获得继续执行权。

### 5.2 推迟 取消 撤销与关闭
| 操作 | 最终语义 | 必须保留的事实 |
| --- | --- | --- |
| 推迟 | 修改该次安排的可执行时间与提醒，仍受协议最早时间约束 | 原安排及变更记录；不能重置学习起点伪造间隔 |
| 取消 | 停止该次未完成安排及未投递提醒 | 已作答、已交付帮助、已发送通知和已发生费用 |
| 撤销本次安排 | 仅对仍由该自动动作拥有、未开始且版本未被用户改动的关联任务进行条件撤销 | 接受回执和历史；不套用不适配的今日教练撤销 |
| 关闭自动复测 | 停止新的自动接受和未提交的自动请求 | 已接受任务不自动删除，用户可另行取消 |
| 请求结果未知 | 查询原请求回执及当前任务版本，再决定后续操作 | 不凭超时重建任务或宣称撤销成功 |

同一来源的安排被取消后，刷新、恢复、重复请求、旧状态重算或仅改评不能把它自动复活。出现新的真实作答后，如确需重新安排，应给出新的建议并尊重先前取消选择；首轮对被取消周期的重启采用显式接受。已开始或用户已修改的任务不做整笔回滚，提供继续、推迟或停止后续安排的可用操作。撤销引起的系统取消记录其真实来源和触发原因，与学生主动跳过分开；不得因此触发跳过惩罚或污染负担统计。

## 6 数据与评分方案
会话议程只持久化现有课程、活动或会话的引用、必要的推进位置和并发版本。原答案、帮助级别、有效评价、复测状态和下一动作从其现有事实源读取或计算，不复制成新的掌握表。优先复用现有 span snapshot 和 conversation resume；确有缺口才在原会话数据中补最少引用和版本字段。
同一用户打开两个标签页或设备时，只有基于当前版本的操作可推进；旧响应不得覆盖新作答、取消或改评。保存失败与保存结果未知分别显示。中断恢复不依赖再次调用模型生成摘要，模型不可用时仍能查看已保存活动和完成已有确定题。
本次新增 span 闭环的正确性依据采用已有确定性评分。AI 可解释、提出错因候选，并在独立样本中做影子评分；影子结果不改变该试用路径的权威成绩。现有其他题域的 AI 评价通路、历史有效观察和用户改评保持原语义，不做全局禁用或批量降级。
若后续评估 AI 自动评分，分别报告金标准正确/错误与 AI 判对/判错/拒判的计数、各类分母及覆盖率。confidence 0.8 不当作准确率；0/n 不表示零风险。AI 准入评估与确定性 span 主线并行，不作为首轮交付的额外前置门槛。

## 7 实施顺序与任务所有权
整个近期研发只形成一个完整交付。以下是内部工作包，不是各自一次发布；必要测量与实际入口接线并行，尽早运行最短路径，再补关键失败分支。
| 工作包 | 具体工作与产物 | 依赖与负责人 |
| --- | --- | --- |
| A 当前候选与最小内容 | 核对最新代码、开关和偏好；选定 span 题族与未见题；映射已有指标；用少量可核对案例驱动入口 | 主线程；实施第一步，完成必要核对即开始主路径，不等待全量案例 |
| B 权限与共享语义 | 明确课程授权、活动引用、并发版本、自动接受和条件撤销；复用已有事务 | 主线程唯一负责公共类型、schema、偏好与事务；先交付这些边界再供并行任务消费 |
| C 对话编排 | 在 tutor 请求链构造最小学习上下文，调用规则，返回一个可执行动作；绑定帮助事实 | 实现者 A；依赖 B 的接口语义，不改公共协议或锁文件 |
| D 入口与恢复 | 目标自然语言入口、可改活动预算、导师授权提示、span 跳转与续学、推迟撤销状态 | 实现者 B；沿用现有 UI，依赖 B/C，不自行浏览器验收 |
| E 集成与必要测量 | 接自动复测、今日入口和改评后的状态；补缺失事件；跑相关回归并汇总风险 | 主线程统筹；与 C/D 迭代接通，不等全部组件写完才集成 |
| F 独立评审与交付 | 只读核对权限、帮助时序、事务、恢复和取消不复活；修复后定向复查 | 空余子 Agent 评审；主线程完成当前候选集成检查与交付说明 |

## 8 验证与首个交付的验收
### 8.1 必须覆盖的行为
| 场景 | 预期结果 |
| --- | --- |
| 有记录、无记录、完全不会、主动要完整讲解 | 选择合理分支，不重复强制诊断，不假装新手已经会做 |
| 先独立提交再看解析；先看解析再作答 | 前者保留原独立事实，后者不误计独立；两者后续状态可不同 |
| 同一请求重试、保存超时、旧响应迟到 | 核对原结果，不重复事实、任务或计费；旧响应不覆盖新状态 |
| 授权已关、账号总开关关闭、课程已归档 | 自动写入被拒绝，界面说明尚未安排，保留可用手动路径 |
| 自动接受与撤销/关闭并发，或任务已经开始 | 事务使用当前权限和版本；不错误回滚已发生行为 |
| 推迟、取消、改评后跨入口恢复 | 今日与对话一致；取消不复活，改评不覆盖原记录 |
| 题目版本、资料权限变化或输入超出评分域 | 不借旧资格判断当前题；拒判或解释阻断，不伪造成功 |
| 模型不可用、离开后再进入 | 能恢复既有事实与确定题，不以新摘要作为恢复前提 |
| 未设置日程的新账号，或有既有设置的账号 | 可开始学习且今日显示真实到期任务；不盲种时段/多日任务，不覆盖旧设置 |
| 当日预算不足、两个请求同时安排复测 | 保留待安排原因；只在当前真实剩余预算内接受，不重复占用 |

### 8.2 检查安排
相关单元回归指定 --project unit；TypeScript 变更检查所属包。授权、并发、复测接受和撤销使用已有集成/handler 路径覆盖；主线程串行安排共享数据库与完整检查。保留现有 CI，完整 lint/typecheck/test/build 由一次整合检查或现有 CI 承担，不为每个工作包重复运行。
实施时可复用的检查入口如下，最终以改动覆盖面选择，不是本轮已执行清单：
- 单元：npm test -- --project unit apps/web/src/features/opening/teaching/span/delayed-retest-service.test.ts packages/domain/src/opening/learning-preferences.test.ts
- 集成：npm run test:integration -- tests/integration/opening-span-delayed-scheduling.test.ts tests/integration/opening-conversation-resume.test.ts tests/integration/opening-tutor-turn.test.ts
- Handler：npm run test:handler -- tests/integration/handler/opening-first-learning.test.ts
- 所属包类型检查：npm run typecheck -w @aistudy/contracts，以及实际变更的 domain、database、web、worker 包。
新增自动授权与取消反例放到最接近的现有测试；若现有测试无法表达新的入口，再补相应测试文件。发现确定缺陷先修原反例，文档或状态检查不代替应用行为检查。

### 8.3 用户浏览器验收
由实现者提供试用账号、已审材料、课程 ID、当前候选、开关和偏好前提；现有 span 页面模式为 /opening/courses/{courseId}/study/span。浏览器、视觉、响应式和 E2E 由用户执行，Agent 不自行或委派运行。
验收顺序为：对话输入目标 → 确认限定导师授权或保留手动方式 → 开始一个活动 → 请求帮助并作答 → 完成新题 → 看到真实复测安排 → 推迟或撤销 → 退出后从对话及今日重新进入 → 更正一次评价并核对新状态。每一步给出预期和已知问题，未反馈时记“待用户浏览器验收”。
正式用户试用前须解决已知的越权、数据丢失、误记独立和不可恢复故障；待浏览器验收不阻塞独立的后续开发。部署继续遵守当前项目发布准备与授权，计划定稿不改变这些状态。

## 9 最少测量和真人验证
### 9.1 首轮必须可解释的指标
| 问题 | 最低口径 |
| --- | --- |
| 帮助有没有转为独立表现 | 按受助 attempt 的首个新题检验机会，分别列机会率、完成率及首次提交结果 |
| 组织负担是否下降 | 相同目标任务内选活动、找资料、排程及修正错误安排的次数与耗时；不把思考、作答、主动求助当负担 |
| 跨会话是否接得上 | 初始参与人数、回访人数、实际可恢复机会与恢复成功分别报告，失败和 unknown 单列 |
| 复测是否真实执行 | 到期分母与完成，区分推迟、取消、未打开和失败；独立性另列 |
| 等待与成本是否合理 | 首个有效教学反馈的时延、恢复耗时、失败、调用与重试成本；保留全部参与者分母 |

帮助后检验以受助 attempt 为单位：机会率为获得首个新题检验机会的受助 attempt 数除以受助 attempt 总数；完成率为这些机会中实际首答数除以已安排机会数。首答按真实提交时序确定，不能丢掉首次错误后挑后续答案。正确率在独立且可判定首答中计算，同时按全部机会报告未提交、非独立、unknown 和拒判，不能仅用筛选后的正确率推断效果。
研究分组和独立终测字段随研究准备补齐，不挡住第一条可用路径。离线案例从最小主线和反例扩充到约 40–60 个，分开发集和保留集；关键数学结论及评审分歧人工核对。LLM 评委可以辅助筛选，不单独判定学习成功。

### 9.2 可行性试用
技术交付后，在经同意的试用账户中招募 5–10 人，观察是否能完成、恢复、正确获得帮助并参加独立测验，输出逐人轨迹、缺失和问题清单。首周可用于操作反馈；若覆盖下述第 14 天终测，应给足至少两周随访和整理时间，不能把一周体验等同完整延迟验证。
小样本不认证学习有效、不劣或不伤害。确认问题按失败机制修复；没有发现问题也只说明所观察路径可行。满意度、自主感与 D1/D7 回访保留为体验诊断，不替代能力成绩。

### 9.3 正式效果估计的确定设计
正式问题确定为：相同内容范围和可用时间预算下，新闭环相对现行 AIstudy 流程的延迟成绩增量。采用按学习者的平行随机分组，并按前测或背景分层；不采用简单两主题交叉。两组材料、模型、测验与帮助暴露记录口径相同，实验组新增的是用这些记录驱动教学选择和续学。
第 1–7 天学习，第 7 天无 AI 即时测，第 14±1 天无 AI 延迟测；统一按学习窗结束计时。两组预算包含讲解、练习、复测和必要操作，不强迫用满，实际时间另记。研究目标在等待期暂停实验提醒、自动教学和到期练习，其他目标不受影响；测验提醒和激励相同，全部测验的答案与纠错在终测后统一提供。自发额外接触单列，不宣称每人都严格停止学习七天。
主指标为学习者层面延迟总分 0–100，调整前测，报告组间差异、95% 区间和分配/完成分母。组织负担、时间、迁移、成本分开报告，不合成成绩除时间；流程更省心不能抵消可信的学习损失。研究终点评分使用确定性答案或盲评量规，与产品 AI 自评和用户手动改评分开；远程无法保证无人辅助时说明限制。
题组事先核对并平衡分配，终测题不进入教学生成上下文；保持与迁移分开计分。按随机分组分析，不只报完成者；预先选定缺失处理与合理情景敏感性分析。无显著差异不等于不劣；区间过宽则保持“证据不足”。
研究负责人在正式招募前完成样本量与分析安排：依据最小有意义差异、分数变异、前测相关及流失确定样本；同时写明预算、截止日期、主缺失方法、中途查看及停止规则，纳入现有计划。现在没有这些实测输入，不虚填人数或承诺效果。此研究设计已确定，正式招募和效果验收尚未启动。

## 10 扩展 停止与恢复决定
| 观察结果 | 采取的行动 |
| --- | --- |
| 越权、重复写入、帮助记录丢失、关键错批或终测泄漏 | 暂停受影响路径或结论，修复原反例并定向回归；其他独立工作继续 |
| 主路径可恢复且可测，尚无效果结论 | 进入限定可行性试用并完善测量；不宣称已学得更好 |
| 小样本均值下降或方向反复 | 检查题组、评分、流失、覆盖、额外接触和使用摩擦，不直接收紧帮助 |
| 正式估计支持有意义正向结果且负担无重大反向变化 | 支持同类题域的有限扩展；不外推整学科和长期保持 |
| 可靠证据提示伤害，或仍有实质风险未解释 | 暂停扩大相应教学策略，按原因修正后再评估 |
| 预算或招募结束仍无法区分收益与伤害 | 记录证据不足，再按资源决定继续研究、维持有限试用或停止研究 |

每周围绕三个问题更新 docs/STATUS.md：完整路径是否能完成和恢复；独立、受助与未知是否可区分；延迟成绩是否可取得且可解释。三个问题都能回答，不等于效果已成立，也不自动授权增加自动化范围。
本阶段以 span 用户结果为边界，完成后继续总计划M2课程全流程和M3长期多目标管理。通用证明全自动评分、复杂知识追踪、多模态全套生成和强制每轮自评仍不作为必需前置；不得将这些扩展的难度用于推迟核心阶段。
