## 最新执行决定（2026-10-28 续接完善；不另立计划）

**需求归属：** 用户已确认北极星、M0–M6 顺序、红线、多资料联合处理、先采集再优化算法、后期 A2A、极简前端及样式先讨论。R1–R8 的字段和实现方案是负责人拆单；具体数字及新排程策略标为【推断：待验证候选】，不是用户逐项指定或论文证明的最优答案，不自动成为 M0/M1 的新门禁。前期先补记录与测量，中期依据数据比较后再决定阈值和间隔；现有红线必须始终满足，不以候选调参替代服务不变量。发布、数据授权、前端样式及真人试验仍按后文等待确认。附录 E 为本文件内的实施拆单，不另立路线或状态账本。

执行顺序：**M0 基线收敛 → M1 测量底座 → M2 编排器 v1 → M3 画像与数据集 → M4 全课程包 → M5 迁移/冲刺与多课程 → M6 经确认的真人试验**。span、“两周后考线代、每天约45分钟”仅为测试场景，不限制设计范围。下文第 2–11 节的 M1–M3 是旧工作包标签：旧 M1 span 闭环约等于新 M1+M2；旧 M2 课程全流程约等于新 M4，其中复测纠偏提前到新 M1/M2；旧 M3 长期多目标约等于新 M5。不能据旧标签宣称新阶段完成。

| R2 帮助怎么分级、怎么撤？ | 证据资格仍只认四值（独立、提示、看过解答、未知），提示、讲解或解答之后的作答不算独立，与现在一致。各帮助入口写同一种收据，保留已有 hinted/revealed 等资格，补记具体阶梯级别（1–4）和发起方（学生请求或系统给出）；用户手动切换模式或偏好覆盖默认也记录，但仅切换/请求不冒充帮助已交付、不直接污染独立资格，实际交付时再写曝光事实。新学：完整示例 → 只留最后一步给学生的半示例 → 独立题；巩固：先独立作答，错后依次给 1–3 级提示，第 4 级为完整解答。改 `span/hint-service.ts`、导师帮助写入和 `nextLearningStep` 的模式分支。 | Renkl 与 Atkinson 2003（示例从最后一步开始逐步撤除）；Kalyuga 2007（示例对新手有效、对熟手反而有害）；Aleven 等 2016（按需帮助有用但作用有限） | 一级提示后仍算独立；把帮助折算成分数计入掌握 |
| R3 何时推进到下一要求？ | v1 候选策略将 verified 改为：按原始作答时间，从有效评价修订投影计算连续 3 道不同的首见题独立答对；可信独立错误或受助作答使计数归零，unknown、拒判及未校准 AI 判定不计数也不归零，但当前不确定应优先澄清，不能据旧连对自动推进。重复题、重批和改评不增加题数；改评沿原作答时序重算，不把修订时间当新练习（当前代码为最新一次答对、历史累计 2 道即可）；“要求的验证方式已就绪”等其余条件不变。之后的延迟复测（间隔见 R4）再独立通过，才算“保持”。【推断：待数据验证】M1/M2 不为调参自动把现有2题改为3题；先记录按当前规则的轨迹，M3 比较后明确决定是否在 `course-route.ts` 改计数。任何新策略使用版本化投影，不重写原始成绩；独立、暴露和有效评价资格仍由原服务不变量约束。 | Kelly 等 2015（原调研中的连续正确阈值参考，不证明三题适用于本产品所有题型）；Pelánek 与 Řihák 2018（数据来源与阈值比模型选择更重要）；Corbett 与 Anderson 1995（BKT 继续 shadow） | 历史上任意 2 次答对即通过；现在用 BKT 概率作门槛 |
| R4 复测间隔多长？ | v1 启发式建议：课程路线与普通复测共用 domain `retest-policy.ts` 的间隔函数，距目标日的工作区日历天数取约四分之一、限制 1–7 天，无目标日用 3 天；取整、时区与临近目标日无可排窗口须在同片用例固定，并返回未安排原因。该经验不是数学技能的已证最优值。课程新间隔使用新协议版本，同步 schedule/read/close、契约及 `backup-retest-protocol.ts`；旧 course v1 和 span 协议仍不少于 72 小时。新旧版本沿同一 baseline/复测身份去重，不能通过升级重建已取消、推迟或终结任务；不得重写已接受日期。研究测验仍另设 7/30 天，卡片保留 FSRS。【推断：中期优化候选】前期保留现行间隔采集数据；M3 比较后才决定是否实施。附录 M1-B2 仅保留兼容实施说明，不属于 M1 必交付或阻塞项。 | Cepeda 等 2008（最佳间隔约为保持期的 20–40%，保持期越长比例越低）；Cepeda 等 2006（分散练习元分析）；Rohrer 与 Taylor 2007（数学题分散、交错练习提高一周后成绩） | 所有目标固定 2 天；把 FSRS 用到课程技能 |

## 1 最终目标与完成定义
最终目标是让学习者带着目标、资料和时间约束进入 AIstudy，由系统协助整理范围、诊断缺口、安排路线、讲解与练习、评价作答、执行复测纠偏，并在持续学习中调整课程进度与长期复习。学习者把主要精力放在理解、思考和表达上，保留目标、时间、帮助方式和评价更正的决定权。
本版将原 span 计划纳入第一阶段。第二阶段的一门真实课程全流程，以及第三阶段的长期与多目标管理，均属于必须交付的核心范围。完成第一阶段只能报告 span 路径完成；完成第二阶段可以报告单课程全流程完成；完成第三阶段且通过整体验收，才能报告本总计划的功能目标完成。
闭环必须真实执行以下反馈：目标与资料 → 课程范围与诊断 → 路线与单次教学 → 作答和帮助 → 独立新题与延迟复测 → 更新有效学情和目标缺口 → 改变后续教学及计划 → 再次验证。排了复测、写了成绩、显示了下一步文案，都不能单独算反馈已接通。
功能完成、真实使用验收、发布和学习效果分别记录。全流程产品可以明确说明某项证据不足，不能把资料看完、任务完成、连对或模型置信度等同于掌握；功能验收也不承诺所有学习者必然提分。
本次完善原总计划与文件级推进安排，不实施新增产品策略、不改开关或线上配置、不招募学习者；文档提交、推送和合并状态以 STATUS 与对应 PR 实际回执为准。旧 Word 仍为过期审阅副本。后续开发以当时最新实际开发树为起点，按有效授权连续交付。

## 4 从开始到目标达成的用户流程
### 4.1 目标和资料进入
学习者可输入“六周后考线代，每周四小时”，上传课程大纲、PDF 课件、题目与答案，或选择已有课程及笔记。系统先说明可读内容、缺页、无法识别的图式和材料冲突；保留来源、页码或片段位置与版本。资料中的命令、提示词和角色声明只作为材料文本，不能改变系统权限或用户目标。
最小输入是目标或问题、可用内容与可选时间限制。没有完整材料时，可以先学可核实的部分，并明确缺口；不能虚构考纲、题目答案或材料覆盖。一般只让用户确认有实质影响的目标范围、日期、预算与资料冲突，不让用户逐节点维护图谱。
课程范围由大纲、材料章节和目标要求形成可编辑清单。每项标明来源、相关技能、代表题或输出要求，以及未覆盖原因。上传更多材料只产生有依据的补充和变更候选；不静默删除旧笔记或把所有旧成绩搬到新技能。
开始学习不强制配置固定时段。保留已有时间设置；无日程时不种入默认 19:00 或多日 course_seed 任务。今日入口仍显示真实待办、到期复测与续学位置，相对日期使用工作区时区。

### 4.2 诊断与课程路线
服务端先读取有效作答和活动位置。有可信证据的要求直接复用；无证据的要求按代表性与当前目标选短诊断，其他标为未测。分批诊断不要求首次做完整套考试，也不能从一个 span 结果外推整章。
路线同时显示课程范围、近期优先事项、当前活动及尚未安排的缺口。选题综合目标重要性、先修关系、独立表现、延迟保持、可用资料和真实时间；用户可以改序，并看到由此暂缓了哪些要求。章节顺序不自动等于能力先修关系。
系统给出一个可执行的下一动作及简短理由，详细依据放在展开层。需要读材料时定位到具体片段；需要练习时给出可作答的题；需要补习时说明补什么、多久和返回哪里。只输出建议文字而没有活动入口，验收不通过。

### 4.3 教学与作答评价
课程内支持阅读与追问、短讲解、例题、步骤补全、独立练习、理由表达和综合题。教学依据目标和卡点选择，不强制每次都走诊断、讲解、答题的固定仪式。完全不会时可先示例；局部错误时给有限提示；允许用户主动查看完整解析。
每次实际交付的帮助绑定具体活动、题目版本与作答时序。先独立提交再看解析，保留此前独立事实；看解析之后提交或修订的答案不变为独立成功。生成、交付和到达状态分别处理，无法确定时保留 unknown。
M1 以确定性评分为权威。M2 扩至课程计算题、概念解释和有限范围的证明/步骤题，并接入照片作答的可修正转写。可计算部分优先用规则核验；开放部分按已核对量规给出分项结果、依据和错因候选。AI 置信度不直接变成准确率或掌握资格。
既有照片批改、题干识别候选编辑和冲刺课程桥接继续复用；即时反馈练习只有接入正式作答及有效评价链后才能作为独立证据。本计划不全局禁用现有AI评价，不降级历史成绩或取消用户改评。照片原图、转写、评分和用户更正分别保存。低质图、歧义符号、缺步骤和评分争议应指出具体不确定位置，允许修正或换用可判定的新题。系统承担正常反馈和批改工作，不能把所有题都要求学生手动判分来宣称全流程已完成。
开放题自动评价在目标题域完成校准后按适用范围启用；未获得足够支持的自动结论保持候选，不能独自改变达标判断。必要的独立评分可以用于有限争议或综合评价，但不能代替日常教学编排。课程中全部关键要求仍须有可用验证路径，缺验证路径的要求如实计为未完成。

### 4.4 课程验证与结束
每个教学活动后用未暴露的新题或输出验证当前要求；跨章阶段使用混合题、变式和限时或综合输出，区分局部程序、概念解释、保持和迁移。考前模式允许集中关键题型与得分步骤，同时保留被暂缓内容。
课程终评对照事先约定的目标范围和评价量规，显示已覆盖、独立通过、待复测、仍需帮助和证据不足。考试目标还检查关键题型、速度和综合表现；理解目标包含理由或应用输出。终评的具体要求由课程目标决定，不设通用“80分即掌握”规则。
范围全部完成不等于能力全部达标。未达标则回到具体缺口和可执行安排；用户可以接受调整、改变目标或停止。目标达成后进入第三阶段的保留、降频、归档或停止复习选择，历史记录继续可读。

## 5 复测纠偏与课程反馈
### 5.1 六类结果必须进入实际执行链
| 复测结果 | 对学情的处理 | 必须产生的后续动作 |
| --- | --- | --- |
| 独立通过 | 更新对应要求在该题域、该间隔下的证据 | 减少近期重复，推进未覆盖要求；按维护规则保留后续抽查，不外推整章掌握 |
| 独立错误 | 定位本题失败，错因与先修仅作有依据的候选 | 区分概念、程序、粗心或时间问题，安排针对性反馈或有限补习，再用新题检验 |
| 依赖帮助后完成 | 记录学习进展与帮助依赖，独立资格不补写 | 渐退帮助、安排同要求未见题；持续依赖时换讲法或补必要前置 |
| 无法判定或材料冲突 | 保留 unknown、拒判或争议，暂停该项强结论 | 修正转写/答案/来源，或换可验证任务；不能当作学生不会，也不能直接排补弱任务 |
| 未完成、推迟或取消 | 记录参与与安排状态，不生成能力下降事实 | 在预算内重新协商时机，尊重取消；缺席不等于遗忘，不惩罚性堆积任务 |
| 评价被更正 | 从有效修订重新计算受影响的学情与建议 | 取消或改写尚未执行的错误建议；已发生作答、帮助、费用和用户修改保留 |

每个分支都要贯通评价读取、决策、活动/任务写入和跨入口显示。验收至少观察一个后续活动确实改变，再执行它并核对新的结果；不能只检查规则函数返回了动作名。

### 5.2 补习必须能够返回
补习前保存原目标、原要求、活动位置、选用解法及预算。只从可信来源和有效错误/受助证据中选择必要前置；同一解法中的必需步骤可同时要求，不同可行解法允许择一路径，不把全部替代解法都变成先修门槛。
补习活动使用自己的题目、作答和评价，不能把前置答对记到原目标。达到本次关键步骤后恢复原目标上下文，剩余预算足够才执行原目标未见题；预算用尽时保存待验证位置，将新题列入可恢复的下次安排并说明原因，不强行超时再答。恢复上下文不等于已完成返回验证，也不宣称原要求已掌握。中途离开后依原引用恢复，旧异步回复不能把已取消补习重新插入。
两次完整纠偏循环后仍出现同类错误或持续高帮助，停止原样重复，改用替代解释、重新诊断任务要求或给出人工协助选项。两次是首版可调整产品策略，不是学习科学阈值；学生主动表示疲劳、要求换方式或停止时可提前调整。人工协助不是唯一出口，系统仍应给出下一条可执行替代路径。
若核心前置尚未解决，系统可让用户选择继续有限尝试、换解法或暂缓该目标，并说明风险；不能悄悄标为通过来保持进度。复测后的新证据还要进入本周剩余计划，扣除实际补习时间并保留未安排项。

### 5.3 从单题到课程的反馈
一次错误只影响与当前题目和证据相关的要求，不自动判弱所有祖先技能。多题持续表现、跨题型验证与延迟结果共同支持扩大判断范围；课程掌握、考试准备和材料覆盖分别显示。
通过后推进哪一项、失败后补哪一步、当前补习挤占了什么安排，都由同一课程路线读取。综合验证暴露跨章问题时，改动相应要求的优先级和后续活动；保留其他未受影响的独立成绩。用户改评后，新路线应反映有效记录，历史活动不被重写。

## 6 第一阶段 span 实施与验收
M1 保留原首轮计划的整合交付：对话目标 → span 工作区 → 按需帮助 → 未见题确定性评分 → 三天复测 → 跨入口恢复，并加入第5节中适用于 span 的通过、失败、受助、未完成及改评分支。M1 无需等待全课程模型或完整开放题评分。
先明确活动引用、课程授权、版本与复测事务，再将 tutor 请求链接入现有决策；对话与今日入口消费同一当前结果。必要记录与主路径接线并行，离线案例按实际反例扩充，不把40–60个案例、AI校准或全图谱更新设为开始实现的条件。
学习者一次明确启用课程范围的导师试用。自动动作仅覆盖该范围内活动选择及合格的 span 复测接受，关联任务仍走原 schedule → accept → createTask 事务。账号评价或复测总开关关闭优先于课程授权；不静默改变全局 copilot/coach 档位。
每日预算包含练习和复测，沿用既有预算或用户明确值；没有预算时展示可修改的30分钟默认值并随授权确认。本次活动可沿用20分钟默认时长，不能把它写成长程目标。提交时检查目标日预算、归属、有效评价、来源版本和一个活跃周期；并发请求不能重复占用同一余额。
课程目标结束、归档或关闭授权后停止新的自动请求。已接受任务不会被悄悄删除；推迟遵守最早执行时间，撤销只作用于仍由该自动动作拥有、未开始且未被用户改动的任务。取消不因刷新、恢复、重试或仅改评自动复活；新的真实作答要重新安排时先给显式接受机会。系统取消与学习者跳过分别统计。
M1 的工程验收必须覆盖帮助时序、拒判、账号关闭、预算并发、保存结果未知、取消不复活、改评一致和模型不可用时恢复既有确定题。用户实际走完一次通过路径、一次失败后的新活动和一次退出再续学，才具备该阶段用户验收证据。它不代表整门课程或长期目标完成。

## 7 第二阶段 课程全流程实施
第二阶段以已选真实线代课程的大纲、课件、练习和阶段目标为依据，完成全课范围与下列四个相互衔接的工作包。M2a–M2d 是内部依赖顺序，不是四套独立产品或逐步追加审批；实现过程中尽早用真实课程跑通一条跨章路径。

### 7.1 M2a 目标资料与稳定关联
工程工作为接通正式目标读写与 Opening 消费适配器，使课程目标、时间窗口、偏好、卡片和规划读取一致。旧 JSON 中可确定归属的数据迁入正式目标，歧义由一次性选择处理；日期不自动解释为考试。课程节奏和展示偏好保留原职责，不做两套目标长期双向写入。
实现课程范围、来源片段、题目/步骤要求与稳定技能关联。复用已有节点保护和显式映射，补重建、改名、拆分、合并与材料更新的关系；可靠映射才承接历史，无法映射保留原记录并显示未知。requirementKey 继续标识具体评价要求，与稳定技能ID分开；具体题目及内容版本资格由 itemVersionId、sourceVersions 和有效证据上下文核验，不凭标签或 key 相同推断版本兼容。
读入 PDF/文本材料、已有笔记与照片题目，识别缺页、解析失败和版本冲突，并保留可修正入口。复用已有导入任务、阅读索引与出处定位；允许部分可用内容先进入学习，不因完整知识图未生成而卡住全部课程。
上传完成、解析就绪、正文可读、题目与参考答案可用、要求关系可信分别判断。有界上下文或当前最多32份就绪材料的取样，不充当课程范围全集；大材料集的覆盖统计与单次模型上下文分开。答案可见性要检查检索、教学编译、发送端、显式查看和恢复，不能只靠界面隐藏答案。当前历史状态记载答案隔离候选仍有未合入部分，实施时核对实际代码与泄漏反例。
验收数据包括同课程重复导入、材料新版、技能改名及拆分、两个相似标题、旧目标歧义。应看到同一目标被各入口一致读取，旧成绩不串到同名新技能，缺失来源不会被虚构。课程清单须覆盖约定大纲所有必学要求，缺题或缺验证方式清楚列出。

### 7.2 M2b 课程路线与教学评价
在稳定关联上生成可调整课程路线，接通目标优先级、代表性诊断、当前证据和先修选择。诊断和练习的结果进入同一作答链；补足跨 activity 的前置活动和返回引用，复用教学编译、上下文和会话恢复。
扩展题目与评分适配，至少覆盖该课程实际需要的计算、概念理由、步骤/证明及跨章综合题。可控题族与经核对题库优先，按需要补题；每个目标要求都要能定位到可学习材料、可执行活动和验证方式。新题不能只是已见题改名，题目错误或答案冲突进入可操作修正路径。综合或限时测验开始时说明独立条件；途中请求帮助可转教学并记录条件变化，不能继续按原独立模考计分。模考后的纠偏另记新作答，不改写原始成绩。
作答照片的转写校正是M2新增衔接，须将原图、原转写、校正版和校正来源分别绑定版本保存，不能与现有题干候选编辑混同。OCR修正不冒充新独立作答、不重置原提交时序，也不自动授权再次付费评分；更换原答或需要重新收费批改时使用可见的新请求和版本，保留普通用户改评入口。照片提交、步骤评价和手工改评接入原记录；AI评价在适用题域按校准结果配置，正常题目给出自动反馈，局部不确定不拖累全部课程。开放题评分未就绪时可以使用经核对的替代题或有限盲评，但没有覆盖到的关键要求不能记为课程已验收。
验收至少包括初学者先看例题、已有学情跳过诊断、跨章前置补习后返回、照片符号纠正、同题先后帮助资格、模型失败后可恢复，以及自主更换学习顺序。系统必须生成实际教学活动和题目，而非只有课程大纲与任务标题。

### 7.3 M2c 复测纠偏与剩余计划
把第5节六类结果接入课程活动、普通复测、span 协议及今日入口。每种结果都要给出下一动作，且在必要时改变课程路线与未执行任务。复测间隔按活动协议和课程规则选择；span三天协议、卡片FSRS与课程独立验证不强制共用一个固定间隔。
每次纠偏预留真实预算；超过本次预算则保存返回位置及未安排原因。相同要求的卡片、错题和复测可协调时段，但保留各自记录语义，不能用一次看卡片冒充完成课程独立复测。
验收采用相同课程的两条轨迹：一条延迟通过后推进下一要求并减少无效重复；另一条延迟失败后执行补习、返回新题、再次延迟验证并调整本周余量。再注入拒判、推迟、取消和改评，检查不会误降能力、复活取消任务或覆盖用户操作。

### 7.4 M2d 跨章验证与目标收尾
接通混合题、限时练习或阶段综合输出，使分项结果能映射到多个要求并反馈课程范围。对已通过但综合应用失败的要求，保留局部成绩并增加综合验证缺口，不把整章重置为未学。
实现目标准备度说明与收尾流程。目标覆盖、独立证据、延迟保持、速度及迁移按目标分别解释；给出剩余任务和可用时间是否足够。时间不足时提出有理由的范围取舍，不静默删掉必学内容；用户确认改变目标后保留变更记录。
M2 最终验收必须使用课程完整目标清单，而非只复跑 span 或只展示一章。真实用户至少走完开课、跨章推进、失败纠偏、阶段综合验证和收尾决定；同一集成候选还须覆盖全部必要分支及完整目标范围的资源/验证映射。用户体验观察不等于完整学习效果证明。

## 8 第三阶段 长期与多目标管理
### 8.1 共同预算和目标协调
在 M2 统一目标和证据基础上支持同课程多个阶段目标、不同课程竞争时间，以及一个综合目标关联多个课程。按实际目标扩展现有唯一约束与关联，不以多个副本模拟同一个目标。一条学习记录可服务多个目标，时间与成本只计算一次，各目标分别判断是否满足要求。
把固定安排、已接受任务、未接受建议、span/普通复测、卡片复习和必要缓冲纳入工作区共同预算。候选阶段先分配可用时间，再排序；不允许各课程分别用完同一空档。卡片队列的实际用时与停止点可反馈预算，dueCardCount 只是输入之一。
当预算不足时，显示未安排项和后果，优先依据用户目标、期限、保持需求与已知风险分配；不隐藏积压，也不把低优先目标静默归档。相同技能跨课程复用必须有可信身份和要求匹配，题型、时限或帮助条件不兼容时不能借用达标结论。
验收包含至少两门有实际内容的课程、同课两个目标、一项跨课程目标、共享技能活动，以及复测和卡片同时到期。总时长不超已授权预算，共享活动不双算，不同目标的评价与期限仍可单独解释。

### 8.2 时间变化与连续缺席
日期、可用时间或优先级改变时，计算对未来草案、已接受安排和目标缺口的影响。普通低影响的候选选择可在授权范围内自动执行；覆盖用户已接受安排、改变目标期限或舍弃目标要求须由用户确认差异。两者不能混成一次默认全自动重排。
缺席后先读取最后位置与真实任务状态，再给一个可执行的恢复动作。用户可选择续学、缩短本次任务或重排；不要求先清完全部逾期复习。逾期、取消和未打开不直接降低能力估计，遗忘判断需要适当的独立抽查。
验收包含一周缺席、预算减半、考试提前、设备切换和正在补习时调整目标。已发生的事实保留，未来安排无重复，原目标与补习返回位置一致；时间不可满足时明确显示缺口。

### 8.3 保持复习与生命周期
目标结束时，学习者选择继续保持、降低频率、归档或停止复习。保持模式保留核心要求、周期性独立抽查和遗忘后的纠偏路径；卡片保持和综合能力抽查各有用途，不能互相冒充。降频规则应结合已有协议和延迟证据，不能仅凭一次短期通过就宣布长期稳定。
归档停止新的自动安排和提醒，已接受事项按明确选择处理；停止复习保留记录和可恢复入口。再次启用时读旧记录及时间变化，先做适量抽查或恢复原活动，不把所有历史清零，也不假定多年后仍然掌握。
自由探索、阅读和笔记继续作为独立入口。用户选择将资料、问题或作品关联到课程/目标时复用同一资产与出处，不能自动把笔记数量变成学习成绩。课程学习中可保存自己的理解和错因，后续检索可回到来源及活动；探索结束后可返回原任务。
验收包含保持后抽查错误并纠偏、降频后的再次安排、归档停提醒、恢复后取回记录，以及无目标探索和笔记使用。长期观察分别报告短期运行、跨周实际使用和更长保持结果；模拟日期仅用于验证时间逻辑，不能证明真实长期有效。

## 9 数据一致性与自动动作边界
正式目标负责范围、期限与成功条件，课程偏好负责表达与节奏；稳定技能关联负责跨材料身份，题目版本负责具体评价资格。有效评价由原修订链计算，议程和计划存引用及当前版本。读写切换要覆盖对话、课程、卡片、今日和复测，不能只改一个入口。
新能力采用兼容扩展与单向映射。可确定归属才回填；歧义保留原始数据。共享类型、schema、权限和事务由主线程或指定唯一负责人串行处理。使用现有主键、外键、唯一约束、事务和版本；没有具体失败场景不新增哈希、冻结契约、基线或门禁。
M2/M3 的自动授权必须明确课程/目标范围、允许动作、预算、有效期和关闭方式。M1 授权不自动扩展到其他课程或长期重排。系统可以在已授权范围选择活动、安排复习和调整未接受候选；改变目标、覆盖已确认安排、删除资料、跨课程扩权仍按用户明确选择处理。
提交自动动作时重读权限、账户总开关、目标状态、预算和版本。关闭后的旧异步请求不能继续写入。请求结果未知时查询原回执，不凭超时再造任务；条件撤销不能回滚已开始活动、已发送通知或费用。不同设备同时推进只允许当前版本生效。目标和偏好变化作用于新活动；进行中的活动保留创建时目标策略，执行前仍重查当前材料权限和有效记录，必要时中止或重新选择，不能用旧快照绕过失效权限。
迁移切换前验证记录计数、关键关联、旧新读取一致性及恢复能力；回滚优先切回兼容读取和停用新编排，保留新旧事实。目标桥接停止旧写入口后不能重新双写；回退代码若会剥离新字段，先提供兼容读写。历史数据删除和破坏性迁移不属于本计划的默认执行动作。

## 10 实施顺序与任务所有权
主线程负责总目标、共享语义、集成和验收。普通子 Agent 使用 gpt-6.1-sol / high；默认两名独立实现者加一个调查或只读评审名额，同时最多三名子 Agent。同一路径单写者，公共类型、schema、迁移、权限、事务、锁文件及共享数据库检查串行交接。
| 工作包 | 交付责任 | 关键依赖与集成时点 |
| --- | --- | --- |
| M1 既有链路接通 | 主线程统筹共享边界，实现者分管对话与入口恢复 | 在现有span范围先跑真实调用链，必要测量同步补齐 |
| M2a 权威目标与内容关联 | 主线程负责目标迁移/身份；实现者负责材料处理和用户确认入口 | 先统一可消费语义，再供路线与评价调用；材料可用部分先接通 |
| M2b 路线与教学评价 | 一名实现者负责规则/教学，另一名负责作答与恢复入口 | 用真实课程尽早贯通跨章前置及照片评价，不并行改公共记录协议 |
| M2c 纠偏和计划反馈 | 主线程协调评价、复测、任务事务，实现者接各入口 | 在M2b可运行后立即接入结果反馈，不能推到“课程上线之后” |
| M2d 综合验证与收尾 | 实现者负责综合活动和展示，主线程集成目标评价 | 与课程范围一起验收，不单独用模考页面替代全流程 |
| M3 共同预算与长期管理 | 主线程负责多目标/预算/生命周期，实现者负责队列与恢复体验 | 复用M2身份与评价，跨课程和卡片在同一候选内整合 |
| 独立评审与交付 | 空余评审者只读检查；主线程修正并安排集中验证 | 高风险共享语义先定向审查，完整结果集中审查，修复后只复核受影响反例 |

阶段有依赖但不设置无意义等待：M1接通时可并行调查M2a，M2身份与接口清楚后可准备M3预算案例。缺少效果显著性或用户浏览器反馈，不阻塞独立的后续开发；已经确认的越权、事实串用、任务重复或不可恢复故障必须修复。
旧版按从零建设估算的研发周数不再用于排期：现有主干已实现大量课程、生命周期和预算能力。以附录 E 的实际缺口逐片推进，前两个实现切片交付后再根据实测周期估算；不把文档页数、PR 数或模型思考时间当作交付速度。部署授权、人工样本标注和真实 7/30 天随访分别列为外部等待，不虚填完成日期。
阶段开始时依据当前代码和真实课程重估工作量，记录估算变化与原因。若资源不够，明确调整时间或由用户决定缩小最终目标；不能把M2/M3悄悄移入可选清单。规划中的阶段完成不自动构成提交、发布或真人试用授权。

## 12 测量与学习效果验证
### 12.1 每阶段都要回答的问题
| 测量问题 | 口径与解释 |
| --- | --- |
| 全流程是否真正覆盖 | 约定目标要求总数中，来源可用、活动可执行、可独立验证的数量分别列出；不只报告已实现子集 |
| 帮助是否转为独立表现 | 以受助attempt首个未见题机会为单位，列机会率、完成率、独立可判首答正确率；未答、受助、unknown和拒判并列 |
| 纠偏是否完成 | 按需要纠偏的机会统计补习启动、回原目标、新题检验、再次延迟验证及缺失，不能只数补课任务 |
| 结果是否改变后续安排 | 抽查实际活动/计划变化与原因，区分通过推进、错误补习、预算不足及用户改选；记录同题无效重复 |
| 组织负担是否下降 | 选内容、找资料、排程、纠正错误安排的时间和次数；不把思考与主动求助当作负担 |
| 长期是否可持续 | 实际预算、积压、回访、恢复、取消、提醒负担及跨周独立表现；所有起始参与者分母保留 |
| 等待和成本是否可接受 | 首个有效教学反馈、恢复时延、失败/重试与调用成本，分正常和异常路径报告 |

机会率为获得首个未见题机会的受助attempt数除以全部受助attempt数；完成率为这些机会中实际首答数除以已安排首机会数；独立可判首答正确率为独立且可判首答中的正确数除以该类首答数。帮助后首答按真实提交顺序确定，不能剔除第一次错误后选后续正确答案。只有独立且可判定首答进入相应正确率分母，同时必须报告全部机会的其他去向。任务完成率、满意度、模型自评和置信度不替代能力成绩。

### 12.2 从可行性到效果估计
M1 只建设合成夹具、模拟学生、事件与测验题库骨架，不在 M1 招募真人。5–10 人试用移至新 M6，必须先由用户确认方案与同意流程。七天终点的时间锚点、允许的产品复习/外部接触与测验窗口在 M6 方案中预先固定；不把产品三天复测、七天后的测验与学习第一周混成同一指标。小样本不认证有效、非劣或无伤害。
单课程功能验收覆盖不同基础、真实资料和完整流程；正式学习效果只能来自另行确认的 M6 研究。首轮采用用户要求的被试内交叉，以不同但等价的内容块平衡顺序，记录难度与既有知识，不能期待同一技能“洗脱”。比较材料、模型、时间预算和测量条件保持可比；课程周期按真实教学范围确定，不机械压成一周。后续若改平行分组，属于新研究设计，须另行确认，不能同时把两种设计写成当前方案。
研究终点采用独立的确定性答案或盲评量规；题组与教学生成隔离，保持和迁移分别计分。各条件/内容块的提醒、激励及测验反馈时间一致；若研究无额外教学的保持，等待窗内暂停目标教学/复测并记录额外接触。产品日常运行的复习不因此永久停止。
M3验证预算协调与长期运行，同时观察真实跨周保持和迁移。若研究的是“包含持续复习的实际效果”，各条件/内容块采用明确记录的复习政策，不与“完全停止学习后的保持”混用结论。模拟时间用于工程边界；真实长期结论来自足够随访。
正式招募前由研究负责人依据最小有意义差异、成绩变异、前测相关及流失设定样本和分析，写明预算、截止日期、缺失处理、查看与停止规则。报告原分组分析、95%区间和分母；无显著差异不等于不劣，区间过宽记证据不足。不虚填样本量和保证提分。
可信的伤害或关键评分错误需暂停受影响教学策略并修正；小样本下降先核对题组、评分、流失、暴露与负担，不机械收紧帮助。等待研究结论不应把课程全流程和长期管理永久搁置，未验证效果须持续如实标记。

## 13 风险处理与完成后的维护
目标、技能或题目关联错误会污染后续建议，必须在受影响范围停止自动采用并修正关联；权限失效、越权写入、重复任务、帮助丢失或不可恢复问题按具体反例修复。其他独立工作继续，不建立“所有研究通过才可开发”的全局门槛。
材料与评分能力不足时公开目标缺口，补材料、可判定题型或有限人工核验；不能把未支持的关键能力改成可选。核心能力的减少由用户明确决定并同步修改最终目标和验收，不由实现者在排期紧张时自行删除。
成本或时延超预算时优先缩小单次生成、复用内容和有界上下文，保留学习证据与恢复。模型不可用时支持已有材料、活动和确定题继续使用；需要模型的新解释明确显示暂不可用，不能输出伪成功。
本总计划是全流程实施范围的维护来源。原导师计划保留为M1细节参考，与本版冲突时以本版为准；旧 Word 是先前阶段范围快照，不再代表总目标。实际进度、失败、验收、发布与下一步只更新 docs/STATUS.md，不另建状态账本。

## 附录 D 导师 Agent 结构与 A2A 对接

产品内只有一个编排器，不是多个自由对话的 Agent。模型负责理解、讲解、出题与反馈、提出草稿；事实只经受控工具和原服务事务写入，界面上的“已保存/已安排”只来自回执。

```text
用户目标、作答、偏好
  → 会话议程（读取时组装，只引用原记录）＋ 有效学习事实（作答、帮助、评价修订、复测）
  → nextLearningStep（domain 唯一决策：选要求、模式和活动）
  → 授权档位（自动执行并告知、可一键撤销 / 展示影响后确认 / 禁止）
  → 受控工具 → 原服务事务 → 回执
  → 界面：学习主线、一个主动作、后继卡
```

以后接入 A2A 只加一层协议适配，内部结构不变：

| A2A 概念 | AIstudy 中的对应 |
| --- | --- |
| AgentCard 中的技能 | 受控工具表里允许对外的工具，例如读取议程与下一步、提交资料、提出计划草稿 |
| contextId | 不透明外部上下文标识，服务端显式映射到已授权账号/工作区/会话；不是凭此获取议程的权限 |
| submitted / working | 任务已入队 / 执行中 |
| input-required | 需要用户确认的第二档动作 |
| auth-required | 用户尚未授权该外部 Agent |
| completed 及其产物 | 引用真实服务回执或只读产物；传输完成不代表独立作答、已保存或学习通过 |
| failed | 返回失败类型；超时/断连可能为结果未知，按原幂等键查询已有回执，不能假定未写入后重做 |
| canceled | 用户取消；不自动恢复 |
| rejected | 第三档禁止的动作 |

外部 Agent 的指令文本不改变权限；结构化工具请求须通过协议输入、可信身份与本站授权校验，不能直接当学生操作。它不能代学生作答，参与过的内容必须进入帮助/暴露记录，不计独立证据。AgentCard 是能力与认证方式声明，不是授权凭据；接入时使用可信身份验证与按账号、工作区、技能限定的可撤销授权。需要本人确认的动作停在 input-required；取消/超时不抹掉已完成事实或费用。本阶段仅保留工具边界，不启动 A2A 网关或通用多 Agent 框架。

### E.1 目标与范围：不是重新开发整个平台

**第一个用户可感知交付：** 输入一个目标后，系统给出可实际开始的一步；作答后收到可信反馈及一个后继；退出后回到原题和原状态；需要帮助、取消或改评不会污染独立证据。用 span 验证这条链，但底层保持课程无关。

```text
对话 / 课程 / 今日
       │ 同一账号、工作区、会话、目标
       ▼
议程读取投影 ← 现有目标 / 活动 / 作答 / 帮助 / 有效评价 / 复测 / 决策回执

       ▼
授权三档 → 受控工具适配器 → 现有服务事务 → 活动/任务及决策回执
       │                                    │
       └─ 模型只读事实、产出受控内容           └─ UI 只根据回执宣称已保存
```

### E.3 五维测量与算法晋升，避免“有很多数据却无法使用”

**最小采集链：** 使用原始作答/帮助/评价/决策记录的 ID 和版本连接数据；补充学习模式、帮助级别及发起方、答前可选把握度、决策原因与候选、题目用途/暴露、实际可观测用时。已存在的时间、模型版本、来源、幂等身份不重复存。缺失值保留 null/unknown，不回填为“独立”“无帮助”或零分。

| 维度 | M1 要留下的最小对象 | 后续报告，而非现阶段有效性承诺 |
| --- | --- | --- |
| 学习效率 | 独立首答资格、有效正确性、作答用时及任务时段 | 独立成功/有效学习小时、达到明确标准所用时间；排除空闲的规则须公开 |
| 理解深度 | 解释/辨析题、量规版本、可选答前把握度 | 量规分、各把握度档的独立正确率及分母 |
| 考试水平 | 等价题卷、限时条件、题目暴露及分项评分 | 前后测和限时正确率；换卷不意味着自动等价 |
| 运用水平 | 同族未见题与迁移题分开、7/30天窗口、期间接触 | 延迟独立正确率与时间归一化值；产品复测不能替代研究测验 |
| 综合能力 | 跨章分项映射、选资料/改排程等组织操作事件 | 混合题表现、人工组织次数与时间；主动求助不算组织负担 |

**主指标建议口径（M6 方案冻结前确认）：** 先分别报告每名学习者七天同族未见题的独立正确率、有效作答时间，再报告其时间归一化结果；明确采用“个人正确率/个人有效测验小时”还是“独立正确题/小时”，二者不可混名。原用户主指标不变，具体公式不在实现时临时选择。全部起始参与者、应测题、独立正确、独立错误、受助、缺测、拒判/无法判定分别给分母；能力结果 unknown 不填 0，亦不能通过只保留完成者制造高正确率。

**算法推进：**
1. M1/M2 使用可解释规则，先测数据覆盖、批改质量和后继是否执行；保留现有 BKT/PFA shadow 与卡片 FSRS，不重新实现已有算法。
2. M3 建按时间截断且按学习者留出的训练/验证/测试划分；同题、近重复题及相关版本不可泄漏到测试；所有特征只能来自预测时点之前。比较规则、带特征逻辑回归/PFA、BKT；FSRS 仍用于卡片，课程保持预测单独验证。
3. 以延迟独立结果的 Brier、log loss、校准和覆盖率评估，不以训练拟合或短期受助正确率晋升。所需样本量根据数据分布与不确定区间确定，不臆定“满一千条就上深度模型”。
4. 模型预测优于规则，只能先晋升为决策辅助候选；“预测更准”不证明“按它排课能学得更好”。实际干预升级需可解释策略、离线反例和经确认的试验；不能直接启动强化学习在线探索。
5. 个人化先画像/检索/偏好，微调后置。任何真实导出先核同意与去标识；合成数据不冒充真实行为数据。

### E.5 前端先确认结构，不先画复杂界面

【建议结构，待用户讨论具体样式】默认学习页只有：一行当前目标/位置、中央资料或作答区、一个主动作；作答后出现一张后继卡。为何现在学、预计时间、证据详情和其他选择按需展开；取消/暂停、求助和必要错误提示不能为了“少文字”藏掉。图标必须有可访问名称，不把长文字变成无意义图标墙。

先与用户确认三件事：① 以作答区为中心还是以对话为中心；② 理由/预计时间默认显示到什么程度；③ 后继卡与可选把握度如何呈现。推荐作答区为中心，助手辅导按需展开，不代表用户已批准。确认后在现有 Tailwind/lucide-react 与组件中改，不更换整个技术栈。

首次 M2 交付给用户不超过五步：
1. 从对话提出目标并进入一个可执行活动，确认只有一个主动作。
2. 独立答错，按需请求提示，确认原答案保留且受助不算独立。
3. 提交未见新题，确认后继能实际开始、安排操作有回执且可撤销。
4. 离开再从今日或课程进入，确认题目版本、帮助及返回位置一致。
5. 对复测取消/推迟或改评，确认不会恢复旧任务，路线与剩余安排反映当前事实。

浏览器验收由用户完成；助手只提供入口、前提与预期，不运行 Playwright 或截图冒充通过。
