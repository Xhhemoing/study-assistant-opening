# A2-R02：单进程 PDF 多页段解析

## 目标与边界

承接用户 PR #115 复核计划 R-02；开发基于 A1 运行修复 `91c2f717`，在独立分支 `perf/sprint-a2-parser-ranges-20261024` 推进。A1 与文档卫生分别由 #117/#118 交付，不等于已合并部署。

- 复用单个 Docling converter，未缓存页段在一个 Python 进程内顺序转换。
- 每段用 JSONL 输出并 flush，Node 逐行校验和持久化；重试仍只执行缺失/失败段。
- 默认页长保持10页，不以推断改20页默认值；先分离“重复初始化”与“段长”的影响。
- 不修改数据库迁移/缓存身份/写入围栏，不发布部分成功为整份资料就绪。R-03 的缺页、partial_ready 与检索说明留下一切片。
- R-04 默认付费批改与上限仍待产品确认，不因本切片改变。无付费模型、生产服务/数据库或浏览器操作。

## 协议与失败语义

`--ranges 1-10,11-20,31-40` 仅用于PDF。范围按物理页严格递增且不重叠；与单页段参数、页数检查互斥。每行恰好一个指定范围：

```json
{"range":[1,10],"pages":[{"page":1,"text":"...","imagePath":null}]}
{"range":[11,20],"error":"conversion_failed"}
```

示例pages省略了其余页；真实成功行必须覆盖完整范围，包括空页。错误码仅 `timeout`、`invalid_output`、`conversion_failed`。总输出仍受8MB限制；日志不进入协议stdout。

- 全成功退出0；普通失败记录该段后可继续，最终退出4。
- 超时线程不能安全与下一段共享converter，故输出当前段timeout后终止该进程，余下段未完成；已保存成功段下次复用。独立CLI在flush后硬退出，避免解释器等待converter的非daemon executor；Node收到timeout行后先围栏保存该失败，再通过回调拒绝杀进程组，不等待剩余整批时限。
- Node 的回调串行执行并施加背压；取消/格式错误/缓存围栏拒绝杀进程组，等待子进程关闭与回调排空后才清理输入。
- 迟到结果不能绕过source version、privacy epoch、claim token和缓存写入事务。失败不能被当作成功空页，也不自动重启进程重做范围。

## 验证

1. Python标准库行为测试：converter只初始化一次、flush、非1物理页、空页、范围校验、失败/超时不重入、大小上限及旧CLI兼容。
2. Node真实本地子进程夹具：JSONL分块UTF-8、背压、8MB、回调失败和取消等待close；分段缓存及作业入口回归。
3. Worker类型/修改lint、原生PG缓存围栏回归，既有CI不降低。
4. 用仓库合成PDF writer生成30/70/150页资料。实际性能对比须固定模型缓存、环境、输入和段长，报告耗时/进程数/峰值RSS，并逐页核验标记；无OCR的本地parser测试不能替代真实OCR或CI上传→队列→DB端到端≥50%门禁。

## 收口结果与剩余门禁

- 默认配置Node定向7文件79项通过（包含线性大行读取修复）；新增长任务超时回执清理后，相关4文件50项再次通过。批次重叠不求和。
- Python标准库29项通过；固定Docling环境先前46项及30子用例通过（新增的硬退出回归由后续标准库批次覆盖）。
- 原生隔离PG 11项通过：真实子进程流→权威缓存写入→完整资料发布；一段失败不发布chunks、下一次只跑缺段，取消提交后拒绝写下一段。子进程输出为明确合成夹具，不冒充Docling或Redis队列结果。
- 实际Docling 2.126.0在单进程解析两页两段，逐页页码/正文标记通过，耗时155.488秒；无OCR，仅本地解析过程，不等同上传→队列→数据库端到端。
- 70页合成输入的旧基线首段在240秒转换预算内超时，整进程约350.957秒结束；没有完整可比基线，不计算提速百分比，不更改默认段长，不声称满足≥50%性能门禁。
- 最终类型/lint及精确head CI以本次提交结果和PR为准；真实70页/OCR性能、partial_ready和发布验收仍待后续切片。无生产、付费模型、合并或部署操作。
