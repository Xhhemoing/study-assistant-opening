基线：`8b500e6bd639488fddfc31d04713f8eecd6aec12`（`feat/opening-release`）。
工作分支：`feat/learning-loop-hardening-20261014`。本切片不合并、不部署、不自动开启模型预算或教学试跑开关。

## 1. 本切片真正交付什么

| 路径 | 实际行为 | 边界 |
|---|---|---|
| 登录 → 首启 | `/api/auth/me` 在 release 模式检测已登录空工作区；运维建号也生效 | 已有内容的工作区不强制重走引导 |
| 三问首启 | 科目/场景、考试日期、上传材料；事务中保存目标、课程、材料关联、三项真实起步任务、默认规划设置 | 默认 20:00–21:00 明示为待调整假设；不虚构具体考试时刻和学习能力 |
| 无 AI 路径 | 可跳过目标进入资料库；AI 阻断面板提供材料/笔记入口 | 不擅自代用户确认额度，不承诺未配置模型也能自动讲解 |
| 学习启动 | 教学活动来自真实任务或续学会话，保留课程/材料；无上下文不造占位主题 | 教学试跑关闭时进入现有学习入口，不创建空教学活动 |
| 规划 Agent | 聊天内显式规划入口，最多 4 次模型调用，60 秒上限；按需读取课表、当前课程学习摘要和确认记忆 | 并非主聊天中每条自然语言都自动路由到 Agent；不支持后台定时自主运行 |
| 计划草稿 | 模型给已有任务的顺序与理由；`planDay` 负责实际时间，日预算裁剪，保留已开始任务；聊天内确认/拒绝 | 不让模型写截止日期、删任务、接受计划或修改学习证据 |
| 聊天建议 | 当前对话产生的候选通过现有 ReviewCard 和稳定动作键就地审核 | 任务创建沿用既有候选通道，规划 Agent 本轮不开放任意 `proposeTask` |
| 教练偏好 | 指导模式、每日分钟预算、保护时段持久保存；保护时段参与排程 | `automaticReorderingActive=false`。未实现队列自动重排/撤销，不伪装成已经生效 |
| AI 主讲 | 真实模型收到学习意图和授权文本材料；严格输出变成实际讲义块、目标与大纲提议；按真实用量计费 | 当前生成一个小单元的第一节，不是完整可编辑课程路径；大纲存在 generationConfig 中，尚无完整编辑 UI |
| 安全 | 公共 health 只报存活；SSH/SCP 严格指纹校验，失败即停 | 详细诊断由受控运维入口执行，公开 200 不等于生产就绪 |

## 2. 架构判断

### 2.1 原生 function calling 与 JSON 协议

不是按“GLM 品牌”判断支持与否。Z.AI 官方文档明确有 tools/tool_calls；实际要核对模型版本、接入地址和转发商能力。本切片沿用现有 Provider 的结构化 JSON 外壳，在 `text` 内解析严格的动作对象，服务端执行有限状态循环。后续原生适配器应映射到同一个动作类型/权限层，不复制业务调度逻辑。

禁止在格式错误、超时或未知计费状态后悄悄更换协议再发一次。能力探测应显式执行、独立预算，按 endpoint + model + provider 配置版本缓存。升级适配器前用同一组拒绝越权、重复调用、取消、幂等和预算测试。

### 2.2 首启和日常规划共享什么

共享工作区目标、任务、日历、指导偏好、学习证据和同一规划入口；首启采集本身保留确定性状态机，不依赖模型。这样模型不可用也能建立有效学习起点，不为三道表单问题消耗多轮推理。

首启不是额外维护一套独立“聪明计划”：保存的真实任务直接进入日常排程。当前不会在用户保存首启表单后偷偷收费调用 Agent；显式规划按钮才触发模型循环。

### 2.3 自主边界

| 操作 | 自由/建议模式 | 未来教练模式 | 本切片 |
|---|---|---|---|
| 读取已授权学习状态 | 仅当前请求所需 | 同左 | 已接入 |
| 生成候选讲解/任务/计划 | 提议 | 提议，受预算约束 | 已有候选通道 + 新规划草稿 |
| 重排未开始、未确认、未锁定的今日候选队列 | 确认 | 明确 opt-in，分钟预算内；必须记录 before/after、允许撤销、每日摘要 | 暂不自动执行 |
| 修改已确认计划、跨日移动、增大时间预算 | 确认 | 确认 | 计划确认通道；其他不开放 |
| 删除任务、改截止日期、发送外部消息、修改预算/密钥 | 单独确认 | 单独确认，不因“教练模式”豁免 | 不对规划模型开放 |
| 改历史答题、伪造独立作答、宣布已掌握 | 禁止 | 禁止 | 模型无此工具 |

`canReorderTask` 只是授权规则的一部分，绝不能代替队列版本 CAS、撤销日志、事务和用户授权。与其接上一行调用声称“教练完成”，不如明确自动执行仍未开放。

### 2.4 优先级

安全/幂等基础 → 可用首启与无 AI 降级 → 受限规划循环与聊天确认，同时打通真实教学最小单元 → 把独立作答证据、复习和次日决策接成跨页面闭环 → 最后开放可撤销自主队列。

不能只优化计划表而忽略教学没有真实内容；也不能只接真实讲解模型而没有学习状态。此次同时实现二者的第一条真实链路。

## 3. 服务与数据流

```
已登录用户
  → first-run 状态（workspace_preferences.opening_onboarding）
  → 目标/场景/材料 + 真实 course/task + 有效规划设置
  → 显式规划请求（稳定 clientKey）
  → workspace 独占活跃 run + 隐私版本
  → 最多 4 步、白名单工具、逐步 runBudgetedCall
  → task priority proposal
  → deterministic planDay + hard blocks + protected slots + daily minutes
  → 2 分钟有效草稿 + 任务/课表/设置/隐私快照哈希
  → 用户确认时重新核验 → 现有 PlanDraft acceptance 事务
  → 真实学习活动 → 真实模型小单元 → 独立作答/复测路径（后续加强衔接）
```

`opening_planning_agent_runs` 仅存运行状态、结果和幂等索引，不存工具对话全文或隐藏推理。每步使用 runId + step 的稳定操作键；未知结果不自动重发。隐私 epoch 变化同时清空旧缓存结果，防止已遗忘内容保留在新 Agent 的解释缓存中。

读取今日状态不能调用会创建 daily draft 的 `plan-service.getToday`。新 Agent 使用只读 repeatable-read snapshot，写草稿与接受分开。接受过程重新校验任务版本、课表、规划设置、受保护时间、目标、旧计划及隐私；旧计划在等待期间已有任务开始也不能重写。

已存在的应用层写路径并非全部使用同一 workspace 锁。跨所有旧写服务的强串行化、任意断点恢复、过期 run 回收 UI仍需单独压力测试；本切片不宣称全仓所有竞争条件均已消除。

## 4. 为学习闭环补齐的产品标准

“完成任务”与“学会知识”是两条不同状态线。初始完成阅读、看了解释、做对有提示的选择题，不得直接升级为可独立运用。

建议稳定维护以下事实：学习目标、概念/先修关系、材料版本、学习活动、答题尝试、提示/答案暴露、判分与信度、复测活动、计划承诺。计划是可以修改的建议，作答与提示暴露是不可覆写的事实。

以用户实际学习中的分部积分为黄金场景：

1. 已看过例题或选择题全对，但没有独立写出 u、dv、du、v 和公式代入：状态是“存在证据缺口”，不是“已掌握”。
2. 下一步优先一题短的无提示独立变式，保留原始过程、符号和自评信心。
3. 学生求助时只给最小提示，记录提示级别；看过完整答案的该题不再计作独立正确。
4. 错因区分方法选择、导数/积分计算、负号处理、记号错误，而不是统一“做错”。
5. 允许学另一节，同时把未验收技能加入待复测队列；不把“继续”解读为通过。
6. 延迟后用新的等价题复测，检查稳定性和迁移；复测到期时间不是用户截止日期，不混为一谈。
7. 今日计划同时处理硬截止与复习负债；塞不下时解释取舍、保留未排任务，不偷偷缩短休息/改截止。

这些是后续闭环验收标准，并非本切片已经完成了全部自动出题、判分和跨日调度。

## 5. 后续三条实际开发切片

### L2：教学活动 → 证据 → 下一步（优先）

在现有教学 prompt 后直接绑定 LearningAttempt，而不是仅展示“试一试”。持久化 skill/requirement、材料版本、题目版本、attemptId、提示暴露、回答和显式 skip。每个活动结束生成 `LearningOutcome` 投影：本次覆盖、独立证据、未验收点、错误原因、推荐下一步；未作答只记 missing，不记 incorrect。

独立/提示后/答案暴露/自述/人工纠正必须可区分。客观题用确定性规则判分；开放步骤题模型给 rubric 提议与不确定性，不越过现有证据确认政策。源材料或评分标准变化必须失效相关投影并重算，保留审计。

验收：同一 attempt 重复提交只有一条事实；提示暴露后答对不得计独立证据；教师改判能重算摘要；“跳过/下一节”不虚构作答；暂停续学保留活动位置与未完成题。

### L3：日/周规划与学习状态联动

把到期复测、未验收技能、最近错误、考试目标、课程先修与实际时间偏差合成版本化 `LearningStateSnapshot`。多课程规划按显式授权读取，不默认把所有课程笔记发给模型。现有本切片仅读取当前绑定课程摘要；跨课程排序是后续工作。

建立确定性 `NextAction` 候选（补讲、独立变式、延迟复测、探究、休息），再由模型解释与选优；教学/答题事件只触发“待更新建议”，不静默改已确认计划。计划适配任务实际耗时、临近考试和复习积压，输出冲突与未排原因。

先以可解释的状态/规则和复测调度为主，再评估 BKT；DKT 需要足量连续技能标注数据，不能用小样本输出看似精确的个人掌握率。新算法按时间与学生隔离训练/验证，评估校准、漏检、复测正确率和学习时间，而非仅聊天满意度。

验收：未测不等于薄弱；复习 not-before 不被提前；同题看答案后的成功不抬升独立证据；多个课程的硬截止和保护时段不冲突；计划不可接受过期摘要；关闭 AI 仍保留手工任务/笔记/练习。

### L4：安全自主队列与体验整合

在独立的未确认候选队列上实现版本化排序，不复用正式计划/历史记录作试验场。每次自动动作必须拥有授权版本、预算扣减、CAS、before/after、操作原因、稳定幂等键、撤销令牌及每日摘要。撤销遇到用户后续修改时进行冲突处理，不覆盖新状态。

接通 `canReorderTask` 之前验证其输入不是模型伪造；锁定、已开始、历史、已确认条目排除。用户拒绝同类介入后降低频率，免打扰优先。教学 UI 将公式、分步例题、作答、反馈、材料引用和下一步统一，避免在聊天、review、任务、教学页反复跳转。

验收：重复投递不多次重排；预算耗尽即停止；撤销只恢复本次合法变化；已有用户编辑不被撤销覆盖；关闭教练立即生效；每天能够解释“为什么改、改了什么、哪些没改”。

## 6. 当前不可宣称已完成的部分

- 没有真实密钥/模型质量实测，也没有浏览器端可用性验收；生成代码接线成功不等于教学正确。
- 未完整实现主聊天意图自动路由、任意新任务工具、多课程学习状态聚合、后台自主规划、完整课程大纲编辑或所有教学闭环界面。
- 未自动重排/撤销，未接入 BKT/DKT；不输出掌握百分比或承诺学习效果提升数值。
- 已结算模型调用后若在结果持久化前崩溃，run 保持未知，不重复收费；缺少操作级人工恢复界面。这是安全停止，不是“恰好一次完成所有动作”。
- 保护时段参与规则与 AI 排程；`dailyMinutes` 的自动裁剪当前只用于新 AI 草稿，既有规则路径和已确认计划不被自动缩短。
- 新工作区目标/指导偏好和 task 材料上下文未纳入原生备份协议升级；不得宣称完整跨机恢复。数据库级备份需包含新迁移。

## 7. 验证与部署检查

本地定向验证命令：`node scripts/check-learning-loop.mjs`。其包含六个受影响包的类型检查、服务端边界、113 项定向单元测试和 2 项部署脚本测试，不包含浏览器测试。

数据库验收命令：设置 `OPENING_TEST_DB=1`、`OPENING_TEST_DATABASE_URL=postgres://aistudy:aistudy@127.0.0.1:5432/aistudy_opening_test`（只允许隔离测试库），再运行 `node scripts/check-learning-loop.mjs --database`。新增集成测试覆盖首启事务重放、未授权来源回滚、指导偏好持久化、只读快照、并发运行、未知结果、隐私清除、接受幂等、旧草稿拒绝；handler 测试覆盖正式关闭注册后的首次登录、401/400/413 与无 AI 入口。

部署前人工核对：备份数据库 → 应用 additive `0061` → 构建 web/worker → 在测试工作区确认时区和保护时段 → 配置模型/定价并由用户显式确认额度 → 单独开启教学开关 → 使用真实材料试跑第一节 → 核验原始回答、引用、账单和暂停/恢复 → 才考虑更大范围启用。

不在公共 health 中调用收费模型；定期 readiness 保留在受保护运维入口。修改 SSH 信任关系必须通过可信控制台核对指纹，不自动修复 sshd。恢复旧代码时不自动删除新增列/表；模型调用可通过现有预算与开关关闭。
