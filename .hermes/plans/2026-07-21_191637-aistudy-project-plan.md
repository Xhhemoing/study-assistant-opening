# AIstudy 项目建立与实施计划

## 目标

建立一个云端优先、面向期末/高考/考研备考的学习决策平台。默认界面只显示精简状态、少量结果指标和下一步行动；原因与解决路径按需展开；完整中间参数进入开发者设置。场景策略可继承、版本化并由用户覆盖。

## 当前基线

- 工作区最初只有同步说明，没有应用代码和 Git 仓库。
- 产品规格、场景模板、UX规则、架构、数据/预测、商业/资源平台已经形成文档基线。
- 首发为官方云 Web；后期提供自托管和少量离线客户端能力。
- MVP 不需要训练复杂模型，先实现版本化规则评估和可重算事件体系。

## 已确认决策

1. 默认结果只有 `稳固/可用/薄弱/未测`、最多三个结果数据、一个主行动。
2. 点击结果显示原因、代表证据和解决任务；开发者模式显示权重、规则、事件和版本。
3. 期末、高考、考研、自定义使用同一 `StrategyPreset` 契约。
4. 共享资源、个人状态、班级状态分离。
5. 原始学习事件追加写；能力切片和状态为可重算派生数据。
6. Web/Worker 采用模块化单体，不在MVP拆微服务。
7. AI只能自动处理低风险机械任务；知识、题目和高影响计划通过候选审核。
8. 开放完整协议和迁移能力；外部Anki/Markdown投影明确有损。

## 实施顺序

### Task 1：技术 Spike 与 ADR

**创建：**`docs/decisions/ADR-001-stack.md`

- 从官方文档锁定 Next.js、TypeScript、PostgreSQL、ORM、认证、BullMQ、对象存储和测试版本。
- 验证自托管、会话、事务、迁移、幂等任务和测试数据库。
- 记录选择、拒绝方案、风险和升级策略。

**验证：**每个关键依赖至少有一个可运行最小示例；ADR中不保留未经验证的结论。

### Task 2：创建 monorepo 脚手架

**创建：**根 `package.json`，`apps/web`、`apps/worker`、`packages/domain`、`packages/database`、`packages/contracts`、`packages/config`、`packages/ui`。

- 配置 npm workspaces、TypeScript、ESLint、测试和构建。
- Web 提供 `/health`；Worker 消费测试任务。

**验证：**`npm run lint && npm run typecheck && npm run test && npm run build`。

### Task 3：本地依赖和 CI

**创建：**`infra/docker/compose.yml`、`.env.example`、CI工作流。

- PostgreSQL、Redis、S3兼容存储；
- 健康检查、隔离测试数据库；
- CI执行lint/typecheck/test/build。

**验证：**干净环境30分钟内启动；Web和Worker健康检查通过。

### Task 4：身份与 StudyGoal 纵向切片

**创建：**认证、目标Schema/API/UI和E2E。

- 注册、登录、退出；
- 创建考试日期、科目、目标和每日时间；
- 服务端对象级授权。

**验证：**新用户可创建目标；其他用户无法读取或修改。

### Task 5：场景模板引擎

**创建：**`packages/domain/src/strategy/`。

- 内置期末、高考、考研、自定义；
- 实现基础→场景→科目→资源→用户→临时覆盖；
- 所有策略有版本，用户覆盖不被静默改写。

**验证：**继承、更新、固定、回滚单元测试。

### Task 6：共享内容与资源包

**创建：**ResourcePackage、ContentItem、SyllabusNode及版本表和开放包Schema。

- 导入第一份版权清晰种子包；
- 用户选择固定版本或跟随更新。

**验证：**新版本不会改写旧内容；坏包给出结构化校验错误。

### Task 7：学习事件与练习播放器

**创建：**不可变事件、Attempt API和选择/短答/步骤题UI。

- 保存答案、用时、提示、信心和错因；
- 支持幂等提交；
- 修正以新事件表示。

**验证：**网络重试不产生重复作答；历史内容版本保持正确。

### Task 8：规则评估与精简UI

**创建：**Assessment纯函数、SummaryStatus契约、状态卡、原因抽屉、只读开发者诊断。

- 能力切片至少覆盖识别、回忆、程序和迁移；
- 默认显示状态、最多两个数据、主行动；
- 原因必须关联解决任务。

**验证：**固定事件快照产生确定结果；UI在320/768/1440px可用。

### Task 9：今日计划与复习

**创建：**Planner契约、场景任务组合、复习状态和今日页面。

- 计划不超过用户时间；
- 期末/高考/考研各有默认任务组合；
- 用户可固定、跳过和调整；
- AI不可用时仍可工作。

**验证：**端到端跑通目标→资源→计划→练习→结果→下一任务。

### Task 10：资料、锚点与来源查看

- 上传对象存储；
- 支持受控PDF和网页快照；
- 精确/文本/结构/仅来源四级锚点；
- 失效检测和降级。

**验证：**固定语料回链测试；失败不得伪装成功。

### Task 11：AI候选流水线

- Provider抽象；
- AIJob和幂等Worker；
- 候选卡片、错因和变式；
- 来源引用与主张支持分离；
- 人工接受、编辑或拒绝。

**验证：**AI不能直接发布正式共享内容；任务重试无重复产物。

### Task 12：资源平台和班级层

- 发布、审核、Fork、版本差异和举报；
- 教师下发；
- 个人状态和共享内容隔离；
- 常见错因只做聚合建议。

**验证：**资源更新不覆盖任何个人学习历史。

### Task 13：模考、归档和导出

- 限时整卷与 `timed_stability`；
- 长期保留、低频、归档、停止和删除；
- 原生完整包、开放包、CSV/Markdown/Anki投影；
- 导出损失报告。

**验证：**完整包round-trip；外部投影明确列出损失。

### Task 14：校准和小规模公测

- 数据质量检查；
- 为具体任务训练简单校准模型；
- 用户与时间隔离的测试集；
- 30–100人、4–8周公测；
- 对比固定队列和用户自选。

**验证：**复杂模型只有优于规则基线才可上线，且必须支持回退。

### Task 15：开源和自托管准备

- 模块/许可证审计；
- Docker Compose发行；
- 升级、备份、恢复文档；
- CONTRIBUTING、安全披露、版本兼容政策。

**验证：**干净机器可以按文档部署兼容社区版。

- 架构和降级符合 `docs/architecture/ARCHITECTURE.md`；
- 商业功能不破坏开放数据格式；
- 每个Milestone通过 `docs/roadmap/EXECUTION_PLAN.md` 的Checkpoint。

## 风险和开放问题

1. 首个考试/科目尚需选择；未选择前只能使用演示种子包。
2. 认证和ORM需通过技术Spike后锁定。
3. PDF支持范围必须受控，不能阻塞学习闭环。
4. AI和复杂预测不能先于事件质量和规则基线。
5. 资源版权和教师供给需要与工程并行推进。
6. 当前不以未成年人专项合规阻塞MVP，但架构不能埋下无法隔离数据和权限的结构性问题。
